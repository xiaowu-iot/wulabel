# Пакет сервиса инференса

Создан в Wulabel. Получает видеопотоки с камер, обрабатывает их обученной моделью и отправляет оповещение, когда обнаружен объект. Также предоставляет HTTP API для детекции.

## Запуск

Нужен Python 3.9 или новее (PyTorch и видеокарта не нужны).

- Windows: дважды щёлкните `run.bat`
- Linux: `sh run.sh`

При первом запуске автоматически создаётся окружение Python и устанавливаются onnxruntime, opencv и numpy (около 100 МБ). Дальше сервис запускается сразу.

Чтобы выполнять инференс на видеокарте NVIDIA: замените `onnxruntime` на `onnxruntime-gpu` в `requirements.txt`, удалите папку `venv` и запустите снова.

## Настройка: config.json

```jsonc
{
  "model": "model.onnx",
  "gpu": true,                 // использовать GPU, если установлен onnxruntime-gpu
  "max_side": 1280,            // перед детекцией уменьшать длинную сторону кадра до этого размера; меньше — быстрее
  "port": 8090,                // порт HTTP API
  "interval": 1.0,             // раз в сколько секунд обрабатывать один кадр каждого потока
  "streams": [
    {
      "name": "Северные ворота",
      "url": "rtsp://admin:пароль@192.168.1.64:554/Streaming/Channels/101",
      "region": [[0.1, 0.4], [0.9, 0.4], [0.9, 1.0], [0.1, 1.0]]  // необязательно: зона детекции, координаты в долях 0–1
    }
  ],
  "alert": {
    "labels": ["без_каски"],   // оповещать только по этим классам; пусто — все классы
    "min_score": 0.5,          // порог уверенности
    "class_scores": {},        // порог для отдельных классов, напр. {"царапина": 0.3}; остальные — min_score
    "cooldown": 60,            // не чаще одного оповещения за N секунд для одного потока и класса
    "hours": "07:00-19:00",    // время работы; пусто — весь день; через полночь пишите "22:00-06:00"
    "save_image": true         // сохранять снимки оповещений в alerts/
  },
  "webhook": { "url": "http://ваша-платформа/api/alarm", "with_image": false, "headers": {} },
  "mqtt": { "host": "", "port": 1883, "topic": "xlabel/alarm", "username": "", "password": "" },
  "reflux": { "enabled": true, "low": 0.3, "high": 0.5, "interval": 60 }
}
```

- Поддерживаются потоки RTSP, HTTP-FLV, HLS (m3u8) и MP4 по http. Источником может быть и путь к локальному видеофайлу — для тестирования (локальные файлы и видео по запросу через http по умолчанию воспроизводятся по кругу). Для локального видео укажите сам файл, например `D:\\test\\1.mp4` (в JSON обратную косую черту пишут дважды, либо используйте `D:/test/1.mp4`), а не только папку; если в журнале постоянно появляется «Ошибка подключения», сначала проверьте это. Чтобы распознать папку с изображениями, отправляйте их по одному через `POST /predict`.
- Попадание в зону детекции определяется по **середине нижней стороны** рамки (там, где стоит человек или машина).

## Содержимое оповещения

Сообщение, которое получают Webhook (POST JSON) и MQTT:

```json
{
  "stream": "Северные ворота",
  "time": "2026-11-01T08:30:15",
  "labels": ["без_каски"],
  "detections": [{ "label": "без_каски", "score": 0.91, "box": [x, y, w, h] }],
  "width": 1920,
  "height": 1080,
  "image": "alerts/20261101/Северные ворота_083015.jpg"
}
```

Если для Webhook включён `with_image`, добавляется поле `image_base64` (JPEG с нарисованными рамками).

## Результаты для разных моделей

Поля каждого элемента `detections` зависят от модели. Поле `task` в ответах `GET /health` и `POST /predict` показывает её тип:

| Модель | task | Поля элемента |
|---|---|---|
| Детекция объектов | `detect` | `label`, `score`, `box` [x, y, w, h] |
| Сегментация экземпляров | `segment` | То же, плюс `polygon` [x1, y1, x2, y2, …] (контур объекта, пиксели исходного изображения) |
| Ключевые точки | `pose` | То же, плюс `keypoints` [x, y, v, …] (v = 2 — найдена, 0 — не найдена); на снимках оповещений скелет рисуется по `skeleton` из `config.json` |
| Классификация изображений | `classify` | `label`, `score`, без `box`: по элементу на каждый класс с вероятностью не ниже `min_score` (до 5; у многометочных моделей без ограничения). Классификация оценивает весь кадр и не фильтрует по `region` |

## HTTP API

| Эндпоинт | Описание |
|---|---|
| `GET /health` | Состояние сервиса и доступность каждого потока |
| `GET /alerts?limit=50` | Последние оповещения |
| `GET /alerts/20261101/xxx.jpg` | Снимок оповещения |
| `POST /predict?conf=0.4` | Загрузить изображение (файл изображения прямо в теле запроса или JSON `{"image": "base64"}`) и получить результаты детекции |

```bash
curl -X POST --data-binary @test.jpg "http://127.0.0.1:8090/predict?conf=0.4"
```

## Данные с объекта

Кадры, в которых модель не уверена (уверенность между `low` и `high`), сохраняются в `reflux/` (не больше одного на поток раз в `interval` секунд).
Периодически копируйте папку `reflux` к себе, нажмите «Импорт изображений с объекта» на странице «Развёртывание» в Wulabel, разметьте изображения и переобучите модель — чем дольше ей пользуетесь, тем точнее она становится.
