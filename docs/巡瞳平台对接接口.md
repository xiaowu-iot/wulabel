# Wulabel ↔ 巡瞳 AI 平台对接接口

Wulabel 桌面端用用户自己的巡瞳 API Key（`Authorization: Bearer sk-live-…`）调用。下面是 Wulabel 需要平台提供的四样东西：

1. 上传自定义模型（API Key 版）；
2. 拉取告警记录和告警图片（API Key 版）；
3. 官方中转服务（让外网的标注员连到用户自己电脑上的 Wulabel 协作主机）；
4. 按客户的类别识别，并能通过聊天告诉 AI 怎么识别（见文末第 4 节）。

现有的 `/v1/models`、`/v1/detect`、`/v1/analyze` 不变。

> **部署状态（2026-11-10 20:06）：** 第 1、2、4 节的接口已在生产上线。`/v1/custom-models` 的上传限制已放宽到 200MB（其他路径仍是 20MB）。第 3 节官方中转已部署：`https://xuntongai.com/wulabel-relay/`（常驻服务 wulabel-relay，--auth xuntong，每个 Key 最多 3 个共享，请求最大 50MB）。
>
> **平台侧实现和下面规格的出入**，Wulabel 已按实际对齐：
>
> - 上传：`task` 只支持 `detect`；`code` 形如 `cust-<账号>-<id>`；返回多了 `enabled`（`ready` 之后要在控制台点启用才能用 `/v1/detect` 调）；`status` 只有 pending / ready / failed，刚上传是 pending，几秒到一分钟后变 ready 或 failed；`recommendedConf` 限定 0.05–0.95；文件 1KB–200MB；没开通托管的账号只能放 1 个模型、每天上传次数有限。
> - 新增 `DELETE /v1/custom-models/{id}` → `{ok: true}`。
> - 告警：`id` 形如 `al_123`；`imageUrl` 形如 `/v1/alarms/al_123/image`，要带同一个 Bearer Key 下载，原图长边最大 2560；平台加原图功能之前的告警 `imageUrl` 为 null；图片保留 7 天，记录保留 30 天；只有配置了推送通道的账号才有告警记录。
> - wulabel-det 推理：长边超过 1920 先等比缩小再送入，框按比例还原；平台不做 NMS；默认阈值取 recommendedConf，调用时的 minConfidence 仍生效。
> - 错误返回 `{code, message}`。
> - 第 4 节（按类别识别、聊天整理规则）已实现（本地联调通过，未部署）：路径和字段同规格；限制为 classes 1–30 个、name ≤30 字、prompt ≤120、description ≤500、instructions ≤1000、messages 1–30 条且最后一条是 user、每条 ≤2000 字；计费按大模型额度，detect-classes 每张 1 张、chat/rules 每轮 1 张，失败不扣；返回多 `id`、`scene`、`usage`。
> - 新增平台规则：`GET/POST /v1/rule-sets`、`GET/PUT /v1/rule-sets/{code}`（code 形如 rs_xxx，PUT 只改传了的字段）。Wulabel 的「同步到巡瞳平台」用它：没绑定就 POST 新建（enabled:false、scenes ["*"]）并记下 code；绑定了就 PUT 更新，只发 name（≤60 字）/classes/instructions，不碰 enabled 和 scenes；PUT 返回 404（平台上删了或不是这个账号的）就重新 POST。保存、采用规则时自动同步。「平台识别也用这套规则」开关单独 PUT {enabled}，打开后平台自己的 /v1/analyze、抓拍、告警推送也按这套规则，告警记录里 detections[].name 就是客户类别名。每个账号最多 20 套规则，超了 POST 返回 400，Wulabel 原样提示。
> - `/v1/analyze` 新增可选 `ruleSet`（不传按场景自动匹配启用的规则；`none` 强制通用识别）。
> - 第 3 节官方中转：中转程序已写好，未部署（要用户同意）。错误统一返回 `{"message": "…"}`，401/403 表示 Key 无效或没权限，402/429 表示额度不足或太频繁（Wulabel 已按这个处理）。

## 1. 上传自定义模型

现在自定义模型只能在控制台走「创建 → ticket → PUT /up/model/{id} → 配置 → 激活」。需要一个 API Key 能用的版本：

### `POST /v1/custom-models`

`multipart/form-data`：

| 字段 | 说明 |
|---|---|
| `file` | ONNX 模型文件 |
| `meta` | JSON 字符串，见下 |

```json
{
  "name": "工地安全帽检测 v3",
  "task": "detect",
  "format": "wulabel-det",
  "classes": ["安全帽", "未戴安全帽"],
  "description": "Wulabel 训练，mAP50 0.912",
  "source": "wulabel",
  "recommendedConf": 0.45,
  "metrics": { "map50": 0.912, "precision": 0.88, "recall": 0.86 }
}
```

返回：`{"id": 123, "code": "cm_xxx", "status": "pending" | "ready" | "failed", "message": "…"}`

### `GET /v1/custom-models`

返回这个 Key 所属账号的自定义模型：`[{"id", "code", "name", "status", "createdAt"}]`（createdAt 用毫秒时间戳）。Wulabel 用它显示上传后的状态。

### 模型格式（平台需要支持）

平台现在只认「原始输出」的 ONNX（YOLO 那种没做 NMS 的）。Wulabel 导出的检测模型**已经在模型里做完后处理**，需要平台新增一种格式 `wulabel-det`：

- 输入：`image`，float32 `[3, H, W]`，RGB，0~1，**任意尺寸**，不需要归一化、不需要缩放补边（模型内部自己做）。
- 输出：
  - `boxes` `[N, 4]`：xyxy，**原图像素坐标**；
  - `labels` `[N]`：int64，类别序号**从 1 开始**（0 是背景，不会出现），对应 `classes[label - 1]`；
  - `scores` `[N]`：置信度，已经按 0.05 左右的低阈值过滤，平台再按用户设置的阈值过滤即可。
- 已经做过 NMS，平台**不要再做 NMS**。

分类模型（以后用）`wulabel-cls`：输入 `image` float32 `[N, 3, S, S]`，RGB，0~1，原图直接缩放到 S×S；输出 `probs` `[N, 类别数]`（已 softmax）。S 在 meta 的 `inputSize` 里。

上传后要不要自动激活、计费怎么算，由平台决定；Wulabel 只显示状态，并给出控制台链接让用户去配置。

## 2. 拉取告警记录

用户想把现场的告警图片（尤其是误报、漏报）拉回 Wulabel 标注、再训练。

### `GET /v1/alarms`

| 参数 | 说明 |
|---|---|
| `since` | 毫秒时间戳，只要这之后的 |
| `until` | 可选，毫秒时间戳 |
| `model` | 可选，模型编码，只要这个模型的告警 |
| `limit` | 每页条数，默认 100，最大 200 |
| `cursor` | 翻页游标，第一页不传 |

返回：

```json
{
  "items": [
    {
      "id": "evt_123",
      "time": 1762761600000,
      "source": "1号仓库门口",
      "modelCode": "cm_xxx",
      "modelName": "安全帽检测",
      "imageUrl": "https://…/alarm-img/xxxx.jpg",
      "width": 1920,
      "height": 1080,
      "detections": [
        { "label": "no_helmet", "name": "未戴安全帽", "confidence": 0.82, "box": [120, 80, 260, 300] }
      ]
    }
  ],
  "nextCursor": "…或 null"
}
```

- `box` 和 `/v1/detect` 一样：`[x1, y1, x2, y2]`，按图片宽高 0–1000 归一化。
- `imageUrl` 要能直接下载原图（不带框）：带同一个 Bearer Key 能访问，或者是有时效的签名地址都可以。现在的 `/alarm-img/{token}.jpg` 如果就是原图可以直接用。
- Wulabel 会把图片导入项目，`detections` 作为预标注（来源记为「巡瞳」），按 `name` 对应项目里的类别。

## 3. 官方中转服务

Wulabel 的实时协作是「发起人电脑当主机」。外网的标注员连不进局域网，所以需要一个中转：主机主动连中转服务器，标注员访问中转的 HTTPS 地址。

**中转程序 Wulabel 这边已经写好**：仓库里的 `relay/wulabel_relay.py`（Python 3.9+，只依赖 aiohttp），用户也可以自己部署。平台要做的是**部署一份官方的**，并用巡瞳 API Key 鉴权：

```bash
python wulabel_relay.py --port 8095 --auth xuntong --xuntong-url https://xuntongai.com
```

- `--auth xuntong`：主机连上来时带 `Authorization: Bearer <巡瞳 API Key>`，中转程序调 `GET {xuntong-url}/v1/models` 验证 Key（结果缓存 10 分钟），通过才放行。平台**不用改代码**。
- nginx 反向代理到 8095，要支持 WebSocket 升级，`proxy_read_timeout` 至少 1 小时，`client_max_body_size` 至少 50m。示例：

```nginx
location /wulabel-relay/ {
    proxy_pass http://127.0.0.1:8095/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    client_max_body_size 50m;
}
```

- 对外地址例如 `https://xuntongai.com/wulabel-relay/`，Wulabel 设置里「官方中转」默认填这个（可改）。
- 要平台决定的：每个账号同时能开几个共享、流量要不要限制或计费、要不要在控制台显示「正在中转的共享」。中转程序支持 `--max-shares-per-key`、`--max-body-mb` 参数。
- 隐私：经过官方中转时，标注员看到的图片会经过平台服务器（只转发、不落盘）。Wulabel 里选「官方中转」时会明确提示这一点，默认用户自建中转或只在局域网用。

### 中转协议（供参考，程序已实现）

- 主机：`GET wss://<中转>/_host?share=<共享编号>`，带鉴权头，连上后保持；中转回一条 `{"type":"ready","url":"https://<中转>/s/<共享编号>/"}`。
- 标注员访问 `https://<中转>/s/<共享编号>/…`：中转把每个 HTTP 请求打包成 `{"type":"req","id","method","path","headers","body"(base64)}` 发给主机，主机回 `{"type":"res","id","status","headers","body"}`。
- 标注员的 WebSocket（实时推送）：`ws-open` / `ws-msg` / `ws-close` 三种消息，按 `id` 区分连接。
- 主机断开后，这个共享编号的请求返回 503「主机不在线」。

## 4. 按客户的类别识别 + 聊天告诉 AI 怎么识别

### 背景

客户在 Wulabel 里建好了自己的类别（比如「未戴安全帽」「电动车进电梯」「消防通道堵塞」）。用巡瞳 AI 预标注时，现在的 `/v1/analyze` 按平台自己的隐患类别返回，会多出客户不需要的东西，类别名也对不上。需要：

1. 识别时把客户的**类别清单**和**识别规则**带上，平台**只返回这些类别**，`name` 原样用客户的类别名；
2. 客户能用**聊天**告诉 AI 怎么识别（「戴了帽子但没系带也算未戴」「只看画面下半部分的通道」「反光衣不算安全帽」），AI 理解后整理成规则，之后识别都按规则来。

### `POST /v1/detect-classes`（按指定类别识别）

```json
{
  "image": "base64（或 data URL）",
  "classes": [
    { "name": "未戴安全帽", "prompt": "person without helmet", "description": "头上没有安全帽的人；戴了帽子但没系带也算；只框头和上半身" },
    { "name": "电动车", "prompt": "electric scooter", "description": "两轮电动车、电瓶车；自行车不算" }
  ],
  "instructions": "只关注画面里的人和车，忽略海报、屏幕里的内容。",
  "minConfidence": 0.3
}
```

返回：

```json
{
  "detections": [
    { "name": "未戴安全帽", "confidence": 0.82, "box": [120, 80, 260, 300], "reason": "头部没有安全帽" }
  ]
}
```

要求：

- `name` 必须是请求里 `classes[].name` 之一，**不在清单里的东西一律不返回**（平台侧要做过滤，不能只靠提示词）。
- `box` 和其他接口一样 `[x1, y1, x2, y2]`，0–1000 归一化。
- `description`（每个类别的识别说明）和 `instructions`（整体规则）都可能为空；有就要遵守。
- `reason` 可选，一句话说明为什么判成这个类别，Wulabel 会显示给标注员参考。
- 计费按平台规则（大概率按大模型额度），批量前 Wulabel 会提示。
- `prompt`（英文提示词）是给开放词汇检测模型用的，平台可以用它先找候选框，再用大模型按 `description` 筛选、分类，具体怎么组合由平台决定。

### `POST /v1/chat/rules`（聊天整理识别规则）

用户在 Wulabel 里和 AI 聊怎么识别，可以附当前这张图：

```json
{
  "classes": [ { "name": "未戴安全帽", "prompt": "person without helmet", "description": "…当前的说明…" } ],
  "instructions": "…当前的整体规则…",
  "messages": [
    { "role": "user", "content": "戴了帽子但没系带的也算未戴安全帽", "image": "可选，base64" },
    { "role": "assistant", "content": "…" },
    { "role": "user", "content": "这张图里左边那个人为什么没认出来？" }
  ]
}
```

返回：

```json
{
  "reply": "明白了……左边那个人背对镜头，头部被遮挡，我会……",
  "rules": {
    "instructions": "更新后的整体规则（没变化可以不返回）",
    "classes": [ { "name": "未戴安全帽", "description": "更新后的识别说明" } ]
  },
  "detections": [ { "name": "未戴安全帽", "confidence": 0.7, "box": [ … ] } ]
}
```

- `reply`：给用户看的回答。
- `rules`：AI 根据对话**建议**的规则更新（只包含有变化的部分）。Wulabel 会显示「采用这些规则」按钮，用户点了才保存，不会自动改。
- `detections`：可选。消息里带了图时，AI 可以按新规则在这张图上试识别一次，让用户马上看到效果。
- 类别名不能被 AI 改掉或新增（`rules.classes[].name` 必须是已有的）。
- 现有的 `/v1/chat` 如果已经能做多轮对话和看图，可以在它基础上扩展，路径由平台决定，告诉我最终路径即可。

## 5. 在 Wulabel 里登录巡瞳账号（设备登录）

用户不想手动去控制台建 API Key、复制粘贴，希望在 Wulabel 里「登录巡瞳账号」就能用。为了不让密码经过 Wulabel、也能用巡瞳原有的登录方式（验证码、短信等），用「设备授权」流程（和电视、命令行工具登录网站账号一样）：

```
Wulabel ──① 申请登录码──▶ 巡瞳
Wulabel ──② 打开浏览器 verifyUrl──▶ 用户在巡瞳网页登录、确认「允许 Wulabel 访问」
Wulabel ──③ 每隔几秒问一次──▶ 巡瞳：确认了就发一个 API Key 给 Wulabel
```

### `POST /v1/device/code`（不需要鉴权）

请求：`{ "client": "wulabel", "deviceName": "DESKTOP-V9MALSR", "clientVersion": "0.1.0" }`

返回：

```json
{
  "deviceCode": "长随机串（只给 Wulabel 用，不显示）",
  "userCode": "ABCD-1234",
  "verifyUrl": "https://xuntongai.com/device?code=ABCD-1234",
  "expiresIn": 600,
  "interval": 3
}
```

- `verifyUrl` 打开后：没登录先走巡瞳正常的登录流程；登录后显示「Wulabel（设备名 DESKTOP-V9MALSR）请求访问你的巡瞳账号：识别、上传模型、读取告警、识别规则」，用户点**允许**或**拒绝**。页面上也要能手动输入 `userCode`（浏览器没自动带上时）。
- 登录码 10 分钟有效，用一次就作废。

### `POST /v1/device/token`（不需要鉴权）

请求：`{ "deviceCode": "…" }`

- 用户还没确认：400 `{"code":"authorization_pending"}`
- 问得太频繁：400 `{"code":"slow_down"}`（Wulabel 会把间隔加 5 秒）
- 过期：400 `{"code":"expired_token"}`
- 用户拒绝：400 `{"code":"access_denied"}`
- 确认了：200

```json
{
  "apiKey": "sk-live-…",
  "keyName": "Wulabel · DESKTOP-V9MALSR",
  "account": { "name": "小物科技", "plan": "专业版" }
}
```

发的就是一个普通的 API Key（名字带设备名），在控制台「API Key」页能看到、能吊销；同一台设备重复登录时吊销旧的、发新的。

### `GET /v1/account`（Bearer）

Wulabel 设置页显示账号和额度用：

```json
{
  "name": "小物科技",
  "plan": "专业版",
  "keyName": "Wulabel · DESKTOP-V9MALSR",
  "quota": [
    { "name": "大模型识别", "used": 120, "total": 5000, "unit": "张" },
    { "name": "专用模型识别", "used": 3000, "total": 100000, "unit": "张" }
  ],
  "expiresAt": 1765000000000
}
```

`quota` 是一个列表，平台有几种额度就列几项（Wulabel 原样显示），没有上限的 `total` 为 null。现有的 `/v1/usage` 如果已经有这些信息，可以直接复用，告诉我字段即可。

### `DELETE /v1/device/token`（Bearer）

退出登录：吊销当前这个 Key，返回 `{"ok": true}`。
