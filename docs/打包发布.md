# 打包发布

两种方式，结果一样：

- **自己电脑打包**：只能打本机系统的包（Windows 电脑打 .exe，Mac 打 .dmg）。
- **GitHub 自动打包**：一次打出 Windows 和 Mac 两个包，不需要 Mac 电脑。

## 分支管理

| 分支 | 用途 | 从哪里拉 | 合并到哪里 |
|---|---|---|---|
| `main` | 已发布的代码，每次发布打一个 `v版本号` 标签 | — | — |
| `release/v版本号` | 一个版本的开发分支，比如 `release/v0.4.0` | `main` | 测试通过后合并到 `main` |
| `feature/功能名` | 一个功能，比如 `feature/in-app-update` | 当前的 `release/…` | 做完合并回 `release/…` |
| `hotfix/v版本号` | 已发布版本的紧急修复，比如 `hotfix/v0.3.1` | `main` | 合并到 `main`，再合并进当前的 `release/…` |

流程：

1. 开新版本：`git checkout main && git pull && git checkout -b release/v0.4.0 && git push -u origin release/v0.4.0`
2. 每个功能单独一个分支：`git checkout release/v0.4.0 && git checkout -b feature/xxx`，做完 `git checkout release/v0.4.0 && git merge --no-ff feature/xxx`，再删掉功能分支。
3. 版本里的功能都合并后，在 `release/…` 上改版本号，用 GitHub Actions 的 `build` 打测试包（选 `release/…` 分支），实测没问题。
4. 发布：`git checkout main && git merge --no-ff release/v0.4.0`，打标签 `git tag -a v0.4.0 -m v0.4.0`，推送 `main` 和标签（推标签会触发正式打包），然后按下面「发布到官网、GitHub、Gitee」操作。
5. 发布后删掉 `release/…` 分支。

合并都用 `--no-ff`，保留「某个功能 / 某个版本整体合并进来」的记录，出问题时方便定位和回退。

## 版本号

发布新版前，先把三个地方的版本号改成一样：`apps/desktop/package.json`、`apps/desktop/src-tauri/tauri.conf.json`、`apps/desktop/src-tauri/Cargo.toml`。

## 一、自己电脑打包（Windows）

需要：Node.js 20+、Rust（stable）、Visual Studio 生成工具（C++）。开发时能 `npm run tauri dev` 就够了。

在 Git Bash 里：

```bash
cd 仓库目录
git pull
cd apps/desktop
npm install
export WULABEL_FEEDBACK_SECRET='反馈服务的密钥'
npm run tauri build
```

- `WULABEL_FEEDBACK_SECRET` 和反馈服务端 `.env` 里的 `APP_SECRET` 一样。不设也能打包，只是软件里的「意见反馈」发不出去。
- 第一次打包要编译全部依赖，十几分钟；之后几分钟。
- 打好的安装包：`apps/desktop/src-tauri/target/release/bundle/nsis/Wulabel_<版本>_x64-setup.exe`

PowerShell 里设密钥的写法是 `$env:WULABEL_FEEDBACK_SECRET = "反馈服务的密钥"`。

## 二、Mac 电脑打包

需要：Xcode 命令行工具（`xcode-select --install`）、Node.js、Rust。

```bash
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cd apps/desktop
npm install
export WULABEL_FEEDBACK_SECRET='反馈服务的密钥'
npm run tauri build -- --target universal-apple-darwin
```

打好的包：`apps/desktop/src-tauri/target/universal-apple-darwin/release/bundle/dmg/Wulabel_<版本>_universal.dmg`，Apple 芯片和 Intel 的 Mac 都能装，最低 macOS 11。

## 三、GitHub 自动打包（推荐，Windows + Mac 一起）

第一次用要先设一次密钥：GitHub 仓库 → Settings → Environments，建一个叫 `WULABEL_FEEDBACK_SECRET` 的环境，在里面 Add environment secret，名字也填 `WULABEL_FEEDBACK_SECRET`，值填反馈服务的密钥。

之后每次发版，任选一种触发：

- 推一个标签：`git tag v0.2.0 && git push origin v0.2.0`
- 或者在 GitHub 仓库的 Actions 页面选 release → Run workflow

大约 20 分钟后，Releases 页面会多一个**草稿**，里面有 `.exe` 和 `.dmg`。检查没问题，点 Edit → Publish release 才会公开。配置在 `.github/workflows/release.yml`。

## 四、Mac 版第一次打开

软件没有花钱买苹果开发者证书签名，Mac 第一次打开会提示「无法验证开发者」，这是正常的：

- 在「应用程序」里**右键** Wulabel → 打开 → 再点「打开」；
- macOS 15 以后：先双击一次，再到「系统设置 → 隐私与安全性」最下面点「仍要打开」；
- 如果提示「已损坏」，在终端执行 `xattr -cr /Applications/Wulabel.app` 再打开。

只需要第一次这样做。

## 四点五、全自动更新的签名密钥（只需设置一次）

软件内全自动更新会校验更新包的签名，防止被人替换成别的程序。签名用一对密钥：公钥写在 `apps/desktop/src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`，私钥只放在 GitHub 的 Environment secrets 里。

1. 在装了 Node.js 的电脑上，仓库的 `apps/desktop` 目录里执行：`npx tauri signer generate -w wulabel-updater.key`，按提示设一个密码。会生成 `wulabel-updater.key`（私钥）和 `wulabel-updater.key.pub`（公钥）。
2. GitHub 仓库 → Settings → Environments → `WULABEL_FEEDBACK_SECRET` → 加两个 secret：`TAURI_SIGNING_PRIVATE_KEY`（私钥文件的全部内容）、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（上一步设的密码）。
3. 把公钥文件的内容填进 `tauri.conf.json` 的 `pubkey`。
4. 私钥文件自己保管好（不要提交到仓库）。丢了的话只能换一对新密钥，已经装了旧公钥的用户要手动装一次新版本。

## 五、发布到官网、GitHub、Gitee

1. 官网：安装包放进网站目录的 `download/`，改首页下载按钮的文件名和版本号，重新生成使用教程页。
2. GitHub：Releases 里发布（自动打包的话就是把草稿点发布）。
3. Gitee：仓库 → 发行版 → 创建发行版，标签填同一个版本号，附上安装包或官网下载地址。
4. README（中英文）：把「下载」一节的版本号和文件名换成新版本，顶部「最新版本」徽章里的版本号也改掉。
5. 检查更新：把反馈服务目录里的 `latest.json` 改成新版本号，`downloads` 里填 Windows、Mac、Linux x86_64（`linux`）、Linux ARM64（`linux-aarch64`，v0.4.2 起）四个安装包（Linux 都用 .deb）的官网直链和 SHA-256（格式见 `server/feedback/latest.json.example`；Git Bash 里 `sha256sum 安装包` 可以算）。老版本启动时就会提示升级，0.4.0 起可以在软件里「立即更新」。
6. 全自动更新（0.4.1 起的客户端用）：在服务器反馈服务目录执行 `python make_updater.py 版本号 --download-dir 官网下载目录 --notes "更新说明"`，它会从 GitHub Release 取各平台的更新包和签名，把更新包放进官网下载目录，并生成 `updater.json`。Linux 有两份：.AppImage 给免安装版用，.deb 给用 .deb 装的用户用（客户端请求时带 `bundle=deb`，v0.4.2 起）；ARM64 同样两份（`linux-aarch64`、`linux-aarch64-deb`）。
