## 1. インストールと初回起動

### 1.1 ダウンロードとインストール

1. 公式サイト <https://wulabel.xiaowuiot.com> を開いて右上の**ダウンロード**をクリックするか、GitHub の Release ページからダウンロードします。
2. Windows：`Wulabel_バージョン番号_x64-setup.exe` をダウンロードし、ダブルクリックして案内どおりにインストールします。インストール後、スタートメニューかデスクトップから **Wulabel** を開きます。
3. Mac：`Wulabel_バージョン番号_universal.dmg` をダウンロードしてダブルクリックで開き、Wulabel を「アプリケーション」フォルダーにドラッグします。
4. Linux（v0.4.0 から）：`Wulabel_バージョン番号_amd64.deb` をダウンロードし、ターミナルで `sudo apt install ./Wulabel_バージョン番号_amd64.deb` を実行します。インストール後、アプリケーションメニューから **Wulabel** を開きます。`.AppImage` をダウンロードして `chmod +x Wulabel_バージョン番号_amd64.AppImage` を実行し、ダブルクリックで起動することもできます（インストール不要）。ARM のパソコン（Phytium、Kunpeng）では `Wulabel_バージョン番号_arm64.deb` か `Wulabel_バージョン番号_aarch64.AppImage`（v0.4.2 から）をダウンロードします。使い方は同じです。

- 動作環境：Windows 10 / 11（64 ビット）、macOS 11 以降（Apple シリコンと Intel の両方に対応）、Linux x86_64（Ubuntu 22.04 以降、Debian 12、UnionTech UOS、x86 パソコンの Kylin OS など）、Linux ARM64（v0.4.2 から。Phytium、Kunpeng のパソコンの Kylin OS、UnionTech UOS など。ファイル名に `arm64` か `aarch64` が付いたものをダウンロード）。
- 現在未対応：Loongson、HarmonyOS。HarmonyOS 端末ではブラウザーからチームの共同アノテーションに参加できます。
- Windows で初回起動時に WebView2 がないと表示されたら、案内どおりにインストールしてください（ほとんどの Windows 10 / 11 には最初から入っています）。
- Mac で初回起動時に「開発元を検証できません」と表示されます（Apple の開発者署名がないため）。「アプリケーション」で Wulabel を**右クリック** → 開く → もう一度「開く」をクリックします。macOS 15 以降では、まず一度ダブルクリックしてから「システム設定 → プライバシーとセキュリティ」の一番下で「このまま開く」をクリックします。「壊れている」と表示された場合は、ターミナルで `xattr -cr /Applications/Wulabel.app` を実行してから開きます。この操作は初回だけです。

### 1.2 メイン画面を知る

起動すると、まず**プロジェクト**画面が表示されます。プロジェクトを開くと、左側にナビゲーションバーが表示されます。上から順に次のとおりです。

| 画面 | できること |
|---|---|
| プロジェクト | プロジェクトの作成、開く、切り替え |
| データ | 画像 / 動画 / データセットのインポート、画像の管理、データセットのエクスポート |
| アノテーション | ボックスやポリゴンの描画、クラスの選択、キーポイントの打点、AI アシストと事前アノテーション |
| ヘルスチェック | アノテーション漏れ、アノテーション誤り、重複画像などの問題を見つける |
| 学習 | モデルの選択、パラメーターの調整、学習の開始、学習記録の確認 |
| 評価 | 指標、混同行列、誤りの例の確認、しきい値の推奨、誤検出テスト、レポートのエクスポート |
| デプロイ | リアルタイム検証、モデルのエクスポート、推論サービスパッケージの作成、現場データの還流のインポート |
| レビュー | チームで共同作業しているときだけ表示：メンバーや状態で絞り込み、まとめて承認・差し戻し、抜き取り検査 |
| 共同作業 | 複数人のリアルタイム共同作業：共有の開始（LAN / オンライン）、メンバー、タスクの割り当て、進捗の集計 |
| 設定 | 学習環境のインストール、ダウンロード元、Xuntong AI |

右上に**フィードバック**ボタンと**プロジェクトを閉じる**があります。

## 2. 設定：学習環境、ダウンロード元、Xuntong AI

アノテーションとインポート・エクスポートだけで学習しない場合は、この章は飛ばしてかまいません。

### 2.1 学習環境をワンクリックでインストール

1. 左側の**設定**をクリックします。
2. 「学習環境」の欄を確認します。
   - **GPU** の行に、検出された GPU、GPU メモリ、ドライバー、対応する CUDA バージョンが表示されます。NVIDIA GPU がない場合は「CPU でしか学習できません（かなり遅くなります）」と表示されます。
   - **PyTorch バージョン**のドロップダウンでは、推奨バージョン（「推奨」と表示）が自動で選ばれます。通常は変更不要です。
     - CUDA 12.8：RTX 50 シリーズなどの新しい GPU
     - CUDA 13.0：比較的新しいドライバーが必要
     - CUDA 11.8：古い GPU とドライバー
     - CPU 版：NVIDIA GPU がない場合
3. （任意）**インストール先**：既定では C ドライブのローカルデータフォルダーにインストールされます。C ドライブの空きが少ない場合は、選択をクリックして空きの多いドライブに変え、**保存**をクリックします。
4. **ワンクリックでインストール**をクリックします。GPU 版は約 3 GB で、uv、Python 3.11、PyTorch を自動でダウンロードします。画面には「ステップ N/5」とダウンロードの進捗、残り時間が表示されます。インストールは一度だけで済みます。
   - ネットワークが切れても中断したところから続きをダウンロードするので、回線が遅くても途中で失敗しません。止めたいときは**キャンセル**をクリックします。
   - 選んだ PyTorch のバージョンが GPU やドライバーと合わないとき（NVIDIA GPU がないのに GPU 版を選んだ、ドライバーが対応するより新しい CUDA バージョンを選んだ、RTX 50 シリーズで古いバージョンを選んだ、など）は、開始前に注意が表示されます。
   - ドライバーが古すぎて CPU 版しか入れられないときは、ドライバーをどのバージョン以上に更新すれば GPU で学習できるかが表示されます。
5. インストールが終わると状態が**準備完了**になり、その下に「GPU を利用可能（cuda）」と表示されます。
   - numpy、onnx、opencv などのコンポーネントが足りないときは一覧で表示され、**不足しているコンポーネントをインストール**をクリックすると、足りないものだけをインストールします。
   - GPU 版を入れたのに GPU が使えないときは、黄色の通知「GPU が使えないため、現在は CPU で学習しています」が表示されます。
6. インストールに失敗したときは、失敗のダイアログでそのまま**この問題をフィードバック**をクリックできます。インストールのログが自動で添付されます。

> 学習環境は独立しているので、システムにあるほかの Python には影響しません。

### 2.2 ダウンロード元

1. まだ選んでいない場合、中国語の画面では中国国内ミラー、ほかの言語では公式ソースが既定になります。
2. 「ダウンロード元」の欄で**速度を測定して推奨**をクリックします。公式ソースと中国国内ミラーからそれぞれ数 MB をダウンロードして速度を測り、速いほうを自動で選びます。
3. 「中国国内ミラー」を選ぶと、SAM やテキストプロンプトなどの補助モデルも中国国内ミラー（hf-mirror.com）からダウンロードします。
4. uv（Python のインストールに使うツール）と ffmpeg（動画のフレーム抽出に使う）は、通常は自動でダウンロードされます。自動でダウンロードできないときは、自分でインストールしてから「uv と ffmpeg（詳細設定）」でその場所を指定できます。

### 2.3 Xuntong AI（任意）

Xuntong AI プラットフォームのモデルで自動アノテーションしたい、モデルをアップロードしたい、アラート画像を取得したい、または「Xuntong 公式中継」でオンライン共同作業をしたい場合にだけ必要です。

1. 「Xuntong AI」の欄で **Xuntong AI アカウントにログイン**をクリックします。
2. ブラウザーで Xuntong AI のページが開きます。未ログインならまずログインします（普段 Xuntong にログインするときと同じです）。次に、ページに表示された確認コードが Wulabel に表示されたものと同じかを確かめて、**許可**をクリックします。
3. Wulabel に戻ると、数秒後に自動で**ログイン中**になり、アカウント名、プラン、残りの利用枠、使える認識方式（プロジェクトのクラスで認識、プラットフォームで有効にした専用モデル、大規模モデルによる汎用認識）が表示されます。Key をコピー＆ペーストする必要はありません。
4. ブラウザーが自動で開かない場合は、**開き直す**をクリックするか、ダイアログのアドレスをコピーして自分で開きます。
5. **ログアウト**：このパソコンの Key は削除され、ログイン時に自動作成された Key もプラットフォーム上で無効化されます。

API Key をすでに持っている場合や、Xuntong をプライベート環境に構築している場合は、**詳細：API Key の手動入力、プライベート環境のプラットフォームのアドレス**をクリックして入力し、**保存して接続をテスト**をクリックします。接続状態はこの欄に常に表示されます。

### 2.4 既存の Python 環境を使う（上級者向け）

PyTorch 入りの Python 環境がすでにあるなら、改めてダウンロードせずに使えます。

1. 「既存の Python 環境を使用（上級者向け）」を展開します。
2. **python.exe を選択**をクリックし、環境内の `python.exe`（例：`D:\envs\torch\Scripts\python.exe`）を選びます。
3. **保存**をクリックします。この環境には torch、torchvision、numpy、pillow が必要です。ONNX をエクスポートするには onnx も必要です。
4. ソフト独自の環境に戻すには、パスを空にして保存します。

### 2.5 更新の確認

ソフトは起動時に新しいバージョンがあるかを一度自動で確認し、あれば右下に通知を表示します。**今すぐ更新**をクリックすると、ソフトがバックグラウンドで新バージョンをダウンロードし、検証してから自動でインストールし、インストール後に自動で再起動します。途中でボタンを押す必要はありません（Windows ではインストールのプログレスバーが 1 つ表示されるだけです。Linux で .deb からインストールした場合も v0.4.2 から自動更新でき、インストール時にシステムのパスワードを一度求められることがあります）。プロジェクトとデータはそのまま残ります（v0.4.1 から）。「ダウンロード」をクリックしてダウンロードページを開くこともできます。あるバージョンの通知を今後表示したくない場合は、「このバージョンは今後通知しない」をクリックします。学習、学習環境のインストール、リアルタイム検証、共同作業の共有のいずれかが動いている最中に更新をクリックすると、先にそれらのタスクが一覧表示され、**今は更新しない**を選べます。更新のダウンロード中はダイアログを閉じてもかまいません。ダウンロードはバックグラウンドで続き、終わると自動でインストールされます。設定画面の一番下の「バージョン情報と更新」でも、手動で**更新を確認**をクリックできます。

更新の確認で送信するのは、ソフトのバージョン、OS の種類、ランダムな匿名 ID だけです。おおよその利用者数を数えるためのもので、画像、プロジェクト、個人情報は一切含みません。ネット接続による確認をしたくない場合は、「バージョン情報と更新」で**起動時に更新を自動確認**をオフにします。

### 2.6 言語・外観・Xuntong AI のスイッチ

設定画面の一番上で次の項目を変更できます：

- **语言 / Language**（v0.5.0 以降）：画面は 简体中文, 繁體中文, English, 日本語, 한국어, Español, Português, Русский, Deutsch, Français, Tiếng Việt, Bahasa Indonesia に対応しています。既定は **システムに合わせる**（中国語のシステムでは中国語、対応していない言語では英語）で、変更すると画面が再読み込みされます。学習ログ、エラーメッセージ、納品レポート、推論サービスパッケージの説明もこの言語になります。
- **外観**（v0.5.1 以降）：**システムに合わせる**、**ライト**、**ダーク**。既定ではシステムのライト／ダークに合わせます。アノテーション画面や画像プレビューなど画像を見る領域は、見やすさのため常にダークです。
- **Xuntong AI のスイッチ**（v0.5.2 以降）：「Xuntong AI」カード右上のスイッチです。簡体字中国語の画面では既定でオン、その他の言語では既定でオフです。オフのときは、アノテーション画面の Xuntong AI と認識ルール、データ画面のアラート画像の取得、デプロイ画面の Xuntong へのアップロード、共同作業画面の Xuntong 公式リレーが表示されません。必要ならオンにしてください。

## 3. プロジェクトの作成と開き方

**プロジェクトは 1 つのフォルダーです**。画像（コピーしたもの）、アノテーション、モデル、学習記録はすべてその中にあります。フォルダーごと別のパソコンにコピーすれば、そのまま開けます。

初めて使うときは、「プロジェクト」画面の上部に**初心者ガイド**が表示されます。学習環境のインストール、新規プロジェクト、画像のインポート、少量のアノテーション、学習、事前アノテーションとデプロイの 6 ステップを案内し、終わったステップには自動でチェックが付きます。右上の × で閉じられ、あとから「初心者ガイドを表示」で再表示できます。

「最近のプロジェクト」のカードには、プロジェクトのカバー画像、画像数、アノテーション済みの枚数（プログレスバー）、学習回数が表示されるので、各プロジェクトの進み具合がひと目でわかります。

### 3.1 新規プロジェクト

1. **プロジェクト**画面で**新規プロジェクト**をクリックします。
2. **プロジェクト名**：例「工事現場のヘルメット検出」。
3. **保存場所**：既定は「ドキュメント/Wulabel」です。**参照**をクリックして別のフォルダーに変えることもできます。プロジェクトはこのフォルダーの中に作られます。
4. **タスクの種類**（作成後は変更できません）：

   | タスク | アノテーション方法 | 向いている用途 |
   |---|---|---|
   | 物体検出 | 矩形ボックス | ヘルメット、車両、煙や炎の位置を見つける |
   | インスタンスセグメンテーション | ポリゴン | 正確な形が必要なもの：水たまりの範囲、ごみの山、欠陥の領域 |
   | 画像分類 | 画像 1 枚に 1 クラス | 画面の「正常 / 異常」、シーンの分類 |
   | キーポイント | 対象のボックス + テンプレートに沿って 1 点ずつ | 人体の姿勢（転倒、よじ登り）、物体の重要な部位 |

5. **クラス**（省略可）：アノテーションするクラスを先に書いておきます。カンマまたは改行で区切ります。例：「ヘルメット, 人, 反射ベスト」。書かなくても、あとでアノテーション画面からいつでも追加できます。
6. **作成**をクリックすると「プロジェクト「…」を作成しました」と表示され、自動で開きます。

### 3.2 プロジェクトを開く

- **最近のプロジェクト**の一覧でクリックすると開きます。一覧には各プロジェクトを最後に開いた日時が表示されます。
- 一覧にない場合は、**プロジェクトを開く…** をクリックしてプロジェクトフォルダーを選びます。
- プロジェクトフォルダーを移動すると、一覧に「フォルダーが見つかりません」と表示されます。**場所を指定…** をクリックして新しい場所を選べば、そのまま使い続けられます。フォルダーをすでに削除した場合は「一覧から削除」をクリックします（ファイルは削除されません）。

## 4. データのインポート

左側の**データ**をクリックします。

### 4.1 画像やフォルダーをインポート

1. まず画面上部でインポート方法を選びます。
   - **プロジェクトにコピー**：画像をプロジェクトフォルダーにコピーします。プロジェクトを丸ごと持ち運べます（推奨）。
   - **元のパスを参照するだけ**：画像の元の場所だけを記録します。余分な容量は使いませんが、元画像を移動できなくなります。
2. インポートします。
   - **フォルダーをインポート**をクリックしてフォルダーを選びます（サブフォルダー内の画像も自動で探します）。
   - または **その他のインポート → 画像ファイルをインポート**をクリックして画像を数枚選びます。
   - または画像やフォルダーを直接**ウィンドウにドラッグ**し、「マウスを離すと画像や動画をインポートします」と表示されたら離します。動画ファイルをドラッグした場合は、「動画からフレーム抽出」ダイアログが直接開きます（4.2 を参照）。
3. インポート中は進捗が 2 段階で表示されます。まず「N / M 枚を処理済み（フィンガープリント計算、サムネイル生成）」、次に「コピーして書き込み中 N / M 枚」（元のパスを参照するだけの場合は「プロジェクトに書き込み中」）です。一度に数万枚をインポートしても固まらず、インポート中もサムネイルは普段どおり見られます。選び間違えたときは**停止**をクリックできます。処理済みの画像はそのまま取り込まれます。完了すると、追加した枚数と、重複でスキップした枚数が表示されます。表示の中の**アノテーションを開始**をクリックすると、そのままアノテーション画面に移動します。

インポート時には自動で**内容による重複除外**（同じ画像は 2 回インポートされません）を行い、写真の EXIF 情報に従って**向きを補正**します。

### 4.2 動画をインポート（フレーム抽出）

1. **その他のインポート → 動画をインポート（フレーム抽出）** をクリックし、動画ファイルを 1 つ以上選びます。
2. 「動画からフレーム抽出」ダイアログで設定します。
   - **N 秒ごとに 1 フレーム抽出**：対象の変化が遅いなら間隔を長めにして、ほとんど同じ画像が大量にできるのを避けます。
   - **動画ごとの最大数** N フレーム（0 = 無制限）。
3. **フレーム抽出を開始**をクリックします。初回は ffmpeg（約 90 MB）が自動でダウンロードされます。2 回目以降は不要です。設定を間違えたときは**停止**をクリックできます。抽出済みのフレームはそのままインポートされます。
4. 抽出したフレームはプロジェクトにコピーされ、内容で自動的に重複除外されます。完了すると「動画 N 本から M フレームを抽出：新規 K 枚」と表示されます。

### 4.3 動画ストリームからフレーム抽出（RTSP / ライブ / 録画再生）

1. **その他のインポート → 動画ストリームからフレーム抽出（RTSP / ライブ / 録画再生）** をクリックします。
2. アドレスを入力します。RTSP カメラ（`rtsp://…`）、または http(s) のライブ、録画再生、オンデマンドの URL（mp4、m3u8、flv）です。
   - Hikvision：`rtsp://ユーザー名:パスワード@IP:554/Streaming/Channels/101`（メインストリーム）または `102`（サブストリーム）
   - Dahua：`rtsp://ユーザー名:パスワード@IP:554/cam/realmonitor?channel=1&subtype=0`
3. **接続をテスト**をクリックすると、解像度と、「ライブストリーム（終わりがないので上限を設定）」か「録画再生ストリーム · 長さ …」かが表示されます。
4. 設定します。
   - **N 秒ごとに 1 フレーム抽出**
   - **最大抽出数** N フレーム、**最大取得時間** N 分（0 = 無制限。ライブのみ）。**ライブは終わりのないストリームなので、どちらか一方は必ず設定します**
   - **ほぼ同じフレームをスキップ**にチェック：画面が静止しているときに重複画像を減らします。
5. **取得を開始**をクリックします。画像は取得しながら取り込まれ、データ画面に 1 枚ずつ表示されていきます。
6. 取得中に**最小化**をクリックすればほかの作業を続けられます。右下に「取得中 · N フレーム抽出済み」と表示され、**展開**で戻れます。**取得を停止**でいつでも終了でき、取得済みの画像は残ります。
7. 取得した画像はプロジェクトの `images/stream_アドレス_日時/` フォルダーに保存されます。完了後に**フォルダーを開く**で確認できます。

> アカウントとパスワードは取得時にだけ使います。パスワード入りのアドレスがプロジェクトのフォルダー名に書き込まれることはありません。

### 4.4 アノテーション付きデータセットをインポート

ほかで作ったアノテーション済みのデータは、アノテーションごとインポートできます。

1. **その他のインポート**をクリックし、プロジェクトの種類に応じて選びます。
   - 検出 / セグメンテーションのプロジェクト：**アノテーション付きデータセットをインポート（YOLO / COCO / VOC）**。YOLO（seg を含む）、COCO（セグメンテーションを含む）、VOC に対応しています。
   - キーポイントのプロジェクト：**アノテーション付きデータセットをインポート（YOLO-pose / COCO キーポイント）**。
   - 分類のプロジェクト：**分類データセットをインポート（クラスごとに 1 フォルダー）**。選んだフォルダーの下のサブフォルダーがそれぞれ 1 クラスになります（その間に train / val の階層があってもかまいません）。
2. データセットのルートフォルダーを選ぶと、形式が自動で判別されます。
3. 完了すると「YOLO データセットをインポートしました」などと、追加されたクラスが表示されます。

### 4.5 一括操作、取り消し、削除、クリア

データ画面上部の集計カード（未アノテーション、アノテーション済み、スキップ済み）はクリックできます。1 回クリックするとその種類の画像だけを表示し、もう 1 回クリックするとすべてに戻ります。下の絞り込みボタンも同じです。

どれも**管理**メニューにあります。

- **まとめて選択**：選択モードに入り、画像をクリックしてチェックを付けます。**Shift** を押しながら別の画像をクリックすると範囲選択できます。「このページをすべて選択」でこのページを、「N 枚をすべて選択」で現在の絞り込み条件のすべての画像を選択します。選択したら、次の操作ができます。
  - **スキップにする**：これらの画像を学習に使いません。
  - **未アノテーションに戻す**：すでにアノテーションがある画像はアノテーション済みに戻ります。
  - **アノテーションへ**：選択した画像だけをアノテーション画面に送り、1 枚ずつアノテーションします。
  - **分割**：学習セット、検証セット、テストセットのいずれかに移動します（アノテーション済みの画像にだけ有効。10.1 を参照）。
  - **削除**。
  絞り込みを切り替えたりページを移動したりすると、選択はクリアされます。見えていない画像を誤って削除しないためです。最後に**完了**をクリックして終了します。
- **前回のインポートを取り消す（N 枚）**：インポートを間違えたときに、前回インポートした画像をワンクリックで削除します（動画ストリームの 1 回の取得も 1 回のインポートとして扱います）。
- **すべての画像をクリア**：プロジェクト内のすべての画像を削除します。

削除すると画像のアノテーションも一緒に削除され、元に戻せません。プロジェクトにコピーした画像の複製は削除されますが、パソコン上の元画像には影響しません。たくさん削除するときは、ダイアログに削除の進捗が表示されます。

### 4.6 画像品質チェック

ぼやけた画像、暗すぎる画像、露出オーバーの画像はアノテーションしにくく、学習でもモデルを誤った方向に導きがちです。先に取り除いておきましょう。

1. **管理 → 画像品質チェック（ぼやけ、暗すぎ、露出オーバー）** をクリックします。
2. 既定で**未アノテーションの画像のみ表示**にチェックが入っています。すべてを確認したい場合はチェックを外します。
3. **チェックを開始**をクリックします。
4. 結果は問題ごとに分類されます：**ぼやけ**、**暗すぎ**、**露出オーバー**、**コントラストが低い**。上のタブをクリックして絞り込めます。各画像の下に、鮮明さ、明るさ、露出オーバーの割合、コントラストの数値が表示されます。
5. 対処します。
   - **1 枚ずつ確認**：アノテーション画面に移動して 1 枚ずつ見て、自分で判断します。
   - **スキップにする**：「スキップ」にして学習に使いません（画像は残り、あとで取り消せます）。
   - **削除**：そのまま削除します。

### 4.7 Xuntong AI からアラート画像を取得

モデルを Xuntong AI プラットフォームにデプロイしたあと、現場のアラートのスクリーンショット（特に誤検出や検出漏れ）は、最も補充する価値のあるデータです。

1. まず**設定**で Xuntong AI を設定します（2.3 を参照）。
2. **データ**画面で **その他のインポート → Xuntong AI からアラート画像を取得**をクリックします。
3. 期間（直近 1 / 3 / 7 日。プラットフォームのアラート画像は 7 日間保存されるので、定期的に取得しましょう）、モデル（すべて、またはいずれか 1 つ）、**最大 N 枚**を選びます。アラート記録が作られるのは、通知チャネルを設定した Xuntong アカウントだけです。
4. 既定で**プラットフォームが認識したボックスを事前アノテーションとして使用**にチェックが入っています。クラス名でプロジェクトのクラスに対応付け、ないものは新規作成します。
5. **取得を開始**をクリックします。画像はプロジェクトの `images/xuntong_日時/` フォルダーに保存され、認識したボックスは破線（ソースは「Xuntong」）で表示されます。
6. アノテーション画面で確認します。誤検出のボックスは削除し（対象のない画像はそのまま **Enter** で完了してネガティブサンプルにします）、漏れているものは追加して、再学習します。

## 5. アノテーション

左側の**アノテーション**をクリックします。

### 5.1 アノテーション画面を知る

- **上部**：左右の矢印で画像を切り替え、現在の画像名と番号（何枚目 / 全何枚。番号をクリックして数字を入力すると、その画像に直接移動します）、解像度、状態ラベル（未アノテーション / アノテーション済み / スキップ済み。対象のない画像は「対象なし」と表示）が表示されます。絞り込みボタンは**すべて / 未アノテーション / アノテーション済み / スキップ済み**です（チームで共同作業しているときは**すべて / 未アノテーション / レビュー待ち / 承認済み / スキップ済み / 差し戻し**になり、状態ラベルも「レビュー待ち」「承認済み」と表示されます。9.4 を参照）。右端には拡大率と保存状態（保存しました / 未保存 / 保存中… / 保存に失敗しました）が表示されます。
- **左側のツールバー**：選択、ボックスを描く（またはポリゴンを描く）、SAM スマート選択、元に戻す、やり直す、前の画像をコピー、キーフレーム補間、後方へ追跡、ウィンドウに合わせる。マウスを重ねると説明とショートカットキーが表示されます。
- **中央**：画像キャンバスです。マウスホイールで拡大・縮小し、スペースキーを押しながら、または右ボタンでドラッグして画面を動かします。
- **右側**：「AI アシスト」、「クラス」、「この画像のオブジェクト」（分類プロジェクトでは「この画像のクラス」）、「完了」のパネルがあります（チームで共同作業しているときは、このパネルは「レビュー」になります）。
- **キャンバスの下**：現在のプロジェクトで使えるショートカットキーのヒントです。**?** を押すと、すべてのショートカットキーの説明パネルが開きます。
- **最下部**：前後の画像のサムネイルバーです。クリックするとその画像に移動します。サムネイル右上の小さな丸は状態を表します。青はアノテーション済み、灰色はスキップ済み、丸がなければ未アノテーションです。

変更は**自動保存**されるので、手動で保存する必要はありません。

### 5.2 クラスの追加と管理

1. 右側の「クラス」の入力欄「新しいクラス名（Enter で追加）」にクラス名（例：「ヘルメット」）を入力し、Enter を押します。
2. 最初の 9 クラスは数字キー **1–9** ですばやく切り替えられます。現在のクラスはハイライト表示されます。
3. クラスの横の編集ボタンをクリックすると、次のことができます。
   - 名前や色の変更
   - **英語プロンプト**の入力（「テキストプロンプト」による自動アノテーション用。カンマ区切りで複数書けます。例：`helmet, hard hat`）
   - **認識の説明**の入力（Xuntong AI の「プロジェクトのクラスで認識」用。このクラスが具体的に何を指すか、どんな場合に該当する / しないか。例：「ヘルメットをかぶっていない人。かぶっていてもあご紐を締めていなければ該当」）
   - クラスの削除。このクラスにすでにアノテーションがある場合は、「マージ先…」で別のクラスを選ぶと、アノテーションはそのクラスに変わり、失われません（クラスを間違えたときや、2 つのクラスを 1 つにまとめたいときに便利です）。選ばなければそのまま削除され、アノテーションも一緒に削除されます。

### 5.3 物体検出：ボックスを描く

1. **1–9** でクラスを選びます。
2. **R** を押し（または左側のボックスツールをクリックし）、対象の上で**マウスを押したままドラッグしてボックスを描きます**。
3. 調整：**V** で選択ツールに切り替え、ボックスをクリックすると、ドラッグで移動したり、辺や角を引っ張ってサイズを変えたりできます。
4. 削除：ボックスを選択して **Del** か **Backspace** を押します。**Esc** で選択を解除します。
5. クラスの変更：ボックスを選択して数字キーを押すか、右側の「この画像のオブジェクト」で変更します。
6. **H** でボックス上のクラス名を非表示 / 表示にします。ボックスが密集しているときに見やすくなります。

### 5.4 インスタンスセグメンテーション：ポリゴンを描く

1. クラスを選び、**R** を押します。
2. 対象の縁に沿って**1 点ずつクリック**します。
3. **ダブルクリック**するか **Enter** を押すとポリゴンが閉じます。点を間違えたら **Backspace** で直前の点を取り消します。
4. ポリゴンを選択すると、頂点をドラッグして微調整できます。
5. もっと速い方法は、**S** を押して SAM スマート選択を使うことです。クリックするだけでポリゴンが自動で作られます（第 6 章を参照）。

### 5.5 画像分類：1 キーで 1 枚

1. 画像を見て、数字キー **1–9** でクラスを選びます。画面の左上に現在のクラスが表示されます。
2. 右側の**選択後に次へ**スイッチをオンにすると、数字キーを押したあと自動で次の画像に進みます。1 キーで 1 枚です。
3. **Del** でこの画像のクラスをクリアします。**Ctrl+D** で前の画像のクラスを引き継ぎます。

### 5.6 キーポイント

1. まず右側の**キーポイントテンプレート**を確認します。既定は「COCO 人体 17 点」（鼻、左目、右目……左足首、右足首）です。変更するには**編集**をクリックします。
   - **テンプレート名**
   - **点の名前**（1 行に 1 つ。点の順番がアノテーション時にクリックする順番になります）
   - **接続線**（1 行に番号のペアを 1 つ。例：`1-2`。骨格の描画に使います）
   - **COCO 人体 17 点を使用**をクリックして既定に戻すこともできます。
   - キーポイントのアノテーションがすでにある場合は、名前と接続線だけ変更でき、点の数は増減できません。
2. クラスを選び、**R** で対象のボックスを描きます。
3. ボックスを描いたら、案内に従って**キーポイントを順番にクリック**します（画面の下に、次に打つ点が「左肩 をクリック（6/17）」のように表示されます）。
   - 普通のクリック：見えている点
   - **Shift + クリック**：隠れている点
   - **N**：見えない点をスキップ
   - **Backspace**：前の点に戻る
   - **Esc**：この対象を終了
4. 微調整：対象を選択すると、キーポイントを直接ドラッグできます。右側に各点の状態が一覧表示されます。名前をクリックするとその点だけ打ち直せ、状態をクリックすると「表示 / 隠れている」を切り替えられます。
5. 対象を選択して**キーポイントを打ち直す**をクリックすると、最初の点からアノテーションし直せます。

### 5.7 前の画像をコピー、元に戻す・やり直す

- **Ctrl+D**（または左側のコピーボタン）：前の画像のアノテーションを丸ごと持ってきます。似たシーンや連続フレームでとても便利です。分類プロジェクトでは、前の画像のクラスを引き継ぎます。
- **Ctrl+Z** で元に戻す、**Ctrl+Y** でやり直します。

### 5.8 完了、スキップ

1 人でアノテーションするときはレビューは不要です。対象をアノテーションした画像は自動で「アノテーション済み」になり、そのまま学習に使われます。右側の「完了」パネル：

- **完了して次へ**（ショートカットキー **Enter**）：後ろにある最初の未アノテーションの画像に進みます。
  - その画像に本当に対象がないときは、Enter を押すと「対象なし」として記録され、**ネガティブサンプル**として学習に使われます（こうした画面で誤検出しないようモデルに教えます）。押し間違えたときは、表示の中の**取り消す**をクリックします。
  - 一括で事前アノテーションした画像（破線のボックス）は、確認・修正してから Enter を押すとアノテーション済みになります。
- **スキップ**（ショートカットキー **X**）：「スキップ済み」にして、この画像を学習に使いません。ぼやけた画像や関係のない画像に向いています。
- **取り消す**：「対象なし」や「スキップ済み」を元の状態に戻します。
- **Shift+D**：次の未アノテーションの画像に直接移動します。

最後の 1 枚を終えると「この分のアノテーションが完了しました」と表示され、アノテーション済みの枚数とまだの枚数が示されます。**学習へ**か、**未アノテーションの続きを進める**をクリックできます。

上部の絞り込みで「スキップ済み」を選ぶと、スキップした画像を見つけて見直せます。

レビューの流れがあるのは、チームで共同作業しているとき（メンバーを追加したか、リアルタイム共同作業を開始したとき）だけです。このときパネルは「レビュー」になり、ボタンは**承認して次へ**、**差し戻し**になります。画像が多いときは、左側の**レビュー**画面でまとめてレビューすると速くなります（9.4 を参照）。

### 5.9 動画フレーム：キーフレーム補間、後方へ追跡

検出とキーポイントのプロジェクトで使えます。動画から抽出したフレーム（同じフォルダー内で、ファイル名順に並んだもの）は、1 フレームずつ描かなくても済みます。

**キーフレーム補間**（対象が一定の速さで動く区間）：

1. 区間の最初のフレームに移動し、対象をすべてアノテーションします（これが「キーフレーム」です）。
2. 区間の最後のフレームに移動し、同じ対象をアノテーションします。
3. 最後のフレームで、左側の**キーフレーム補間**ボタンをクリックします。
4. クラスと位置をもとに両端の対象を 1 対 1 で対応付け、間のフレームを自動で補完します。「間の N フレームで M 個の対象を補間しました」と表示されます。両端で対応が取れない対象は別途知らせます。

**後方へ追跡**（対象の動きが不規則なとき）：

1. 現在のフレームで対象をアノテーションします。
2. 左側の**後方へ追跡**ボタンをクリックし、表示された小さなウィンドウに**フレーム数**（既定 30、最大 500）を入力して**追跡**をクリックします。
3. このフレームのボックスから 1 フレームずつ追っていきます。対象が隠れたり見失ったりすると止まります。後ろに手動でアノテーションしたフレームがあればそこでも止まり、人のアノテーションを上書きすることはありません。
4. 追跡が終わると、最後に追跡できたフレームに自動で移動します。ボックスがずれていたらドラッグして直し（ドラッグしたボックスは手動アノテーションになり、このフレームが新しいキーフレームになります）、もう一度**後方へ追跡**をクリックして続けます。

補間や追跡で作られたボックスは、右側の「この画像のオブジェクト」でソースが「補間」「追跡」と表示されます。補間や追跡をやり直すとこれらは置き換えられますが、手動で付けたボックスは変更されません。

> 手間を省くコツ：まず少量（数十～200 枚ほど）を手でアノテーションして初版のモデルを学習し、そのモデルで残りの画像を事前アノテーションします（第 12 章）。あとは間違いを直すだけです。

## 6. AI アシストによるアノテーション

自分のモデルがまだなくても、AI にアノテーションを手伝ってもらえます。

### 6.1 SAM スマート選択

1. クラスを選び、**S** を押します（または左側の SAM ボタンをクリック）。
2. 初回はコンポーネントのインストールとモデルのダウンロードがあり、数分かかることがあります。画面に「SAM を準備中…」と表示され、右下には「ダウンロード・インストール中」とファイルごとの進捗が表示されます（中断しても続きからダウンロードし、初回のみです）。NVIDIA GPU があれば SAM ViT-B、なければ軽量な SlimSAM を使います。
3. 対象の上で**クリック**すると、対象の輪郭が自動で選択されます（プレビュー）。
   - 選びすぎたとき：余分な部分を **Shift + クリック**して除外します。
   - 足りないとき：選ばれていない部分をもう一度クリックします。
   - クリックを間違えたら **Backspace** で最後の点を取り消します。
   - **ボックスをドラッグ**して対象を囲むこともできます。
4. よければ **Enter** で現在のクラスとして採用します。**Esc** で破棄します。
5. 結果：セグメンテーションのプロジェクトではポリゴン、検出のプロジェクトでは対象にぴったり合ったボックス、キーポイントのプロジェクトでは新しい対象が 1 つできます（そのあと「キーポイントを打ち直す」で点を打ちます）。

### 6.2 テキストプロンプト

クラス名をもとに、画像内の対象を自動で探します。

1. 右側の「AI アシスト」で**テキストプロンプト**を選びます。
2. モデルは英語しか理解しません。よく使われる中国語のクラス名（安全帽、人员、电动车、渣土车、锥桶など 100 以上）は自動で英語に対応付けられ、クラス名の後ろに「安全帽 · helmet」のように表示されます。クラス名にこれらの語が含まれていても対応します（例：中国語の「红色安全帽」）。日本語などほかの言語のクラス名や、対応しない・変えたいものは、クラスの編集で**英語プロンプト**を入力します。
3. **信頼度**を調整します。見つかりすぎるなら上げ、見つからないなら下げます。
4. **この画像をアノテーション (P)** で現在の画像を、**一括事前アノテーション**でまとめてアノテーションします。
5. 初回はモデルのダウンロードがあり、数分かかります。セグメンテーションのプロジェクトでは、さらに SAM でポリゴンを作ります。

### 6.3 Xuntong AI

（Xuntong AI の詳しい使い方は第 16 章を参照してください。）

1. まず**設定**で Xuntong AI を設定します（2.3 を参照）。
2. 「AI アシスト」で **Xuntong AI** を選び、「認識モデルを選択」で次のいずれかを選びます。
   - **プロジェクトのクラスで認識（推奨）**：プロジェクトにあるクラスだけを探します。クラス名はそのまま対応し、各クラスの認識の説明と全体ルールに従うので、不要なものまで認識することはありません。
   - プラットフォームで有効にした**専用モデル**
   - **大規模モデルによる汎用認識**：安全上の危険要因のカテゴリ（消防、電気、環境衛生など）で探します。
3. **この画像をアノテーション (P)** か**一括事前アノテーション**をクリックします。専用モデル（ごみ分別など）での一括事前アノテーションは高速で、8 枚を 1 バッチとして 2 バッチを同時に送ります。大規模モデルとプロジェクトのクラスで認識は 1 枚ずつ処理するので、少し遅くなります。
4. Xuntong AI は画像 1 枚につき 1 回の呼び出しとしてカウントされ、アカウントのプランの利用枠を消費します。一括処理の前に確認が表示されます。

### 6.4 認識ルール：AI に認識方法を伝える

クラス名だけでは、AI はあなたが本当に求めているものがわからないことがあります。ルールをはっきり書くか、直接 AI とチャットしましょう。

1. 「AI アシスト」の見出しの横にある**認識ルール**をクリックすると、右側に認識ルールのパネルが開きます。
2. **AI とチャット**：どう認識してほしいかを普段の言葉で伝えます。例：「ヘルメットをかぶっていてもあご紐を締めていなければ未着用とみなす」「反射ベストは対象外」「画面の下半分の通路だけを見る」。「この画像の左の人はなぜ認識されなかったの？」と質問することもできます。
   - 既定で**現在の画像を添付**にチェックが入っており、AI は新しいルールでこの画像を試し認識します。
   - AI がルールの更新を提案すると、「AI がルールの更新を提案」と具体的な内容が表示されます。**このルールを適用**をクリックしたときだけ保存されます。
   - 試し認識の結果があれば、**試し認識のボックス N 個をこの画像に追加**をクリックすると、そのまま事前アノテーションとして使えます。
   - `Ctrl+Enter` で送信します。会話のたびに Xuntong AI の利用枠を消費します。
3. **現在のルール**：**全体ルール**（すべてのクラスに適用）と**クラスごとの認識の説明**を直接編集し、**ルールを保存**をクリックします。
4. 以降、Xuntong AI の「プロジェクトのクラスで認識」で事前アノテーションすると、このルールに従います。
5. （任意）「現在のルール」の一番下で **Xuntong プラットフォームに同期**をクリックすると、クラスとルールが Xuntong プラットフォームに保存されます。既定では**無効**なので、プラットフォームの現在の認識には影響しません。紐付けたあとは、ルールを保存または適用するたびに内容が自動で同期されます（Xuntong コンソールで設定した有効 / 無効や適用シーンは変更しません）。
6. Xuntong プラットフォーム自体の認識（撮影アシスタント、アラート送信）でも必要なクラスだけを通知させたい場合は、**プラットフォームの認識にもこのルールを使用**をオンにします。注意：オンにすると、Xuntong アカウント全体の認識がこのプロジェクトのクラスに従います。適用シーンは Xuntong コンソールの「認識ルール」で調整できます。同期をやめるには**紐付けを解除**をクリックします（プラットフォーム上のルールは削除されません）。Xuntong アカウントごとに認識ルールは最大 20 セットまでです。

制限：プロジェクトのクラスで認識できるのは最大 30 クラス、クラス名は 30 文字以内です。全体ルールは最大 1000 文字、クラスごとの認識の説明は最大 500 文字です。

共同作業中は、メンバーも認識ルールを開いて AI とチャットできます（ホストが AI アシストを許可している場合。ホストの利用枠を使います）。ルールを変更できるかどうかは、「メンバーはクラスと認識の説明を追加・変更できます」スイッチに従います。

### 6.5 アシストの結果を確認する

AI が付けたボックスやポリゴンは**破線**で表示されます。一通り確認し、間違いは削除し、ずれは直し、漏れは追加してから、**Enter**（完了して次へ）を押します。

## 7. データのヘルスチェック

左側の**ヘルスチェック**をクリックすると、データの問題をワンクリックで洗い出せます。

1. チェック方法を選びます。
   - 学習済みのモデルがある場合：「モデルでチェック：モデル名 · mAP50 …」を選ぶと、ルールとモデルの両方でチェックします。
   - モデルがない場合：「ルールチェックのみ（モデルを使わない）」を選びます。
2. **ヘルスチェックを開始**をクリックします。進捗は段階ごとに表示されます：「重複チェック：フィンガープリントを計算中」→「重複チェック：画像どうしを比較中」→「モデルでチェック中」。画像が多いと数分かかります。**停止**をクリックすることもできます（止めた回の結果は保存されません）。ヘルスチェック画面を離れて戻ってきても、実行中の進捗を確認できます。チェックした画像のフィンガープリントはキャッシュされ、次回は新しく追加した画像だけを計算します。
3. 結果は問題の種類ごとに表示されます。

   | 問題 | 意味 | モデルが必要 |
   |---|---|---|
   | アノテーション漏れの疑い | モデルはここに対象があると強く判断しているが、アノテーションがない | はい |
   | クラス誤りの疑い | ボックスの位置は合っているが、クラスがモデルの判断と違う | はい |
   | ボックスが不正確 | クラスは同じだが、ボックスとモデルの予測の重なりが小さい | はい |
   | 余分なボックスの疑い | ボックスがあるが、モデルはその位置に何も見ていない | はい |
   | 極小ボックス | 短辺が 8 ピクセル未満で、モデルはほとんど学習できない | いいえ |
   | 重複ボックス | 同じ画像で同じクラスの 2 つのボックスがほぼ完全に重なっている | いいえ |
   | 重複画像 | 画面がほぼ同じ画像。評価結果が実際より高く出る原因になる | いいえ |
   | クラスなし | ボックスにクラスがなく、学習に使われない | いいえ |

4. 各問題に対して、次の操作ができます。
   - **修正する**：アノテーション画面に移動し、そのボックスをハイライト表示します。
   - **アノテーションとして追加**：アノテーション漏れの疑いのとき、モデルの判断どおりにボックスを追加します。
   - **問題ではありません**：無視して、今後のヘルスチェックで指摘しないようにします。
   同じ種類の問題が多いときは、**すべてアノテーションとして追加**（アノテーション漏れの疑い）や**すべて無視**でまとめて処理できます。無視した問題は「N 件を無視しました · 復元」をクリックすると元に戻せます。
5. アノテーション画面で修正した画像は、ヘルスチェック画面に戻ると「変更済み」になり、既定で折りたたまれます。ヘルスチェックをやり直す必要はありません。
6. 重複画像はグループごとに表示され、各画像に状態とアノテーション数が表示されます。緑の枠が残す画像で、既定ではアノテーションが最も充実したもの（承認済み > アノテーション済み > アノテーションが多いもの）が選ばれます。ほかの画像をクリックすると変更でき、ダブルクリックするとアノテーション画面で確認できます。**各グループで 1 枚だけ残す**をクリックするとほかが削除されます。アノテーションのある画像が誤って削除されることはありません。
7. 画面の下には**クラスの分布**（ボックス数 · 画像数）と**ボックスサイズの分布**もあり、クラスが少なすぎるときやボックスが小さすぎるときはアドバイスが表示されます。分類プロジェクトでは、クラス誤りの疑いと重複画像だけをチェックします。

## 8. データセットのバージョン

ある時点のデータをスナップショットとして保存しておけば、比較や巻き戻しが簡単です。

1. **データ**画面で **管理 → データセットのバージョン（スナップショット保存、比較、復元）** をクリックします。
2. **バージョン名**（例：v1、夜間画像を追加）と**メモ**（任意）を入力し、**現在のデータを新しいバージョンとして保存**をクリックします。
   - バージョンに保存されるのは、現在のアノテーション済みの画像（チームで共同作業しているときはレビュー待ちと承認済みの画像）とアノテーション、および学習 / 検証 / テストの分割です。
3. バージョン一覧の各行では、次の操作ができます。
   - **現在のデータと比較**：追加された画像、外された画像、アノテーションが変更された画像と、クラスごとのアノテーション数の変化を確認します。
   - **このバージョンをエクスポート**
   - **このバージョンに復元**：復元の前に、現在のデータを「復元前の自動バックアップ」バージョンとして自動保存するので、いつでも元に戻せます。
   - **名前・メモを変更**、**このバージョンを削除**（削除されるのはスナップショットだけで、現在のデータや学習済みのモデルには影響しません）
4. **学習**画面の「学習データ」で、特定のバージョンを選んで学習できます（10.1 を参照）。

## 9. 複数人での共同作業

画像が多くて 1 人では終わらないときは、2 つの方法があります。

- **リアルタイム共同作業**：複数人で同じプロジェクトを同時にアノテーションします。あなたのパソコンがホストになり、メンバーはブラウザーでアドレスを開いてログインすればアノテーションでき、変更はリアルタイムに同期されます。LAN でもインターネット越しでも使えます。
- **オフラインのパッケージ分割**：ネットワークがない場合や、データを社外に出せない場合に、画像をアノテーションパッケージに分けてほかの人にコピーで渡し、アノテーション後にマージして戻します（9.10 を参照）。

### 9.1 リアルタイム共同作業を開始する

1. 左側の**共同作業**をクリックします。
2. まず「メンバー」でメンバーを追加します。**名前**（ログイン用）を入力し、**役割**を選びます。パスワードは既定でランダムに作られます（変更可）。**追加**をクリックします。表示されたアカウントとパスワードをコピーして本人に送ります（表示されるのはこの 1 回だけです。忘れたら**パスワードを再設定**できます）。
   - **アノテーター**：自分に割り当てられた画像だけを閲覧・編集できます。
   - **レビュアー**：すべての画像を閲覧でき、承認や差し戻しを担当します。
   - あなた自身は**管理者**です。
3. 「共有」で共有方法を選びます。
   - **LAN**：メンバーがあなたと同じ社内ネットワーク、同じ Wi-Fi にいる場合。最も速く、データが社外に出ません。
   - **オンライン · 自前の中継**：メンバーがインターネット越し（外注先、在宅勤務）の場合。自前のクラウドサーバーに Wulabel の中継サービスをインストールする必要があります（リポジトリの `relay/` フォルダーにデプロイ手順があります）。**中継 URL** と**シークレット**を入力します。データは自前のサーバーだけを経由します。
   - **オンライン · Xuntong 公式中継**：メンバーがインターネット越しで、自前のサーバーもない場合に使います。あなたの Xuntong API Key で Xuntong の中継サーバーに接続します。画像とアノテーションは Xuntong のサーバーを経由して転送されます（転送のみで保存はしません）。データが機密性の高いプロジェクトでは、ほかの 2 つの方法を使ってください。
4. **あなたの名前**（メンバーに表示されるホスト名）を入力します。**ポート**は通常変更不要です（既定 8765）。
5. オプション：
   - **メンバーは AI アシストを使えます**：SAM スマート選択、モデルの事前アノテーション、テキストプロンプトはすべてあなたのパソコンで計算します。AI との認識ルールのチャットはあなたの Xuntong の利用枠を使います。
   - **メンバーはクラスと認識の説明を追加・変更できます**：クラスを削除するとそのアノテーションもすべて消えるため、クラスの削除はあなただけが行えます。
   - **メンバーの画面に本人の名前入りの透かしを重ねる**：スクリーンショットの流出を防ぎます。外注向けです。
6. **共同作業を開始**をクリックします。画面に **LAN アドレス**（例：`http://192.168.1.20:8765/`）が表示されます。オンラインモードでは**外部アドレス**（例：`https://relay.example.com/s/xxxxxxxxxxxx/`）も表示されます。アドレスと各自のアカウント・パスワードをメンバーに送ります。
   - 初めて開始するとき、Windows のファイアウォールの確認が表示されることがあります。**アクセスを許可する**をクリックします。
   - 共同作業中でも、3 つのオプションはいつでも変更でき、すぐに反映されます。
   - **共同作業を停止**をクリックすると、メンバーはすぐに切断されます。保存済みのアノテーションには影響しません。プロジェクトを切り替えたり Wulabel を閉じたりしても停止します。

### 9.2 タスクの割り当て

1. 「タスクを割り当て」でアノテーターを選びます（**すべてのアノテーターを選択**も可）。
2. 範囲を選びます。
   - **まだ誰にも割り当てていない未アノテーションの画像**（最もよく使います）
   - **未アノテーションの画像すべて**（割り当て済みも再割り当て）
   - **未レビューのもの**（未アノテーション + レビュー待ち）
3. **1 人あたり** N 枚：空欄なら範囲内の画像を均等に割り振ります。画像の順番どおりに連続して割り当てるので、動画の連続フレームは同じ人に割り当てられます。
4. **割り当て**をクリックします。メンバー側では新しいタスクが自動で表示されます。
5. メンバー一覧で、各メンバーの割り当て枚数、提出枚数、差し戻し枚数を確認できます。**タスクを回収**をクリックすると、その人がまだ提出していない画像を回収し、ほかの人に割り当て直せます。

### 9.3 メンバーのアノテーション方法（ブラウザー）

1. Chrome か Edge でホストから届いたアドレスを開き、**名前**と**パスワード**を入力してログインします。自分のパソコンなら**ログイン状態を保持**にチェックを入れてもかまいません。ソフトのインストールは不要です。
2. アノテーターはログインするとアノテーション画面になり、自分に割り当てられた画像だけが表示されます。レビュアーはログインするとレビュー画面（9.4 を参照）になり、上部で**アノテーション**に切り替えられます。操作は Wulabel と同じです：ボックスの描画、ショートカットキー、AI アシスト（ホストが許可している場合）。右上に今日の提出枚数が表示されます。
3. アノテーションが終わったら**提出して次へ**（`Enter`）をクリックし、レビューを待ちます。対象が本当に写っていない画像は、そのまま提出すればネガティブサンプルとしてレビュー待ちになります（分類プロジェクトでは、先にクラスを選ばないと提出できません）。
4. 差し戻された画像は絞り込みの**差し戻し**にあり、画像の上に差し戻しの理由が表示されます。修正してから再提出します。
5. ほかの人がアノテーション中の画像では「「○○」がこの画像をアノテーション中です」と表示され、閲覧のみになります。相手の変更はリアルタイムに表示され、相手が離れると自動で編集できるようになります。
6. ネットワークが切れると右上に「リアルタイム接続が切れました。再接続中…」と表示されます。復旧すると自動で再開し、保存済みのものは失われません。

### 9.4 レビュー

チームで共同作業しているときの画像の状態は、**未アノテーション** → アノテーターが提出すると**レビュー待ち** → レビュアーが承認すると**承認済み**、と進みます。差し戻された画像は「差し戻し」にあります。データ画面、アノテーション画面、ヘルスチェック画面の絞り込みと状態ラベルは、すべてこの名前を使います。1 人でアノテーションするときはレビューの手順がないので、「アノテーション済み」とだけ表示されます。

レビューには専用の**レビュー**画面があり、チームで共同作業しているとき（メンバーを追加したか、リアルタイム共同作業中のとき）だけ表示されます：

- あなた（管理者）：左側のナビゲーションに**レビュー**が増え、横の数字はレビュー待ちの枚数です。共同作業を停止してメンバーを全員削除すると、この項目は自動で消えます。
- レビュアー（ブラウザー）：ログインすると最初からレビュー画面になり、上部で**レビュー / アノテーション**を切り替えられます。
- アノテーターにはレビュー画面は表示されません。

**絞り込み**

1. **メンバー**：一番上の行にメンバーごとのレビュー待ちの枚数と承認率（承認された回数 ÷ レビューされた回数）が表示され、承認率が 80% 未満だと黄色になります。メンバーをクリックするとその人の画像だけ、**すべてのメンバー**をクリックすると全員の画像が表示されます。
2. **状態**：複数選べます。既定では**レビュー待ち**だけが表示されます。承認済み、差し戻し、未アノテーション、スキップ済みの画像も見られます。
3. **ファイル名で検索**：ファイル名の一部を入力します。
4. **並べ替え**：提出日時順（新しい順）かファイル名順です。
5. **その他の絞り込み**：特定のクラスを含むものだけ、対象なしのみ（ネガティブサンプル）、差し戻し歴ありのみに絞り込めます。グリッドの画像サイズも変えられます。**絞り込みをクリア**で既定に戻ります。

**まとめてレビュー（グリッド）**

1. グリッドの各画像にはボックス、ポリゴン、キーポイントが描かれています（分類プロジェクトではクラス名を表示）。画像の下にはファイル名、アノテーター、クラスごとの個数、提出日時が表示され、差し戻されたことのある画像には「差し戻し歴あり」と付きます。
2. 画像をクリックすると選択され、`Shift` を押しながら別の画像をクリックすると、その間の画像もまとめて選択されます。**このページをすべて選択**や、**絞り込み結果をすべて選択**（後ろのページも含みます。「山田さんのレビュー待ちを全部承認」したいときに便利）も使えます。
3. **承認**をクリック：選んだ画像が「承認済み」になります。
4. **差し戻し…**をクリック：よくある理由（アノテーション漏れ、ボックスが不正確、クラスの誤り、余分なアノテーション、キーポイントが不正確）にチェックを入れるか、どこを直すべきかを書きます。選んだ画像には同じ理由が付き、それぞれ元のアノテーターの「差し戻し」に戻ります。
5. ほかの人が編集中の画像や、レビュー待ちでない画像は自動でスキップされ、何枚スキップしたかがメッセージに表示されます。
6. 操作を間違えたら：メッセージの**元に戻す**は 10 秒間有効で、今回処理した画像を元の状態に戻せます（その後ほかの人が変更した画像はそのままです）。
7. 1 枚をよく見たいとき：選んでから**スペース**で拡大し、左右キーで画像を切り替え、もう一度スペースで閉じます。

**1 枚ずつレビュー**

1. 画像をダブルクリックするか、**1 枚ずつ**をクリックすると、大きな画像で 1 枚ずつ確認できます。右側にはアノテーター、提出日時、差し戻されたことがあるか、クラスごとのアノテーション数が表示されます。
2. 問題がなければ**承認**（`A`）をクリックすると、自動で次の画像に進みます。問題があれば**差し戻し**（`R`）をクリックします。
3. 自分で直したいとき：**自分で修正**（`E`）をクリックすると、今の画像のまとまりを持ってアノテーション画面に移ります。直し終わったらアノテーション画面の**レビューに戻る**をクリックすると戻り、絞り込みと位置もそのまま残っています。
4. **グリッドに戻る**（`Esc`）をクリックします。

**抜き取り検査**

メンバーの画像が多いときは、全部を見なくてもかまいません：

1. **抜き取り検査…**をクリックし、メンバーと割合（10% / 20% / 50% を抽出）を選んで、**抜き取り検査を開始**をクリックします。
2. その人のレビュー待ちの画像から、その割合の枚数がランダムに抜き出されるので、1 枚ずつレビューします（操作は上と同じです）。
3. 終わると合格率が表示されます。合格率が高ければ**残り N 枚をすべて承認**、低ければ**残り N 枚をすべて差し戻す**をクリックします。差し戻しの理由は「抜き取り検査で不合格でした。自分で確認してから再提出してください」になります。今は処理しないでおくこともできます。

これまでどおり、アノテーション画面で**レビュー待ち**に絞り込み、1 枚ずつ確認して**承認して次へ**（`Enter`）か**差し戻し**をクリックしてもかまいません。

### 9.5 進捗、作業量、履歴

- **オンライン**：メンバー一覧に、誰がオンラインか、どの画像を見ているかが表示されます。クリックするとその画像に移動して確認できます。アノテーターの行で**画像を見る**をクリックすると、レビュー画面でその人のレビュー待ちの画像を直接見られます。左側のナビゲーションの「共同作業」に付く緑の点は、共同作業中であることを示します。
- **進捗と作業量**：今日 / 直近 7 日 / 直近 30 日 / すべての期間で、メンバーごとの提出枚数、アノテーションのオブジェクト数、承認と差し戻しの回数、承認率、レビュー回数、作業時間（操作の間隔が 5 分以内のものを合計）を集計します。**CSV をエクスポート**をクリックして Excel で開けば、外注の出来高精算に使えます。
- **操作履歴**：誰がいつログイン、提出、レビュー、差し戻し、クラスの変更、タスクの割り当てをしたかを記録します。画像番号をクリックするとその画像に移動します。**自動保存もすべて含める**にチェックを入れると、より細かく確認できます。

### 9.6 3 つの共有方法の選び方

| | LAN | オンライン · 自前の中継 | オンライン · Xuntong 公式中継 |
|---|---|---|---|
| 向いている場面 | 同じ社内ネットワーク、同じ Wi-Fi | 外注、在宅勤務で、自前のクラウドサーバーがある | 外注、在宅勤務で、サーバーがない |
| メンバーがアクセスするアドレス | `http://あなたのパソコンのIP:8765/` | `https://あなたの中継/s/ID/` | `https://xuntongai.com/wulabel-relay/s/ID/` |
| 速度 | 最速 | サーバーの帯域幅しだい | Xuntong のサーバーの帯域幅しだい |
| データの経路 | 社内ネットワーク内のみ | 自前のサーバー（転送のみで保存しない） | Xuntong のサーバー（転送のみで保存しない） |
| 必要な準備 | 不要 | クラウドサーバー 1 台に `relay/README.md` に従って中継サービスをインストール | Xuntong AI アカウント（設定でログイン） |

- どの方法でも、画像とアノテーションはあなたのパソコンにだけ保存され、中継サーバーは転送だけを担当します。
- オンライン方式の共有 ID は固定です。次に開始しても同じアドレスなので、メンバーは一度ブックマークすれば済みます。
- メンバーが接続できるのは、あなたのパソコンが起動していて、Wulabel が共同作業を続けている間だけです。パソコンがスリープすると、メンバーには「ホストの Wulabel は現在オフラインです」と表示されます。電源設定で自動スリープをオフにしておくことをおすすめします。

1 枚の画像を同時に編集できるのは 1 人だけです。先に開いた人が「ロック」を取り、ほかの人が開くと閲覧のみになり、相手の変更をリアルタイムに見られます。ロックを持つ人が次の画像に移るか、ページを閉じるか、ネットワークが 90 秒切れると、ロックは自動で解除されます。

### 9.8 一通りの例

「外注チームがごみ分別の画像 2000 枚をアノテーションし、自社チームがレビューする」場合を例にします。

1. **準備**：Wulabel で検出プロジェクトを新規作成し、画像 2000 枚をインポートして、右側でクラス（資源ごみ、生ごみ、有害ごみ、その他のごみ）を追加します。先に Xuntong AI の専用モデルで一括事前アノテーションしておけば（16.4 を参照）、アノテーターは間違いを直すだけなので、ずっと速くなります。
2. **メンバーの追加**：「共同作業」画面でアノテーター 3 人（外注の山田さん、佐藤さん、鈴木さん）とレビュアー 1 人（自社チームの田中さん）を追加し、それぞれにアカウントとパスワードを送ります。
3. **共同作業の開始**：「オンライン · Xuntong 公式中継」（または自前の中継）を選び、「透かし」にチェックを入れて開始し、外部アドレスを 4 人に送ります。
4. **割り当て**：すべてのアノテーターを選び、範囲は「まだ誰にも割り当てていない未アノテーションの画像」、1 人あたりの枚数は空欄のまま割り当てをクリックします。1 人約 666 枚になります。
5. **アノテーション**：アノテーターはブラウザーでアドレスを開いてログインします。自分の画像だけが表示され、1 枚終えるごとに `Enter` で提出します。
6. **レビュー**：田中さんはレビュー画面を開き、メンバーの「山田さん」をクリックして、山田さんのレビュー待ちの画像をグリッドでざっと確認します。問題のないものはまとめて選んで「承認」をクリックし、問題のあるものはチェックを入れて「差し戻し」をクリックし、「アノテーション漏れ」にチェックを入れて「右下にもう 1 本ボトルがある」と書きます。差し戻された画像は元のアノテーターの「差し戻し」に戻り、修正後に再提出されます。画像が多すぎるときは「抜き取り検査」で 20% を抜き出し、合格率が高ければ残りもまとめて承認します。
7. **進捗の確認**：「共同作業」画面で、誰がオンラインか、誰が速いか、誰の差し戻しが多いかを確認します。遅れている人がいたら、「タスクを回収」でその人の未着手の画像を回収し、ほかの人に割り当てます。
8. **精算**：「進捗と作業量」で期間を選び、「CSV をエクスポート」をクリックして、提出枚数と承認率に応じて外注費用を精算します。
9. **仕上げ**：すべてのレビューが承認されたら共同作業を停止し、Wulabel に戻っていつもどおり学習、評価、デプロイを行います。

### 9.9 よくある質問

- **メンバーが LAN アドレスを開けない**：
  - 相手があなたと同じネットワークにいるか確認します（同じ社内ネットワークや Wi-Fi に接続しているか。ゲストネットワークは通常つながりません）。
  - 初めて開始したときの Windows ファイアウォールの確認では「アクセスを許可する」をクリックする必要があります。「キャンセル」をクリックした場合は、「Windows セキュリティ → ファイアウォールとネットワーク保護 → ファイアウォールによるアプリケーションの許可」で Wulabel にチェックを入れます。
  - ポートが使用中なら、8766 などに変更します。
- **メンバーに「ホストの Wulabel は現在オフラインです」と表示される**：あなたの Wulabel で共同作業が開始されていないか、パソコンがスリープしたか、ネットワークが切れています。開始し直してから、相手にページを再読み込みしてもらいます。
- **外部アドレスがずっと「中継サーバーに接続中…」のまま**：
  - 自前の中継：アドレスとシークレットがデプロイ時と同じか確認します。
  - 公式中継：Xuntong AI アカウントにログインしているか確認します。
- **メンバーに「この画像はあなたに割り当てられていません」と表示される**：アノテーターは自分に割り当てられた画像しか開けません。管理者からその画像を割り当ててもらうか、別の人がアノテーションします。
- **2 人が同時に同じ画像を編集したい**：できません。後から開いた人は閲覧のみになります。先の人が次の画像に移れば編集できます。
- **まとめて承認したら、何枚かスキップしたと表示された**：ほかの人が編集中の画像や、すでにレビュー待ちでない画像は、まとめて処理されません。その人が修正して提出してからレビューしてください。
- **メンバーのネットワークが切れたら、アノテーションは消える？**：保存済みのものは消えません（変更のたびにあなたのパソコンへ自動保存されます）。ネットワークが復旧すると、ページは自動で再接続します。
- **スマートフォンでアノテーションできる？**：開いて閲覧はできますが、ボックスの描画はパソコンをおすすめします。
- **最大何人まで？**：厳密な上限はありません。十数人が同時にアノテーションしても問題ありません。人数が多いときは、あなたのパソコンを起動したままにし、ネットワークを安定させてください。
- **共同作業を停止したり Wulabel を閉じたりするとどうなる？**：メンバーはすぐに切断され、「ホストが共同作業を停止しました」と表示されます。保存済みのアノテーションはすべて残ります。次に開始したら、メンバーはページを再読み込みすれば続けられます。
- **プロジェクトを切り替えた**：共同作業は自動で停止します。共同作業は現在開いているプロジェクトが対象です。

### 9.10 オフラインのパッケージ分割

ネットワークがない場合や、データを社外に出せない場合に使います。各パッケージは独立した Wulabel プロジェクトで、ほかの人にコピーで渡してアノテーションしてもらい、終わったらマージして戻します。

**パッケージに分割：**

1. **データ**画面で **管理 → 複数人での共同作業（パッケージ分割、マージして戻す）** をクリックし、**パッケージに分割**に切り替えます。
2. **保存先**：フォルダーを選びます。アノテーションパッケージはここに作られます。
3. **アノテーター**を 1 行に 1 人（またはカンマ区切り）で入力します。例：「山田」「佐藤」。人数分のパッケージに分けられます。
4. 範囲を選びます：**未アノテーションの画像のみ割り当て** / **未レビューのもの**（未アノテーション + レビュー待ち）/ **すべて**（スキップを除く）。
5. **既存のアノテーションも含める**にチェックを入れます：モデルで事前アノテーションした画像なら、アノテーターはそれを修正するだけなので速くなります。
6. （任意）**画像にモザイクをかける**にチェックを入れると、顔やナンバープレートなどのプライバシー領域にモザイクをかけてから渡せます（13.2 を参照）。
7. **N 個のパッケージに分割**をクリックします。完了すると保存先のフォルダーが自動で開きます。パッケージのフォルダーをそれぞれの担当者にコピーで渡せば、相手は Wulabel の**プロジェクトを開く**でアノテーションできます。

**マージして戻す：**

1. アノテーションが終わったパッケージのフォルダーをコピーして戻します。
2. **複数人での共同作業**を開き、**マージして戻す**に切り替えます（または「配布したパッケージ」の一覧で、そのパッケージの**マージ**を直接クリックします）。
3. パッケージのフォルダーを選びます。オプション：**競合時はパッケージ側で上書き**（パッケージ分割後に元のプロジェクトでも変更した画像は、既定では上書きしません）、**アノテーターがパッケージに追加した画像もインポート**。
4. **マージ**をクリックすると、下にマージの進捗が表示されます。マージした枚数、変化のなかった枚数、新しく追加された枚数、競合した枚数が表示されます。競合がある場合は**1 枚ずつ確認**をクリックします。

## 10. 学習

左側の**学習**をクリックします。初めて学習する前に学習環境をインストールしておく必要があります（第 2 章を参照）。未インストールの場合は画面に**インストール**が表示されます。

### 10.1 学習パラメーターの設定

画面の上部に「学習に使える画像」の枚数が表示されます（アノテーション済みの画像。チームで共同作業しているときはレビュー待ち + 承認済み）。まだ分割していない画像は、学習の開始時に 8:2 で学習セットと検証セットに自動で分けられます。一度分けた画像は勝手に変わらないので、複数回の学習結果をそのまま比較できます。

「学習に使える画像」の横の**表示・調整**をクリックすると、各画像がどこに分けられているかを確認できます。

- **学習セット**：モデルはこれらの画像から学習します。
- **検証セット**：学習には使わず、1 エポックごとにこれで評価して、最も結果のよかったエポックを保存します。
- **テストセット**：学習中はまったく使わず、学習後に「評価」画面で別に採点します。モデルを運用したときの実際の効果に最も近い結果になります。

ダイアログでは画像をクリックして選択し（ダブルクリックでアノテーションを開く）、**学習セットへ移動 / 検証セットへ移動 / テストセットへ移動**で手動で調整します。下では学習 / 検証 / テストの比率を変更でき、**未割り当ての N 枚を今すぐ割り当て**か**すべて再分割**をクリックします（すべて再分割するとそれまでの分割が崩れ、前後の学習を直接比較できなくなります）。学習セットが空になると警告が表示され、学習を開始できません。

| 項目 | 説明 |
|---|---|
| 開始点 | 既定は「事前学習済み重みから開始（ゼロから学習）」です。新しいデータを追加したあとは「「ある回の学習」の続きから学習」を選べます。ゼロから学習するより速く、安定します。クラスが変わった場合、分類の部分は学習し直されます。 |
| モデル | プロジェクトのタスクに応じて一覧表示されます。「推奨」と付いたものは、このパソコンに合わせた推奨です。検出プロジェクトでは、専用 GPU がなければ YOLOX-Tiny、GPU メモリ 4 GB 以上なら YOLOX-S、8 GB 以上なら YOLOX-M、Mac では YOLOX-S を推奨します。新規作成した検出プロジェクトの既定は YOLOX-S です。続きから学習する場合は、その回のモデルを引き継ぎます。 |
| 学習エポック数 | データが少ないほど多くのエポックが必要です。通常は 20～50 です。 |
| 入力サイズ | 対象が小さい（遠くの人、ヘルメット）場合は大きいサイズを使います。速度は遅くなります。分類では通常 224 です。 |
| バッチサイズ | GPU メモリ不足でエラーになったら小さくします。 |
| 学習データ | 「現在のデータ」またはデータセットのバージョン。 |
| デバイス | 「自動（GPU があれば GPU を使用）」または「CPU のみ使用」。 |
| 承認済みの画像のみ使用 | チームで共同作業しているときだけ表示：チェックを入れると、「承認済み」の画像だけで学習します。レビュー待ちの画像は今回は使われません。 |

入力サイズ、バッチサイズ、データ拡張、デバイス、承認済みの画像のみ使用（チームで共同作業しているときだけ）は「詳細設定」にまとめてあり、既定では閉じています。「詳細設定」をクリックすると展開します。前回展開したか閉じたかはソフトが覚えています。

学習中に GPU メモリが足りなくなったとき（v0.4.2 から）：ソフトがバッチサイズを自動で半分にしてゼロから学習し直し、1 になるまで繰り返します。画面に一度通知が表示され、学習記録にも「バッチサイズ 2（GPU メモリ不足のため 8 から自動で縮小）」と記録されます。バッチサイズが小さいほど学習は遅くなります。GPU メモリがどうしても足りない場合は、1 段階小さいモデルに変えるか、入力サイズを小さくすることもできます。

選べるモデル：

| タスク | モデル | 特徴 |
|---|---|---|
| 検出 | YOLOX-Nano | YOLO 系列で最も軽いサイズ。CPU、スマートフォン、非力なエッジデバイス向け。既定の入力は 416 |
| 検出 | YOLOX-Tiny | とても軽量。CPU や NPU エッジボックスでのリアルタイム推論向け。既定の入力は 416 |
| 検出 | YOLOX-S | 速度と精度のバランスが最も良い。ほとんどのプロジェクトはまずこれで |
| 検出 | YOLOX-M | 精度がより高い。GPU メモリ 6 GB 以上を推奨 |
| 検出 | YOLOX-L | 精度が最も高く、最も遅い。GPU メモリ 8 GB 以上を推奨 |
| 検出 | Faster R-CNN MobileNetV3 | 高速で GPU メモリの使用量が少ない。入門や専用 GPU のないパソコン向け |
| 検出 | Faster R-CNN ResNet50 | 精度がより高いが遅い。GPU メモリ 6 GB 以上を推奨 |
| 検出 | RetinaNet | 1 段階型。精度は Faster R-CNN に近く、TensorRT への変換がスムーズ |
| 検出 | FCOS | 1 段階型、アンカーフリー。構造がシンプルでデプロイ向き |
| 検出 | SSDLite | 1 段階型でとても軽量。CPU や NPU エッジデバイス向け。入力は 320 固定で、小さな対象は苦手 |
| セグメンテーション | Mask R-CNN | インスタンスセグメンテーション。GPU メモリ 6 GB 以上を推奨 |
| キーポイント | Keypoint R-CNN | 人体 17 点なら COCO の事前学習を活用できる |
| 分類 | MobileNetV3 / EfficientNet-B0 / ResNet50 | 軽くて速いものから、より高精度なものまで |

### 10.2 YOLOX モデル

YOLOX は Megvii がオープンソースで公開している YOLO 系列の検出モデルで（Apache-2.0。安心して商用利用できます）、Xuntong AI プラットフォームの専用モデルと同じ系列です。

- **事前学習済み重み**：初回の学習時に公式の COCO 事前学習済み重み（Nano 約 8 MB、S 約 70 MB、L 約 430 MB）を自動でダウンロードします。まず公式サイトから取得し、失敗したら GitHub から取得します。一度ダウンロードすれば、次回からは不要です。
- **データ拡張**：YOLOX 公式の方法を使い、Mosaic、MixUp、ランダムな拡大縮小と回転、色の揺らぎ、水平反転、マルチスケール学習をすべて自動で有効にします。最後の約 10% のエポックでは強い拡張をオフにして仕上げます。そのため、YOLOX を選んだときは下の「データ拡張」の設定は表示されません。
- **学習エポック数**：YOLOX は Faster R-CNN より多くのエポックが必要です。50 エポック以上を推奨します。データが少ない（数百枚）場合は 100 エポック程度です。
- **学習率**：バッチサイズに応じて自動で換算されるので、設定は不要です。
- **入力サイズ**：Nano と Tiny は既定 416、S、M、L は既定 640 です。変更でき、32 の倍数に丸められます。
- **なぜ YOLOv5 / v8 / v11 ではないのか**：これらは AGPL-3.0 ライセンスで、商用製品での利用に制限があります。YOLOX は Apache-2.0 で、Wulabel と同じです。ほかで学習した YOLOv5 / v8 / v11 のモデルは、「外部モデルをインポート」で取り込んで事前アノテーションや評価に使えます。

学習した YOLOX モデルは、ほかのモデルと同じように使えます。評価、モデルによる事前アノテーション、誤検出テスト、リアルタイム検証、エクスポートとデプロイ、Xuntong へのアップロードのすべてに対応しています。

### 10.3 データ拡張

学習時に画像をランダムに変化させ、モデルにより多様な見え方を経験させます。データが少ないときに特に効果があります。

1. 「データ拡張」でプリセットを選びます：**オフ**、**既定**、**弱**、**標準**、**強（データが少ないとき）**。
2. 細かく調整したい場合は展開して、**左右反転**、**上下反転**、**明るさ**、**コントラスト**、**彩度**、**色相**、**ぼかし**（ピンぼけや動きによるぶれを再現）、**ノイズ**（夜間の低照度を再現）、**マルチスケール**（遠近で大きさが大きく変わる対象に有効）、**回転**、**ランダムな切り抜き**を変更します。変更するとプリセットは「カスタム」と表示されます。
3. **効果をプレビュー**をクリックすると、何枚かの画像にランダムな拡張をかけた結果が表示されます（各画像を 2 回ランダムに変化させ、赤いボックスは変換に合わせて動いたアノテーションの位置です）。やりすぎになっていないか確認します。

### 10.4 学習の開始と経過の確認

1. 開始する前に、ボタンの上の「1 エポック約 N ステップ · 合計約 M ステップ」を確認します。画像が少なすぎる（学習セットが 20 枚未満）か、総ステップ数が少なすぎる（約 300 ステップ未満）場合は、**学習を開始**をクリックすると先に注意が表示されます。このまま学習してもほとんど何も学べず、指標がずっと 0 のままになるおそれがあります。画像をもっとアノテーションするか、案内に従って学習エポック数を増やすことをおすすめします。データがとても少ないときは、まず Faster R-CNN MobileNetV3 を使う手もあります。どうしても試してみたいだけなら**このまま開始**をクリックします。検証セットが 1～2 枚しかないときも、指標のばらつきが大きく信頼できないという注意が表示されます。
2. **学習を開始**をクリックします。まず学習データを準備します（画像が多いときはボタンの下に「学習データを準備中 N/M」と表示されます）。あるモデルを初めて使うときは事前学習済み重みをダウンロードし、学習画面に「事前学習済み重み ファイル名 をダウンロード中：ダウンロード済み / 合計 MB · 速度」と表示され、右下にもプログレスバーが出ます。ネットワークが切れても続きからダウンロードし、一度ダウンロードすれば次からは不要です。
3. 学習中は「エポック N / M · イテレーション · loss · 残り約」が表示され、その下に**損失 loss** の曲線、**検証セット**の指標の曲線、**ログ**があります。
   - ログの上の「重要な情報」には、ログの最初の数行が常に表示されます。使っているデバイス、学習セットと検証セットの枚数、事前学習済み重みを読み込めたかどうかです。エラーや警告の行は黄色で表示されます。
   - ログを上にスクロールしているときは、一番下に引き戻されません。一番下にいるときは自動でスクロールします。
   - 事前学習済み重みをダウンロードできなかった場合（たいていはネットワークの問題）や、指標が 10 エポック連続で 0 の場合は、画面上部に黄色の通知バーが表示され、考えられる原因と対処法が示されます。
4. 途中で終えたいときは**停止**をクリックし、確認すると現在のバッチの計算が終わったところで止まります。学習し終えたエポックと、その時点で最も良いモデルは残ります。
   - 学習中にソフトを閉じようとすると、「学習がまだ終わっていません。ソフトを閉じると学習が中断されます」という確認が先に表示されるので、誤って閉じることを防げます。
5. **中断した所から再開**：学習を停止した、ソフトを閉じた、エラーで中断した、といった場合は、その記録に**学習を再開**ボタンが表示されます。クリックすると同じ記録のまま、最後に終わったエポックの続きから残りのエポックを実行し、グラフとログも後ろに続きます。最初からやり直す必要はありません。学習が正常に最後まで終わると、再開用のチェックポイントは自動で削除されます（大きなモデルでは数百 MB になります）。
   - 開始点の「「ある回の学習」の続きから学習」とは別物です。あちらはある回で学習したモデルを開始点にして新しい学習を始めるもので、新しいデータを追加したあとに学習し直すのに向いています。
6. 学習が終わると、システム通知が表示され、タスクバーのアイコンが一度点滅します（ソフトがバックグラウンドにあってもわかります）。ソフトの右下に「学習が完了しました」と表示され、最も良い指標と評価（不十分 / まずまず / 実用レベル）が添えられます。
   - 結果が良ければ、そのまま**評価する**や**事前アノテーション**をクリックできます。
   - 結果がとても悪いときは、まず**原因を見る**をクリックして学習画面で確認するよう案内されます。
   - 学習に失敗したときは、学習画面を開いていなくても通知が表示されます。**エラーを見る**をクリックして確認します。
7. 学習でエラーが起きたときは、よくあるエラーがわかりやすい言葉に置き換えられ、修正用のボタンが表示されます。GPU ドライバーと PyTorch が合っていない（**設定で PyTorch のバージョンを変更**）、GPU メモリやメモリが足りない（**CPU に切り替え**）、ディスクがいっぱい、ネットワークからのダウンロードに失敗、画像ファイルが見つからない（**データ画面へ**）などです。エラーの全文は**詳細**をクリックすると展開されます。

### 10.5 学習記録と学習の比較

学習のたびに自動で**学習記録**が 1 件保存され、日時、モデル、データ、エポック数、指標、状態（学習中 / 完了 / 停止しました / 失敗）が一覧表示されます。各記録では次の操作ができます。

- **評価を見る**（開くのはその回の学習の評価です）、**ONNX をエクスポート**（エクスポート中は進捗を表示）、**学習フォルダーを開く**、削除。学習中の記録は、学習が終わるまで評価やデプロイができません。
- 停止・中断・失敗した記録には**学習を再開**があります（10.4 を参照）。

**一括削除**：学習記録でいくつかにチェックを入れて**選択を削除（N）** をクリックし、確認するとまとめて削除されます（モデルファイル、ログ、その回の学習に使ったデータセットの複製もすべて削除され、元に戻せません）。学習中の記録は選択できません。

**学習の比較**：

1. 学習記録で**2 つ以上の学習にチェック**を入れます（同時に比較できるのは最大 8 回です）。
2. **選択したものを比較（N）** をクリックします。
3. 比較ウィンドウでは、パラメーターとデータが並べて表示され（違うところは太字）、各指標、重ねた損失曲線、クラスごとの結果で最も良かった回が示されます。

### 10.6 外部モデルをインポート

ほかで（たとえば Ultralytics YOLO で）学習した検出モデルは、ONNX にエクスポートすれば取り込めます。事前アノテーション、ヘルスチェック、評価、誤検出テストに使えます（続きからの学習やデプロイはできません）。現在は検出プロジェクトのみ対応しています。

1. 学習記録の上にある**外部モデルをインポート**をクリックします。
2. **.onnx ファイルを選択**をクリックします。
3. ソフトが自動で判別します。
   - **形式**：YOLOv8 / v11（Ultralytics）、YOLOv5 / v7、YOLOv10 などのエンドツーエンド型、YOLOX、RT-DETR、DETR / RF-DETR、Wulabel でエクスポートしたモデル。判別が違っていたら手動で変更できます。
   - **入力サイズ**
   - **クラス名**（1 行に 1 つ。順番はモデルと同じにします）。英語のクラス名をプロジェクトのクラス名に書き換えれば対応付けられます。たとえば person を「人」に変えます。
4. **使用するクラス**：チェックのないクラスは事前アノテーション時に追加されません。プロジェクトと同じ名前のクラスには既定でチェックが入ります。
5. **インポート**をクリックします。学習記録に「…（外部）」が 1 件追加されます。

## 11. 評価

左側の**評価**をクリックし、学習記録を 1 つ選びます（学習画面の「評価を見る」から来た場合は、その回がすでに選ばれています）。学習中の記録は「学習中」と表示され、学習が終わるまで選べません。

### 11.1 指標を見る

- 上部に、今回の評価がどのエポックの最良モデルを使っているかが表示されます。**検証セット**と**テストセット**を切り替えられます。
- 一番上の行は**結論**です。主な指標から「不十分 / まずまず / 実用レベル」を判定し（検出系は mAP50 で、0.3 未満が不十分、0.3～0.6 がまずまず、0.6 超が実用レベル。分類は正解率で、0.6 未満が不十分、0.6～0.85 がまずまず、0.85 超が実用レベル）、**最も低いクラス**を示します。横には次にすることのボタンがあります。検出漏れの誤りの例を見る、誤りの例をアノテーションに回す、データを補充して再学習する / 大きいモデルに替える、などです。結果が実用レベルなら**デプロイへ**が表示されます。評価に使った画像が 10 枚未満のときは「指標のばらつきが大きい」と注意が表示されます。
- 検出、セグメンテーション、キーポイントのプロジェクト：**mAP50**（最もよく使われる検出の指標）、**mAP50-95**（ボックスの正確さにより厳しい指標）、**適合率**（出力したボックスのうち正しいものの割合。低いと誤検出が多い）、**再現率**（実際の対象のうち見つけられたものの割合。低いと検出漏れが多い）。セグメンテーションとキーポイントは対象のボックスで計算します。
- 分類のプロジェクト：**正解率**、**マクロ平均 F1**、平均適合率、平均再現率。
- 指標にマウスを重ねると説明が表示されます。
- **クラス別**の表：クラスごとの画像数、正解ボックス数、各指標。

### 11.2 混同行列

行が実際のクラス、列がモデルの予測です。対角線は正しく分類されたもので、それ以外のマスはあるクラスを別のクラスと誤判定したものです。最後の列の「背景」は検出漏れ、最後の行の「背景」は誤検出です。マウスを重ねると具体的な数値が表示されます。

### 11.3 誤りの例

- 問題のある画像が一覧表示され、**検出漏れあり**、**誤検出あり**、**クラス誤り**で絞り込めます。
- **誤りの例をクリック**すると、アノテーション画面に移動して確認・修正できます。修正してから再学習すれば、改善のサイクルが回ります。

### 11.4 信頼度のしきい値

デプロイ時にアラートに使うしきい値は、ここで決めます。

1. ソフトは F1 が最も高くなるしきい値を推奨し、そのしきい値での適合率と再現率を表示します。
2. 曲線は、しきい値に応じた適合率、再現率、F1 の変化を示します。**スライダーをドラッグ**すると、しきい値ごとの結果（正解、誤検出、検出漏れの数）を確認できます。
3. 選び方：誤検出が多ければしきい値を上げ、見逃しが多ければ下げます。
4. 下の表は**クラスごとの推奨しきい値**です。
5. 推奨しきい値は「デプロイ」画面のリアルタイム検証と推論サービスパッケージに自動で引き継がれ、既定の信頼度のしきい値になります。

### 11.5 現在のデータで評価

データを追加したりアノテーションを修正したりしたあと、再学習しなくても**現在のデータで評価**をクリックすれば、今のアノテーション済みデータ（検証セット / テストセット）で指標を計算し直せます。画面には「検証セットを評価中 N/M 枚」と表示されます。インポートした外部モデルもこれで評価します。

### 11.6 誤検出テスト

**アラートが出てはいけない**動画（対象がない、または誤認しやすいものだけが映っている動画。たとえば誰もいない通路や夜の工場敷地）を使って、モデルが何回誤検出するかをテストします。

1. 「誤検出テスト」で**動画ファイルを選択**をクリックするか、`rtsp://` / `http(s)://` のアドレスを入力します。
2. 設定します：**1 秒あたり N フレーム検出**、**N 回連続検出で 1 回のアラート**、**テスト時間 N 分**（動画ストリーム用）。
3. **テストを開始**をクリックします。いつでも**早期終了**をクリックできます。
4. 結果：テストした時間、アラート回数、**1 時間あたり**の回数がクラス別に集計されます。その下に**誤検出の画面**が表示されます（赤いボックスはモデルが検出したもの。最新の 60 枚だけを残します）。
5. **これらのフレームをネガティブサンプルとしてデータセットに追加**をクリックすると、「対象なし」の画像として追加され、次の学習でモデルはこうした画面でアラートを出さないように学びます。中に本物の対象が含まれていた場合は、追加後にアノテーション画面でアノテーションを付けてください。

### 11.7 納品レポートのエクスポート

1. **レポートをエクスポート**をクリックし、保存場所を選びます（既定のファイル名は「プロジェクト名_学習名_モデルレポート.html」）。
2. レポートは 1 つの HTML ファイルで、データの状況、学習パラメーター、指標、曲線、混同行列、誤りの例、推奨しきい値、誤検出テストの結果を含みます。ブラウザーでそのまま開けるので、顧客の検収用に送れます。

## 12. モデルによる事前アノテーションと画像の選別

### 12.1 自分のモデルで事前アノテーション

1. **アノテーション**画面に移動し、右側の「AI アシスト」で**マイモデル**を選び、ドロップダウンで学習済みのモデルを選びます（名前と mAP50 / 正解率が表示されます）。
2. **信頼度**を調整します。
3. 1 枚ずつ：**P** を押すか、**この画像を予測 (P)** をクリックします。
4. 一括：**一括事前アノテーション**をクリックすると、未アノテーションの画像をまとめてアノテーションします。ダイアログはすぐに閉じ、進捗バーは右側に表示されるので、処理を進めながらアノテーションを続けられます。途中で止めたいときは進捗バーの横の**停止**をクリックします。それまでにアノテーションした分は残ります。
5. 事前アノテーションのボックスは破線です。確認して修正したら **Enter**（完了して次へ）を押すと、その画像はアノテーション済みになります。分類プロジェクトでは「モデルの候補」が表示され、上位 3 クラスはクリックするだけで採用できます。

アノテーションするほど → モデルが正確になり → 事前アノテーションが楽になります。

### 12.2 アノテーションする価値が最も高い画像を選ぶ

初版のモデルができたら、適当にアノテーションするより、モデルが最も判断に迷う画像を先にアノテーションしましょう。

1. **データ**画面で **管理 → アノテーションする価値が最も高い画像を選ぶ（モデルを使用）** をクリックします。
2. モデルを選び、**選ぶ** N 枚を入力して、**選別を開始**をクリックします。
3. 結果は「判断が難しい」順に並びます。
4. **この順番でアノテーション**をクリックすると、アノテーション画面にはこの画像群だけが表示されます（上部の絞り込みに「モデルによる選別」が追加されます）。終わったら、その横の × をクリックするとすべての画像の表示に戻ります。

## 13. データセットのエクスポート（モザイク処理を含む）

### 13.1 エクスポート

1. **データ**画面で**データセットをエクスポート**をクリックします。
2. **形式**（プロジェクトのタスクによる）：
   - 検出：YOLO、COCO、VOC
   - セグメンテーション：YOLO-seg、COCO、VOC（外接ボックスのみ）
   - キーポイント：YOLO-pose、COCO キーポイント、VOC（対象のボックスのみ）
   - 分類：クラス別フォルダー（train/クラス/画像.jpg）
3. **範囲**：未アノテーションとスキップ済みの画像はエクスポートされません。「対象なし」にした画像は、ネガティブサンプルとしてエクスポートされます。チームで共同作業しているときは、**承認済みの画像のみエクスポート**にチェックを入れることもできます。
4. **学習 / 検証 / テストの比率（%）**：まだ分割していない画像は、この比率で割り振られます。すべてを分割し直したい場合は**すべて再分割**をクリックします（それまでの学習結果は、新しい分割とは直接比較できなくなります）。
5. **エクスポート先**：**参照**をクリックして場所を選びます。**フォルダー名**は自動で作られ、変更もできます（変更したあとは形式を切り替えても上書きされません）。
6. **エクスポート**をクリックします。完了すると、エクスポートした画像の数、アノテーションの数、分割ごとの枚数が表示されます。**フォルダーを開く**をクリックするとすぐに確認できます。

データセットのバージョンをエクスポートする場合：データセットのバージョン一覧で**このバージョンをエクスポート**をクリックします。分割はバージョン内の分割に固定されます。

### 13.2 モザイク処理

データセットのエクスポート、バージョンのエクスポート、パッケージ分割のときに、**画像にモザイクをかける**にチェックを入れられます。

1. **クラス別**：ドロップダウンでモザイクをかけるクラスを選びます。たとえば自分でアノテーションした「顔」「ナンバープレート」です。名前に「face」「plate」（または中国語の「脸」「车牌」「牌照」）を含むクラスは既定で選ばれます。
2. **自動検出**：**顔を自動検出**、**ナンバープレートを自動検出**にチェックを入れると、オープンボキャブラリー検出モデルで見つけます（初回はモデルのダウンロードが必要です。GPU があればずっと速くなります）。
3. **方法**：**モザイク**、**ぼかし**、**黒塗り**。
4. エクスポート時には「モザイク」段階の進捗が加わります。

モザイク処理で変更するのはエクスポートしたコピーだけで、プロジェクト内の元画像はそのままです。自動検出では、とても小さいもの、横顔、遠くの対象を見逃すことがあります。重要なデータは抜き取りで確認してください。

## 14. デプロイ

左側の**デプロイ**をクリックし、学習済みのモデルを 1 つ選びます。画面には 4 つのタブがあります：**リアルタイム検証**、**モデルをエクスポート**、**推論サービスパッケージ**、**現場データの還流**。

### 14.1 リアルタイム検証

カメラや動画につないで、モデルの効果をその場で確認します。

1. **動画ストリーム**か**ローカル動画**を選びます。
2. ストリームのアドレスを入力します：RTSP カメラ（例：`rtsp://admin:パスワード@192.168.1.64:554/Streaming/Channels/101`）、または HTTP-FLV、HLS（m3u8）、http 上の MP4 のアドレス。**動画ファイルを選択**をクリックしてもかまいません。
3. **開始**をクリックします。起動中は「実行環境を準備中…」「モデルを読み込み中…」「動画ソースに接続中…」と順に表示され、映像が出ると画面に結果がリアルタイムに描かれます。検出モデルはボックス、セグメンテーションモデルは輪郭、キーポイントモデルは点と骨格、分類モデルは左上に確率の高いクラスを表示します。上部には解像度と、GPU と CPU のどちらで推論しているかが表示されます。
4. **信頼度**スライダーをドラッグしてしきい値を調整します。既定では評価画面の推奨しきい値を使います。変更したあとは「推奨値 0.xx を使う」をクリックすると元に戻せます。
5. 検出漏れや誤検出の画面を見つけたら、**スクリーンショットをデータセットに追加**をクリックします。画像は「未アノテーション」として追加されるので、アノテーションしてから再学習します。
6. **停止**をクリックして終了します。

### 14.2 モデルをエクスポート

1. 形式を選びます。
   - **ONNX（動的サイズ）**：汎用形式。onnxruntime で Windows / Linux / ARM のどれでも動きます。
   - **ONNX（固定サイズ）**：入力を [1,3,N,N] に固定します。固定の形状が必要な推論フレームワーク向けです。
   - **OpenVINO**：Intel の CPU、内蔵 GPU、産業用 PC での高速化用。ソフト内で直接変換して検証します（初回は OpenVINO を自動でインストールします。インストールできないときはこの形式だけをスキップし、ほかの形式は通常どおりエクスポートします）。
   - **TensorRT 変換パッケージ**：NVIDIA GPU、Jetson 向け。対象デバイス上でスクリプトを実行してエンジンを生成する必要があります。
   - **RKNN 変換パッケージ**：Rockchip RK3588 / 3568 など向け。Ubuntu 上でスクリプトを実行して変換する必要があります。
2. 固定サイズが必要な場合は、サイズを設定します。
3. **エクスポート先**の場所と**フォルダー名**を選び、**エクスポート**をクリックします。既定では ONNX だけにチェックが入っています。エクスポート中は「ステップ N / 全 M」と現在の形式が表示され、終わると形式ごとに成功か失敗かが表示されます。**開く**をクリックすると確認できます。

内蔵の Faster R-CNN は 2 段階型のモデルで、NPU（RKNN）や古いバージョンの TensorRT ではサポートが限られ、変換に失敗したり速度が出なかったりすることがあります。こうしたデバイスで使うなら、YOLOX かほかの 1 段階型モデル（RetinaNet、FCOS、SSDLite）を学習することをおすすめします。ONNX と OpenVINO は安心して使えます。

YOLOX モデルをエクスポートする場合：ONNX（動的サイズ）と OpenVINO はほかのモデルと同じで、モデル内でリサイズ、デコード、重複ボックスの除去（NMS）まで済ませてあり、そのまま結果を出力します。ONNX（固定サイズ）、TensorRT、RKNN の変換パッケージは YOLOX 公式の形式を使います（入力は BGR 0～255、左上を基準に 114 でパディング、出力は NMS 未処理）。演算子はすべて普通の畳み込みなので、NPU でも TensorRT でも完全に動きます。後処理は変換パッケージ内の README を参照してください。

セグメンテーションとキーポイントのモデル（Mask R-CNN、Keypoint R-CNN）も ONNX や OpenVINO などの形式でエクスポートできます。セグメンテーションモデルには出力 `masks`（対象ごとのマスクの確率。0.5 より大きい部分が対象）が、キーポイントモデルには `keypoints`（各点の x、y、可視性）と `keypoints_scores` が追加されます。リアルタイム検証と推論サービスパッケージは、検出・セグメンテーション・キーポイント・分類のすべてのモデルに対応しています。

### 14.3 推論サービスパッケージ

現場のパソコンに持っていけばそのまま動く推論サービスを作成します。検出・セグメンテーション・キーポイント・分類のすべてのモデルに対応しています。

1. **動画ストリーム**：名前とアドレス（`rtsp://…`、`http(s)://…` の FLV / m3u8 / MP4、または動画ファイルのパス）を入力します。**映像を追加**をクリックすると複数の映像を追加できます。
2. **検出間隔（秒）**：映像ごとに何秒おきに 1 フレームを検出するか。
3. **アラートルール**：
   - **アラート対象のクラス**（何も選ばなければすべてのクラスでアラート）
   - **信頼度のしきい値**（既定では評価画面の推奨しきい値を使います）
   - **重複除外の間隔（秒）**：同じ映像の同じクラスについて、この時間内はアラートを 1 回だけ出します。
   - **有効時間帯**：終日、または `07:00-19:00` のように指定
   - **アラートのスクリーンショットを保存（ボックス付き）**
4. **アラート送信**：
   - Webhook：アラート時にこのアドレスへ JSON を POST します。任意で**スクリーンショットを添付（base64）** できます。
   - MQTT：サーバーアドレス、トピック、ユーザー名、パスワード（空欄なら送信しません）。
5. **サービス**：**HTTP API ポート**、**GPU で推論**（現場のパソコンに onnxruntime-gpu が必要。なければ自動で CPU を使います）。
6. **現場データの還流**：モデルが判断に迷った（信頼度が設定した範囲内の）画面を、サービスパッケージの `reflux/` フォルダーに保存します。
7. **出力先**の場所を選び、**推論サービスパッケージを作成**をクリックします。作成中は「ステップ N / 全 M」が表示されます。
8. フォルダーごと現場のパソコンにコピーします。Windows では `run.bat` をダブルクリック、Linux では `sh run.sh` を実行します。設定は `config.json`、説明は `README.md` にあります。現場のパソコンに PyTorch や GPU は不要で、必要なのは onnxruntime、OpenCV、numpy だけです。初回の実行時は Python 3.9 以上をインストールしておき、ネットワークにつないでこれらの依存パッケージをインストールする必要があります。インストールが途中で失敗した場合は、次回の実行時に自動でインストールし直します。

### 14.4 現場データの還流

1. サービスパッケージは現場で動いている間、モデルが判断に迷った画面を `reflux/` フォルダーに保存します。
2. 定期的に `reflux/` をコピーして持ち帰り、**現場データの還流**タブで**現場から戻った画像をインポート**をクリックして、このフォルダーを選びます。インポート中は進捗が表示され、停止もできます。
3. **このバッチをアノテーション**をクリックすると、今インポートしたこのバッチの画像だけがアノテーション画面に送られます。モデルで事前アノテーションしてから修正します。
4. 再学習して新しいサービスパッケージを作成し、現場の `model.onnx` を置き換えます。使うほどモデルが正確になります。

### 14.5 Xuntong AI プラットフォームにアップロード

自分でサービスをデプロイしたくない場合は、モデルを Xuntong AI プラットフォームにアップロードし、プラットフォーム上でカメラの接続やアラートの設定ができます（現在は物体検出モデルに対応）。

1. まず**設定**で Xuntong AI を設定します（2.3 を参照）。
2. **デプロイ → モデルをエクスポート**の一番下にある「Xuntong AI プラットフォームにアップロード」で**モデル名**を変更し、**アップロード**をクリックします。まだ ONNX をエクスポートしていない場合は、先に自動でエクスポートされます。
3. アップロード後、プラットフォームでの検証に数秒～1 分かかります。「プラットフォームで検証中です」と表示され、合格すると「検証に合格しました」に変わります（失敗した場合は理由が表示されます）。評価画面で計算した推奨しきい値も一緒にアップロードされ、プラットフォーム上の既定のしきい値になります。
4. **コンソールを開く**をクリックし、「カスタムモデル」で**有効にする**をクリックすれば、カメラの接続やアラートの設定ができるようになります。
5. その下の「プラットフォーム上のカスタムモデル」に、アップロード済みのモデル、検証状態、有効かどうかが一覧表示されます。ホスティングを契約していないアカウントではモデルを 1 つしか置けないので、新しいバージョンをアップロードする前に古いものを**削除**します。
6. プラットフォームで発生したアラート画像は、取り込んで再びアノテーションできます（4.7 を参照）。

## 16. Xuntong AI 利用ガイド

Xuntong AI（[xuntongai.com](https://xuntongai.com)）は AI 認識プラットフォームです。すぐに使える専用の認識モデル（ごみ分別、ヘルメット、煙や炎など）と大規模モデルによる認識があり、自分のモデルのホスティング、カメラの接続、アラートの送信もできます。Wulabel と連携すると、**アノテーション、学習、運用開始、現場データの還流**を 1 つのサイクルにつなげられます。これまでの章で個別に説明してきた使い方を、この章でまとめて説明します。

Wulabel で Xuntong AI を使う場所：

| 場所 | できること | 参照 |
|---|---|---|
| 設定 → Xuntong AI | アカウントへのログイン、利用枠の確認 | 16.1、16.2 |
| アノテーション画面 → AI アシスト → Xuntong AI | 専用モデル / 大規模モデル / プロジェクトのクラスで自動アノテーション | 16.3–16.5 |
| アノテーション画面 → AI アシスト → 認識ルール | 認識の説明を書く、認識方法を AI とチャット、プラットフォームに同期 | 16.5 |
| デプロイ → モデルをエクスポート → Xuntong AI プラットフォームにアップロード | 学習済みのモデルをプラットフォームで使う | 16.6 |
| データ → その他のインポート → Xuntong AI からアラート画像を取得 | 現場の誤検出や検出漏れを取り込んで再アノテーション | 16.7 |
| 共同作業 → オンライン · Xuntong 公式中継 | インターネット越しのメンバーと一緒にアノテーション | 16.8 |

### 16.1 アカウントにログイン

1. **設定**を開き、「Xuntong AI」の欄で **Xuntong AI アカウントにログイン**をクリックします。
2. ブラウザーで Xuntong AI のページが開きます。
   - 未ログインならまずログインします（普段 Xuntong にログインするときと同じで、認証コードや SMS も使えます）。
   - ページの確認コードが Wulabel のダイアログのものと同じかを確かめ、**許可**をクリックします。
3. Wulabel に戻ると、数秒後に**ログイン中**になり、アカウント名とプラン、残りの利用枠、使える認識方式が表示されます。

補足：

- コンソールで API Key を作成・コピーする必要はありません。ログイン時にプラットフォームがこのパソコン専用の Key を発行します。名前は「Wulabel · パソコン名」で、Xuntong コンソールの「API Key」ページで確認・無効化できます。
- 同じパソコンでログインし直すと、古い Key は自動で置き換えられます。個人アカウントの Key は最大 2 つで、上限に達するとページの「許可」をクリックできません。コンソールで使っていない Key を 1 つ無効にしてから再試行してください。
- ブラウザーが自動で開かない場合：ダイアログの**開き直す**をクリックするか、アドレスをコピーして自分で開きます。ログインコードの有効期限は 10 分です。
- **ログアウト**：このパソコンの Key は削除され、ログイン時に発行された Key もプラットフォーム上で無効になります。
- API Key をすでに持っている場合や、Xuntong をプライベート環境に構築している場合：**詳細：API Key の手動入力、プライベート環境のプラットフォームのアドレス**をクリックします。

### 16.2 利用枠と料金

- 設定画面に、種類ごとの利用枠の残りと有効期限が表示されます：大規模モデルによる認識、専用モデルによる認識、自前のモデルによる認識、追加パックなど。内容はプランによって異なります。
- カウント方法：画像 1 枚の認識を 1 枚と数えます。一括事前アノテーションの前に合計枚数が表示されます。AI との認識ルールのチャットは、1 往復ごとに大規模モデルの利用枠を 1 枚分消費します。
- 消費するのは自分のアカウントの利用枠だけです。共同作業のメンバーが AI とチャットするときは、ホストの利用枠を使います（ホストは共同作業画面で「メンバーは AI アシストを使えます」をオフにできます）。
- 利用枠を使い切ると「利用枠が不足しています」と表示され、一括事前アノテーションは止まります。アノテーション済みのものは残ります。

### 16.3 4 つの認識方式の選び方

アノテーション画面右側の「AI アシスト」で **Xuntong AI** を選ぶと、「認識モデルを選択」のドロップダウンに次のものがあります。

| 認識方式 | 向いている場面 | 速度 | 利用枠 |
|---|---|---|---|
| 専用モデル（ごみ分別、ヘルメットなど） | プロジェクトのクラスがプラットフォームの既存モデルと合っている | **最速**。一括時は 8 枚を 1 バッチとして 2 バッチを同時に送信 | 専用モデルによる認識 |
| 自分でアップロードして有効にした自前のモデル | 自分で学習してプラットフォームにアップロードしたモデル | 同上 | 自前のモデルによる認識 |
| プロジェクトのクラスで認識（推奨） | プラットフォームに合うモデルがない。プロジェクトのクラスだけを探したい | 1 枚ずつで少し遅い | 大規模モデルによる認識 |
| 大規模モデルによる汎用認識 | 安全上の危険要因の大分類（消防、電気、環境衛生など）で探す | 1 枚ずつ | 大規模モデルによる認識 |

選び方は簡単です。**合う専用モデルがあれば専用モデルを使います**（速くて正確です）。なければ**プロジェクトのクラスで認識**を使い、各クラスの認識の説明をはっきり書きます（16.5）。

### 16.4 専用モデルで一括自動アノテーション

ごみ分別を例にします。

1. 検出プロジェクトを新規作成し、画像をインポートします。クラスは先に作らなくてもかまいません。モデルが認識したクラス名（中国語の「可回收物」〈資源ごみ〉など）がプロジェクトになければ自動で作られます。
2. アノテーション画面を開き、右側の「AI アシスト」で **Xuntong AI** を選び、モデルで**ごみ分別**を選びます。
3. **信頼度**を調整します。まずは既定値で試し、ボックスが多すぎれば上げ、漏れが多ければ下げます。
4. まず `P` で現在の画像をアノテーションして結果を確かめ、よければ**一括事前アノテーション**をクリックします。「未アノテーション」でまだアノテーションのない画像すべてをバッチごとに認識し、プログレスバーに進捗が表示されます。
5. 認識したボックスは破線（ソースは「Xuntong」）です。1 枚ずつ確認し、間違いは削除し、ずれは直し、漏れは追加して、`Enter`（完了して次へ）を押します。
6. もっと速くするには：数百枚アノテーションしたら、そのデータで自分のモデルを学習し（第 10 章）、以降はパソコン上で事前アノテーションすれば利用枠を使いません。

一括処理中に「呼び出しが多すぎる」状態になると、自動で速度を落として再試行します。利用枠が二重に引かれることはありません。利用枠の不足やモデル未契約といったエラーの場合は停止し、何枚までアノテーションしたかを知らせます。

### 16.5 プロジェクトのクラスで認識と認識ルール

プラットフォームに合うモデルがないときは、「プロジェクトのクラスで認識」を使います。プラットフォームはプロジェクトにあるクラスだけを探し、クラス名はそのまま対応し、**リストにないものは一切報告しません**。うまくいくかどうかは、ルールをどれだけはっきり書いたかで決まります。

**認識の説明を書く：**

1. クラスの横の編集ボタンで**認識の説明**を入力します。このクラスが具体的に何を指すか、何が該当し何が該当しないかを書きます。例：
   - ヘルメット未着用：ヘルメットをかぶっていない人。かぶっていてもあご紐を締めていなければ該当。頭と上半身だけを囲む。
   - 電動バイク：二輪の電動バイク、電動自転車。自転車とオートバイは該当しない。
2. または「AI アシスト」の見出しの横で**認識ルール**をクリックし、**現在のルール**で**全体ルール**（すべてのクラスに適用。例：「画面の下半分の通路だけを見て、ポスターや画面の中の内容は無視する」）と各クラスの説明をまとめて編集し、**ルールを保存**をクリックします。

**AI とチャット：** ルールの書き方がわからなければ、**認識ルール → AI とチャット**で普段の言葉で伝えます。

- 「ヘルメットをかぶっていてもあご紐を締めていなければ未着用とみなす」
- 「反射ベストはヘルメットではない」
- 「この画像の左の人はなぜ認識されなかったの？」

既定で現在の画像が添付され、AI は回答後に新しいルールでこの画像を試し認識します。AI がルールの変更を提案すると具体的な内容が表示され、**このルールを適用**をクリックしたときだけ保存されます。試し認識の結果があれば、**試し認識のボックスをこの画像に追加**をクリックするとそのまま使えます。

**Xuntong プラットフォームに同期（任意）：**「現在のルール」の一番下で **Xuntong プラットフォームに同期**をクリックすると、ルールがプラットフォームに保存されます。既定では無効なので、プラットフォームの現在の認識には影響しません。

Xuntong プラットフォーム自体の認識（撮影、アラート送信）でもプロジェクトのクラスだけを報告させたい場合は、**プラットフォームの認識にもこのルールを使用**をオンにします。注意：オンにすると、Xuntong アカウント全体の認識がこのルールに従います。適用シーンは Xuntong コンソールの「認識ルール」ページで調整できます。

紐付けたあとは、ルールを保存または適用するたびに内容が自動で同期されますが、コンソールで設定した有効 / 無効やシーンは変更しません。同期をやめるには**紐付けを解除**をクリックします。プラットフォーム上のルールは削除されません。

**制限：** 最大 30 クラス、クラス名は 30 文字以内です。全体ルールは最大 1000 文字、クラスごとの認識の説明は最大 500 文字です。Xuntong アカウントごとにルールは最大 20 セットまでです。

### 16.6 学習済みのモデルを Xuntong にアップロード

1. Wulabel で**物体検出**モデルを学習します（Xuntong が現在受け付けるのは検出モデルだけです）。
2. **デプロイ → モデルをエクスポート**の一番下にある「Xuntong AI プラットフォームにアップロード」でモデル名を変更し、**アップロード**をクリックします。まだ ONNX をエクスポートしていない場合は先に自動でエクスポートされ、評価画面の推奨しきい値も一緒にアップロードされます。
3. プラットフォームでの検証に数秒～1 分かかります。「検証中」→「検証に合格しました」（または「検証に失敗しました」と理由）と表示されます。
4. **コンソールを開く**をクリックし、「カスタムモデル」で**有効にする**をクリックします。有効にすると、プラットフォーム上でカメラの接続やアラートの設定ができ、アノテーション画面のモデル一覧でも選べるようになります。
5. その下の「プラットフォーム上のカスタムモデル」に、アップロードしたモデル、検証状態、有効かどうかが一覧表示されます。ホスティングを契約していないアカウントではモデルを 1 つしか置けないので、新しいバージョンをアップロードする前に古いものを**削除**します。モデルファイルの上限は 200 MB です。

### 16.7 現場のアラート画像を取り込んで改善を続ける

モデルを運用し始めると、現場のアラートのスクリーンショットには誤検出や検出漏れが含まれます。これこそ最も補充する価値のあるデータです。

1. **データ → その他のインポート → Xuntong AI からアラート画像を取得**。
2. 期間（直近 1 / 3 / 7 日）、どのモデルのアラートか、最大何枚かを選びます。既定で**プラットフォームが認識したボックスを事前アノテーションとして使用**にチェックが入っています。
3. 取り込んだ画像はプロジェクトの `images/xuntong_日時/` フォルダーにあり、ボックスは破線（ソースは「Xuntong」）です。
4. 1 枚ずつ修正します。誤検出のボックスは削除し（もともと対象が映っていない画像はそのまま **Enter** で完了してネガティブサンプルにします）、漏れは追加します。
5. 再学習と評価をして新しいバージョンをアップロードし、プラットフォーム上の古いモデルを置き換えます。

注意：プラットフォームのアラート画像は 7 日間保存されるので、定期的に取得しましょう。アラート記録が作られるのは、通知チャネルを設定したアカウントだけです。

これで改善のサイクルが完成します：**アノテーション → 学習 → Xuntong にアップロード → 現場でアラート → 取り込んで修正 → 再学習**。使うほどモデルが正確になります。

### 16.8 共同作業での Xuntong AI

- **公式中継**：共同作業画面の共有方法で**オンライン · Xuntong 公式中継**を選ぶと、インターネット越しのメンバーが Xuntong のサーバー経由で接続でき、自前のサーバーは不要です。先に Xuntong アカウントにログインしておく必要があります。1 アカウントで同時に開ける共有は最大 3 つです。画像とアノテーションは Xuntong のサーバーを経由して転送され、保存はされません。データが機密性の高いプロジェクトでは、LAN か自前の中継を使ってください。
- **メンバーが使えるもの**：メンバーは Xuntong AI で直接事前アノテーションすることはできません（あなたの利用枠を使ってしまうため）。「メンバーは AI アシストを使えます」がオンなら、メンバーは認識ルールを開いて AI とチャットできます（あなたの利用枠を使います）。ルールを変更できるかどうかは、「メンバーはクラスと認識の説明を追加・変更できます」スイッチに従います。

### 16.9 よくある質問

- **ログインをクリックしてもブラウザーが反応しない**：ダイアログの**開き直す**をクリックするか、アドレスをコピーしてブラウザーで開きます。会社のパソコンでブラウザーの自動起動が禁止されている場合も同じです。
- **ページの「許可」をクリックできない**：アカウントの Key が上限に達しています。Xuntong コンソールの「API Key」ページで、使っていないものを 1 つ無効にします。
- **「接続に失敗しました」と表示される**：
  - 表示された理由を確認します。
  - 手動で入力した Key なら、完全にコピーできているか（`sk-live-` で始まる）、コンソールで有効になっているか、IP ホワイトリストを設定していないかを確認します（ログインで発行された Key にはホワイトリストはありません）。
  - ログアウトしてからログインし直すこともできます。
- **「利用枠が不足しているか、呼び出しが多すぎます」と表示される**：設定画面で残りの利用枠を確認します。使い切った場合は、Xuntong で更新するか追加パックを購入します。一括アノテーション自体はすでに速度を制御しています。
- **モデル一覧に特定の専用モデルがない**：アカウントで契約していないということです。Xuntong AI で対応するプランを契約してください。
- **認識されたクラス名がプロジェクトのものと違う**：専用モデルは独自のクラス名を使い、プロジェクトにないものは自動で作られます。名前をそろえたい場合は「プロジェクトのクラスで認識」を使うか、認識後にクラスの編集で名前を変更します。
- **Xuntong のプライベート環境**：設定の「詳細」で、自社のプラットフォームのアドレスと API Key を入力します。
