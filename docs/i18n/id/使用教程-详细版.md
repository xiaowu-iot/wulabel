## 1. Instalasi dan pembukaan pertama

### 1.1 Unduh dan instal

1. Buka situs resmi <https://wulabel.xiaowuiot.com>, klik **Unduh** di kanan atas, atau unduh dari halaman Release di GitHub.
2. Windows: unduh `Wulabel_<versi>_x64-setup.exe`, klik dua kali dan ikuti petunjuk instalasi. Setelah selesai, buka **Wulabel** dari menu Start atau desktop.
3. Mac: unduh `Wulabel_<versi>_universal.dmg`, klik dua kali untuk membukanya, lalu seret Wulabel ke folder "Applications".
4. Linux (mulai v0.4.0): unduh `Wulabel_<versi>_amd64.deb`, lalu jalankan `sudo apt install ./Wulabel_<versi>_amd64.deb` di terminal. Setelah terpasang, buka **Wulabel** dari menu aplikasi. Anda juga bisa mengunduh `.AppImage`, menjalankan `chmod +x Wulabel_<versi>_amd64.AppImage`, lalu klik dua kali untuk menjalankannya tanpa instalasi. Untuk komputer ARM (Phytium, Kunpeng), unduh `Wulabel_<versi>_arm64.deb` atau `Wulabel_<versi>_aarch64.AppImage` (mulai v0.4.2); cara pakainya sama.

- Persyaratan sistem: Windows 10 / 11 (64-bit); macOS 11 ke atas (Apple Silicon maupun Intel); Linux x86_64 (Ubuntu 22.04 ke atas, Debian 12, UOS, Kylin di komputer x86, dan lainnya); Linux ARM64 (mulai v0.4.2, misalnya Kylin dan UOS di komputer Phytium atau Kunpeng; unduh file yang namanya mengandung `arm64` atau `aarch64`).
- Belum didukung: Loongson, HarmonyOS. Perangkat HarmonyOS bisa ikut anotasi kolaborasi tim lewat browser.
- Jika saat pertama dibuka di Windows muncul pesan WebView2 tidak ada, instal saja sesuai petunjuk (sebagian besar Windows 10 / 11 sudah memilikinya).
- Saat pertama dibuka di Mac akan muncul pesan "pengembang tidak dapat diverifikasi" (aplikasi belum ditandatangani dengan sertifikat pengembang Apple): di "Applications", **klik kanan** Wulabel → Open → klik "Open" lagi. Di macOS 15 ke atas, klik dua kali sekali dulu, lalu buka "System Settings → Privacy & Security" dan klik "Open Anyway" di bagian paling bawah. Jika muncul pesan "rusak" (damaged), jalankan `xattr -cr /Applications/Wulabel.app` di terminal lalu buka lagi. Langkah ini hanya perlu sekali.

### 1.2 Mengenal tampilan utama

Setelah dibuka, Anda akan melihat halaman **Proyek**. Setelah membuka proyek, di kiri ada bilah navigasi, dari atas ke bawah:

| Halaman | Fungsinya |
|---|---|
| Proyek | Membuat, membuka, dan berganti proyek |
| Data | Mengimpor gambar / video / dataset, mengelola gambar, mengekspor dataset |
| Anotasi | Menggambar kotak dan kontur, memilih kelas, menandai keypoint, bantuan AI dan pra-anotasi |
| Cek data | Menemukan masalah seperti objek terlewat, label salah, gambar duplikat |
| Pelatihan | Memilih model, mengatur parameter, memulai pelatihan, melihat riwayat pelatihan |
| Evaluasi | Melihat metrik, matriks konfusi, contoh kesalahan, ambang yang disarankan, uji positif palsu, ekspor laporan |
| Deploy | Uji langsung, ekspor model, membuat paket layanan inferensi, mengimpor data balik dari lapangan |
| Tinjau | Hanya ada saat kolaborasi tim: filter per anggota dan status, setujui atau kembalikan secara massal, tinjauan sampel |
| Kolaborasi | Kolaborasi tim langsung: mulai berbagi (LAN / online), anggota, menugaskan pekerjaan, statistik progres |
| Pengaturan | Instal lingkungan pelatihan, sumber unduhan, Xuntong AI |

Di kanan atas ada tombol **Masukan** dan **Tutup proyek**.

## 2. Pengaturan: lingkungan pelatihan, sumber unduhan, Xuntong AI

Kalau Anda hanya menganotasi dan mengimpor/mengekspor tanpa melatih model, bab ini bisa dilewati dulu.

### 2.1 Instal lingkungan pelatihan sekali klik

1. Klik **Pengaturan** di kiri.
2. Lihat bagian "Lingkungan pelatihan":
   - Baris **GPU** menampilkan GPU yang terdeteksi, memori GPU, driver, dan versi CUDA yang didukung. Tanpa GPU NVIDIA akan muncul pesan bahwa pelatihan hanya dapat memakai CPU (jauh lebih lambat).
   - Daftar pilihan **Versi PyTorch** otomatis memilih versi yang disarankan (bertanda "Disarankan"); biasanya tidak perlu diubah:
     - CUDA 12.8: GPU baru seperti seri RTX 50;
     - CUDA 13.0: membutuhkan driver yang cukup baru;
     - CUDA 11.8: GPU dan driver yang lebih lama;
     - Versi CPU: tanpa GPU NVIDIA.
3. (Opsional) **Lokasi instalasi**: secara bawaan dipasang di folder data lokal di drive C. Jika ruang drive C terbatas, klik pilih, ganti ke drive yang lebih lega, lalu klik **Simpan**.
4. Klik **Instal sekali klik**. Versi GPU sekitar 3 GB; uv, Python 3.11, dan PyTorch diunduh otomatis, dan layar menampilkan "Langkah N / 5" beserta progres unduhan dan sisa waktu. Cukup dipasang sekali.
   - Jika jaringan terputus, unduhan dilanjutkan dari titik terakhir, dan jaringan yang lambat tidak membuatnya gagal di tengah jalan; untuk berhenti, klik **Batal**.
   - Jika versi PyTorch yang dipilih tidak cocok dengan GPU atau driver (misalnya memilih versi GPU padahal tidak ada GPU NVIDIA, versi CUDA lebih baru dari yang didukung driver, atau versi lama untuk RTX seri 50), Anda akan diperingatkan sebelum mulai.
   - Jika driver terlalu lama sehingga hanya versi CPU yang bisa dipasang, ditampilkan versi driver minimal yang perlu dipasang agar bisa melatih dengan GPU.
5. Setelah selesai, status berubah menjadi **Siap**, dan di bawahnya muncul "GPU tersedia (cuda)".
   - Jika ada komponen yang kurang seperti numpy, onnx, atau opencv, komponen itu akan didaftar; klik **Instal komponen yang kurang** untuk memasang yang kurang saja.
   - Jika versi GPU sudah terpasang tetapi GPU tidak dapat dipakai, muncul peringatan kuning "GPU tidak dapat digunakan, saat ini pelatihan memakai CPU".
6. Jika instalasi gagal, Anda bisa langsung klik **Laporkan masalah ini** di dialog kegagalan; log instalasi otomatis dilampirkan.

> Lingkungan pelatihan berdiri sendiri dan tidak memengaruhi Python lain di sistem.

### 2.2 Sumber unduhan

1. Jika belum pernah dipilih, antarmuka berbahasa Tionghoa memakai mirror Tiongkok secara bawaan, sedangkan bahasa lain memakai sumber resmi.
2. Di bagian "Sumber unduhan", klik **Uji kecepatan dan sarankan**. Aplikasi mengunduh beberapa MB dari sumber resmi dan mirror Tiongkok untuk mengukur kecepatan, lalu otomatis memilih yang lebih cepat.
3. Jika memilih "Mirror Tiongkok", model bantuan seperti SAM dan Prompt teks juga diunduh dari mirror Tiongkok (hf-mirror.com).
4. uv (alat untuk memasang Python) dan ffmpeg (untuk mengekstrak frame video) biasanya diunduh otomatis. Jika unduhan otomatis gagal, Anda bisa memasangnya sendiri lalu menentukan lokasinya di "uv dan ffmpeg (lanjutan)".

### 2.3 Xuntong AI (opsional)

Bagian ini hanya diperlukan jika Anda ingin menganotasi otomatis dengan model di platform Xuntong AI, mengunggah model, mengambil gambar alarm, atau berkolaborasi online lewat "Relay resmi Xuntong":

1. Di bagian "Xuntong AI", klik **Masuk ke akun Xuntong AI**.
2. Browser akan membuka halaman Xuntong AI: jika belum masuk, masuk dulu (sama seperti biasa masuk ke Xuntong), lalu pastikan kode konfirmasi di halaman web sama dengan yang tampil di Wulabel, dan klik **Izinkan**.
3. Kembali ke Wulabel. Beberapa detik kemudian otomatis muncul **Masuk sebagai** beserta nama akun, paket dan sisa kuota, serta metode pengenalan yang tersedia (kenali berdasarkan kelas proyek, model khusus yang diaktifkan di platform, pengenalan umum LLM). Tidak perlu menyalin-tempel Key.
4. Jika browser tidak terbuka otomatis, klik **Buka kembali**, atau salin alamat di jendela pop-up dan buka sendiri.
5. **Keluar**: Key di komputer ini dihapus, dan Key yang dibuat otomatis saat masuk juga dicabut di platform.

Jika sudah punya API Key, atau Xuntong dipasang secara privat (on-premise), klik **Lanjutan: isi API Key secara manual, alamat platform untuk deployment privat**, isi datanya, lalu klik **Simpan dan uji koneksi**. Status koneksi selalu tampil di bagian ini.

### 2.4 Memakai lingkungan Python yang sudah ada (lanjutan)

Jika sudah punya lingkungan Python dengan PyTorch terinstal, Anda tidak perlu mengunduh lagi:

1. Buka "Gunakan lingkungan Python yang sudah ada (lanjutan)".
2. Klik **Pilih python.exe**, lalu pilih `python.exe` di lingkungan tersebut (misalnya `D:\envs\torch\Scripts\python.exe`).
3. Klik **Simpan**. Lingkungan ini harus punya torch, torchvision, numpy, pillow; untuk ekspor ONNX juga perlu onnx.
4. Untuk kembali ke lingkungan milik aplikasi: kosongkan path lalu simpan.

### 2.5 Periksa pembaruan

Saat dibuka, aplikasi otomatis memeriksa sekali apakah ada versi baru; jika ada, muncul notifikasi di kanan bawah. Klik **Perbarui sekarang**: aplikasi mengunduh versi baru di latar belakang, memverifikasinya, lalu memasangnya otomatis dan membuka dirinya kembali. Anda tidak perlu mengklik tombol apa pun selama proses (Windows hanya menampilkan satu bilah progres instalasi; di Linux yang dipasang dengan .deb, pembaruan otomatis juga berfungsi mulai v0.4.2, dan mungkin perlu memasukkan kata sandi sistem sekali). Proyek dan data tetap aman (mulai v0.4.1). Anda juga bisa klik "Unduh" untuk membuka halaman unduhan. Jika tidak ingin diingatkan lagi tentang versi tertentu, klik "Jangan ingatkan lagi untuk versi ini". Jika Anda klik perbarui saat pelatihan, instalasi lingkungan pelatihan, uji langsung, atau berbagi kolaborasi sedang berjalan, tugas-tugas itu akan didaftar dulu dan Anda bisa memilih **Nanti saja**. Saat pembaruan diunduh, dialognya boleh ditutup; unduhan berlanjut di latar belakang dan otomatis dipasang setelah selesai. Di bagian "Tentang & pembaruan" paling bawah halaman Pengaturan, Anda juga bisa mengklik **Periksa pembaruan** secara manual.

Saat memeriksa pembaruan, aplikasi hanya mengirim versi aplikasi, jenis sistem operasi, dan sebuah ID anonim acak untuk memperkirakan jumlah pengguna, tanpa gambar, proyek, atau informasi pribadi apa pun. Jika tidak ingin aplikasi terhubung ke internet untuk memeriksa, matikan **Periksa pembaruan saat aplikasi dibuka** di "Tentang & pembaruan".

### 2.6 Bahasa, tampilan, dan sakelar Xuntong AI

Di bagian atas halaman Pengaturan Anda bisa mengubah:

- **语言 / Language** (sejak v0.5.0): antarmuka tersedia dalam 简体中文, 繁體中文, English, 日本語, 한국어, Español, Português, Русский, Deutsch, Français, Tiếng Việt, Bahasa Indonesia. Defaultnya **Ikuti sistem** (bahasa Mandarin di sistem berbahasa Mandarin, bahasa Inggris untuk bahasa yang belum didukung); antarmuka dimuat ulang setelah diubah. Log pelatihan, pesan kesalahan, laporan serah terima, dan petunjuk paket layanan inferensi juga memakai bahasa ini.
- **Tampilan** (sejak v0.5.1): **Ikuti sistem**, **Terang**, atau **Gelap**. Defaultnya mengikuti mode terang atau gelap sistem. Area gambar seperti kanvas anotasi dan pratinjau gambar selalu gelap agar gambar mudah dilihat.
- **Sakelar Xuntong AI** (sejak v0.5.2): sakelar di pojok kanan atas kartu "Xuntong AI". Aktif secara default untuk bahasa Mandarin sederhana dan nonaktif untuk bahasa lain. Saat nonaktif, Xuntong AI dan aturan pengenalan di halaman Anotasi, pengambilan gambar alarm di halaman Data, unggah ke Xuntong di halaman Deploy, dan relay resmi Xuntong di halaman Kolaborasi disembunyikan; aktifkan jika perlu.

## 3. Membuat dan membuka proyek

**Satu proyek adalah satu folder**: gambar (yang disalin), anotasi, model, dan riwayat pelatihan semuanya ada di dalamnya. Seluruh folder bisa disalin ke komputer lain dan langsung dibuka.

Saat pertama kali memakai aplikasi, di bagian atas halaman "Proyek" ada **panduan pemula** yang memandu Anda lewat enam langkah: instal lingkungan pelatihan, buat proyek, impor gambar, anotasi sebagian kecil, latih, serta pra-anotasi dan deploy. Langkah yang sudah selesai otomatis dicentang. Klik × di kanan atas untuk menutupnya; nanti bisa dibuka lagi lewat "Tampilkan panduan pemula".

Kartu di "Proyek terbaru" menampilkan sampul proyek, jumlah gambar, jumlah yang sudah dianotasi (bilah progres), dan berapa kali sudah dilatih, sehingga Anda bisa melihat sekilas sejauh mana tiap proyek.

### 3.1 Membuat proyek

1. Di halaman **Proyek**, klik **Proyek baru**.
2. **Nama proyek**: misalnya "Deteksi helm di proyek konstruksi".
3. **Lokasi penyimpanan**: bawaannya "Documents/Wulabel"; Anda juga bisa klik **Telusuri** untuk memilih folder lain. Proyek dibuat di dalam folder tersebut.
4. **Jenis tugas** (tidak bisa diubah setelah dibuat):

   | Tugas | Cara anotasi | Cocok untuk |
   |---|---|---|
   | Deteksi objek | Kotak persegi | Menemukan posisi helm, kendaraan, asap dan api |
   | Segmentasi instans | Kontur poligon | Butuh bentuk yang presisi: genangan air, tumpukan sampah, area cacat |
   | Klasifikasi gambar | Satu kelas per gambar | Gambar "normal / abnormal", pengelompokan adegan |
   | Klasifikasi multi-label | Beberapa kelas per gambar | Beberapa hal dalam satu gambar: beberapa jenis kerusakan produk, beberapa atribut adegan |
   | Keypoint | Kotak objek + klik titik satu per satu sesuai templat | Postur tubuh (jatuh, memanjat), bagian penting suatu objek |

5. **Kelas** (boleh dikosongkan): tulis dulu kelas yang akan dianotasi, pisahkan dengan koma atau baris baru, misalnya "helm, orang, rompi reflektif". Jika dikosongkan, kelas bisa ditambahkan kapan saja di halaman Anotasi.
6. Klik **Buat**. Muncul pesan bahwa proyek "…" sudah dibuat, dan proyek langsung terbuka.

### Cara memilih jenis tugas

Jenis tugas tidak bisa diubah setelah proyek dibuat, jadi pikirkan dulu tiga pertanyaan berikut:

1. **Apakah Anda perlu tahu letak objek di gambar?** Jika perlu tahu posisinya atau menghitung jumlahnya, pilih deteksi objek, segmentasi instans, atau keypoint. Jika hanya peduli "gambar ini apa, ada masalah apa", pilih klasifikasi gambar atau klasifikasi multi-label.
2. **Seberapa presisi posisinya?** Jika posisi kira-kira (satu kotak) sudah cukup, pilih **Deteksi objek**; jika butuh bentuk, luas, atau batas yang presisi, pilih **Segmentasi instans**; jika ingin tahu letak tiap bagian orang atau objek (kepala, tangan, kaki), pilih **Keypoint**.
3. **Berapa kesimpulan dalam satu gambar?** Jika hanya satu dan saling meniadakan (produk baik atau cacat, siang atau malam), pilih **Klasifikasi gambar**; jika beberapa bisa berlaku sekaligus (tergores sekaligus kurang aksesori), pilih **Klasifikasi multi-label**.

Pilihan untuk kasus yang umum:

| Kasus | Jenis yang disarankan | Cara anotasi |
|---|---|---|
| Helm dan rompi reflektif di proyek konstruksi, menghitung orang | Deteksi objek | Satu kotak untuk tiap kepala dan tiap rompi reflektif |
| Asap dan api, api terbuka, kendaraan, pejalan kaki | Deteksi objek | Kotaki tiap objek; asap dan api bentuknya tidak beraturan, cukup kotaki area kira-kiranya |
| Cakupan dan luas genangan air, tumpahan oli, tumpukan sampah | Segmentasi instans | Telusuri konturnya |
| Letak retakan, goresan, dan bagian gompal di permukaan produk | Segmentasi instans (perlu bentuk) atau Deteksi objek (cukup posisi) | Cacat yang panjang tipis atau tidak beraturan pakai kontur, selain itu pakai kotak |
| Postur seperti jatuh, memanjat, mengangkat tangan | Keypoint | Gambar dulu kotak orangnya, lalu klik 17 titik sesuai templat |
| Produk baik / cacat di lini produksi, meteran normal / abnormal | Klasifikasi gambar | Di tiap gambar, tekan tombol angka untuk memilih satu kelas |
| Pengelompokan adegan: siang / malam, dalam ruangan / luar ruangan | Klasifikasi gambar | Sama seperti di atas |
| Retur e-commerce, menentukan jenis kerusakan (bilah kipas rusak, debu/noda, aksesori hilang…) | Klasifikasi multi-label | Di tiap gambar, centang semua kerusakan yang terlihat; jika tidak ada masalah, centang "Baru" |
| Atribut foto produk (warna, model, ada kemasan atau tidak) | Klasifikasi multi-label | Di tiap gambar, centang semua atribut yang sesuai |

Kasus yang sering salah pilih:

- **Klasifikasi atau deteksi**: jika satu gambar berisi beberapa objek, objeknya kecil, atau Anda perlu melaporkan posisi dan jumlah, pakai deteksi. Jika seluruh gambar hanya punya satu subjek utama dan Anda hanya peduli apa itu, pakai klasifikasi; anotasinya jauh lebih cepat (satu tombol per gambar).
- **Satu label atau multi-label**: jika kelas-kelasnya saling meniadakan dan tiap gambar hanya bisa salah satunya, pakai klasifikasi gambar; jika beberapa bisa berlaku sekaligus, pakai klasifikasi multi-label. Di proyek multi-label tiap gambar wajib punya minimal satu kelas, jadi tambahkan kelas seperti "Baru" atau "Normal" untuk gambar yang tidak bermasalah.
- **Deteksi atau segmentasi**: jika hanya perlu peringatan, hitungan, atau posisi, pakai deteksi; pakai segmentasi hanya jika perlu luas atau batas yang presisi. Anotasi segmentasi jauh lebih lambat dibanding menggambar kotak.
- **Masalahnya sangat kecil**: jika cacat hanya menempati bagian kecil gambar, klasifikasi seluruh gambar mungkin tidak bisa mengenalinya. Ganti ke deteksi untuk mengotaki cacatnya, atau foto dari lebih dekat agar cacat tampak lebih besar di gambar.
- **Gambar untuk pelatihan**: jangan langsung melatih dengan gambar perbandingan hasil gabungan atau gambar yang diberi lingkaran merah atau tulisan, karena model bisa belajar bahwa "ada lingkaran merah berarti ada masalah". Sebisa mungkin pakai gambar asli.

Jika ragu, buat dulu proyek kecil, anotasi beberapa puluh gambar, coba latih sekali, lalu putuskan setelah melihat hasil evaluasi.

### 3.2 Membuka proyek

- Klik proyek di daftar **Proyek terbaru** untuk membukanya; daftar ini menampilkan kapan tiap proyek terakhir dibuka.
- Jika tidak ada di daftar, klik **Buka proyek…** dan pilih folder proyek.
- Jika folder proyek dipindahkan, daftar akan menampilkan "Folder tidak ditemukan": klik **Cari lokasi…** dan pilih lokasi barunya untuk melanjutkan. Jika foldernya sudah dihapus, klik "Hapus dari daftar" (file tidak dihapus).

## 4. Impor data

Klik **Data** di kiri.

### 4.1 Impor gambar atau folder

1. Pertama, pilih cara impor di bagian atas halaman:
   - **Salin ke proyek**: gambar disalin ke folder proyek, sehingga proyek bisa dipindahkan utuh (disarankan);
   - **Hanya rujuk path asli**: hanya mencatat lokasi asli gambar, tidak memakan ruang tambahan, tetapi gambar asli tidak boleh dipindahkan.
2. Impor:
   - Klik **Impor folder** dan pilih folder (gambar di subfolder juga dicari otomatis);
   - Atau klik **Opsi impor lainnya → Impor file gambar** dan pilih beberapa gambar;
   - Atau **seret** gambar atau folder langsung **ke jendela**, lalu lepaskan saat muncul "Lepaskan untuk mengimpor gambar atau video". Jika yang diseret adalah file video, dialog "Ekstrak frame dari video" langsung terbuka (lihat 4.2).
3. Selama impor, progres tampil dalam dua tahap: pertama "Diproses N / M gambar (menghitung sidik jari, membuat thumbnail)", lalu "Menyalin dan menulis: N / M gambar" ("Menulis ke proyek" jika hanya mereferensikan path asli). Mengimpor puluhan ribu gambar sekaligus tidak membuat aplikasi macet, dan thumbnail tetap bisa dilihat selama impor. Jika salah pilih, klik **Hentikan**; gambar yang sudah diproses tetap masuk. Setelah selesai, muncul berapa gambar baru dan berapa duplikat yang dilewati; klik **Mulai anotasi** di pesan tersebut untuk langsung ke halaman Anotasi.

Saat impor, gambar otomatis **dideduplikasi berdasarkan isi** (gambar yang sama tidak diimpor dua kali), dan **orientasinya diluruskan** berdasarkan informasi EXIF foto.

### 4.2 Impor video (ekstrak frame)

1. Klik **Opsi impor lainnya → Impor video (ekstrak frame)**, lalu pilih satu atau beberapa file video.
2. Atur di dialog "Ekstrak frame dari video":
   - **Setiap N dtk, ekstrak 1 frame**: jika objek berubah lambat, buat jaraknya lebih lama agar tidak muncul banyak gambar yang hampir sama;
   - **Maksimal per video**: N frame (0 = tanpa batas).
3. Klik **Mulai ekstraksi**. Pada pemakaian pertama ffmpeg diunduh otomatis (sekitar 90 MB); setelah itu tidak perlu lagi. Jika parameternya salah, klik **Hentikan**; frame yang sudah diekstrak tetap diimpor.
4. Frame hasil ekstraksi disalin ke proyek dan otomatis dideduplikasi berdasarkan isi. Setelah selesai muncul pesan "M frame diekstrak dari N video: K gambar baru".

### 4.3 Ekstrak frame dari stream video (RTSP / siaran langsung / rekaman)

1. Klik **Opsi impor lainnya → Ekstrak frame dari stream video (RTSP / siaran langsung / rekaman)**.
2. Isi alamat: kamera RTSP (`rtsp://…`), atau alamat siaran langsung, rekaman, atau on-demand http(s) (mp4, m3u8, flv).
   - Hikvision: `rtsp://<pengguna>:<sandi>@IP:554/Streaming/Channels/101` (stream utama) atau `102` (substream)
   - Dahua: `rtsp://<pengguna>:<sandi>@IP:554/cam/realmonitor?channel=1&subtype=0`
3. Klik **Uji koneksi**. Resolusi akan tampil, beserta jenis stream: "Siaran langsung (tanpa akhir, atur batas)" atau "Stream rekaman · Durasi …".
4. Pengaturan:
   - **Setiap N dtk, ekstrak 1 frame**;
   - **Ekstrak maksimal** N frame, **Rekam maksimal** N menit (0 = tanpa batas, hanya siaran langsung). **Siaran langsung tidak pernah berakhir, jadi minimal salah satunya harus diatur**;
   - Centang **Lewati frame yang hampir identik**: lebih sedikit gambar duplikat saat gambar diam.
5. Klik **Mulai perekaman**. Gambar langsung disimpan sambil direkam, dan muncul satu per satu di halaman Data.
6. Selama perekaman Anda bisa klik **Perkecil** untuk mengerjakan hal lain; di kanan bawah tampil "Merekam · N frame diekstrak", klik **Perluas** untuk kembali. Klik **Hentikan perekaman** kapan saja untuk berhenti; gambar yang sudah direkam tetap disimpan.
7. Gambar hasil rekaman disimpan di folder `images/stream_<alamat>_<waktu>/` dalam proyek. Setelah selesai, klik **Buka folder** untuk melihatnya.

> Nama pengguna dan kata sandi hanya dipakai saat perekaman; aplikasi tidak menulis alamat yang berisi kata sandi ke nama folder proyek.

### 4.4 Impor dataset beranotasi

Jika sudah punya data yang dianotasi di tempat lain, Anda bisa mengimpornya bersama anotasinya:

1. Klik **Opsi impor lainnya**, lalu pilih sesuai jenis proyek:
   - Proyek deteksi / segmentasi: **Impor dataset beranotasi (YOLO / COCO / VOC)**, mendukung YOLO (termasuk seg), COCO (termasuk segmentasi), VOC;
   - Proyek keypoint: **Impor dataset beranotasi (YOLO-pose / keypoint COCO)**;
   - Proyek klasifikasi: **Impor dataset klasifikasi (satu folder per kelas)**. Setiap subfolder di dalam folder yang dipilih adalah satu kelas (boleh juga ada satu tingkat train / val di atasnya).
2. Pilih folder akar dataset; aplikasi otomatis mengenali formatnya.
3. Setelah selesai muncul pesan seperti "Dataset YOLO diimpor", beserta kelas baru yang ditambahkan.

### 4.5 Operasi massal, urungkan, hapus, kosongkan

Kartu statistik di bagian atas halaman Data (Belum dianotasi, Sudah dianotasi, Dilewati) bisa diklik: klik sekali untuk hanya menampilkan jenis gambar itu, klik lagi untuk kembali ke semua. Tombol filter di bawahnya juga sama.

Semuanya ada di menu **Kelola**:

- **Pilih banyak**: masuk mode pilih, klik gambar untuk mencentangnya; tahan **Shift** dan klik gambar lain untuk memilih semua gambar di antaranya. "Pilih semua di halaman ini" memilih halaman ini, "Pilih semua N gambar" memilih semua gambar di filter saat ini. Setelah dipilih, Anda bisa:
  - **Tandai dilewati**: gambar-gambar ini tidak ikut pelatihan;
  - **Pulihkan ke belum dianotasi**: gambar yang sudah punya anotasi akan kembali menjadi Sudah dianotasi;
  - **Ke anotasi**: hanya gambar yang dipilih yang dikirim ke halaman Anotasi untuk dianotasi satu per satu;
  - **Bagi**: pindahkan ke set pelatihan, set validasi, atau set uji (hanya berlaku untuk gambar yang sudah dianotasi; lihat 10.1);
  - **Hapus**.
  Saat filter atau halaman diganti, pilihan dikosongkan agar gambar yang tidak terlihat tidak ikut terhapus. Terakhir klik **Selesai** untuk keluar.
- **Urungkan impor terakhir (N gambar)**: kalau baru saja salah impor, hapus gambar dari impor terakhir sekali klik (satu kali perekaman stream video dihitung satu kali impor).
- **Hapus semua gambar**: menghapus semua gambar di proyek.

Saat gambar dihapus, anotasinya ikut terhapus dan tidak bisa dipulihkan. Salinan gambar di proyek dihapus, tetapi gambar asli di komputer Anda tidak terpengaruh. Jika yang dihapus banyak, dialog menampilkan progres penghapusan.

### 4.6 Penyaringan kualitas gambar

Gambar yang buram, terlalu gelap, atau terlalu terang sulit dianotasi dan bisa menyesatkan model saat pelatihan. Saring dulu:

1. Klik **Kelola → Penyaringan kualitas gambar (buram, terlalu gelap, terlalu terang)**.
2. Secara bawaan **Hanya tampilkan gambar yang belum dianotasi** dicentang; hapus centang jika ingin memeriksa semuanya.
3. Klik **Mulai penyaringan**.
4. Hasil dikelompokkan per masalah: **Buram**, **Terlalu gelap**, **Terlalu terang**, **Kontras rendah**; klik label di atas untuk menyaring. Di bawah tiap gambar tampil nilai ketajaman, kecerahan, proporsi area terlalu terang, dan kontras.
5. Tindakan:
   - **Periksa satu per satu**: pindah ke halaman Anotasi untuk melihat satu per satu dan memutuskan sendiri;
   - **Tandai dilewati**: ditandai "Dilewati" dan tidak ikut pelatihan (gambar tetap ada, bisa dibatalkan nanti);
   - **Hapus**: langsung dihapus.

### 4.7 Mengambil gambar alarm dari Xuntong AI

Setelah model di-deploy ke platform Xuntong AI, tangkapan alarm dari lapangan (terutama positif palsu dan objek yang terlewat) adalah data yang paling layak ditambahkan:

1. Atur Xuntong AI dulu di **Pengaturan** (lihat 2.3).
2. Di halaman **Data**, klik **Opsi impor lainnya → Ambil gambar alarm dari Xuntong AI**.
3. Pilih rentang waktu (1 / 3 / 7 hari terakhir; platform menyimpan gambar alarm selama 7 hari, jadi ambil secara rutin), model (semua atau salah satu), dan jumlah **maksimal** N gambar. Hanya akun Xuntong yang sudah mengatur saluran pengiriman yang menghasilkan catatan alarm.
4. Secara bawaan dicentang **Gunakan kotak hasil deteksi platform sebagai pra-anotasi**: dicocokkan ke kelas proyek berdasarkan nama kelas; kelas yang belum ada akan dibuat.
5. Klik **Mulai ambil**. Gambar disimpan di folder `images/xuntong_<waktu>/` dalam proyek, dan kotak hasil pengenalan tampil dengan garis putus-putus (sumber "Xuntong").
6. Periksa di halaman Anotasi: hapus kotak positif palsu (gambar tanpa objek cukup tekan **Enter** (Selesai) agar disimpan sebagai sampel negatif), tambahkan yang terlewat, lalu latih ulang.

## 5. Anotasi

Klik **Anotasi** di kiri.

### 5.1 Mengenal halaman Anotasi

- **Bagian atas**: panah kiri/kanan untuk berpindah gambar, nama dan nomor gambar saat ini (gambar ke berapa / dari total; klik nomornya untuk mengetik angka dan langsung melompat), resolusi, label status (Belum dianotasi / Sudah dianotasi / Dilewati; gambar tanpa objek menampilkan "Tanpa objek"); tombol filter **Semua / Belum dianotasi / Sudah dianotasi / Dilewati** (saat kolaborasi tim menjadi **Semua / Belum dianotasi / Menunggu tinjauan / Disetujui / Dilewati / Dikembalikan**, dan label statusnya juga bernama "Menunggu tinjauan" dan "Disetujui", lihat 9.4); paling kanan ada skala zoom dan status penyimpanan (Tersimpan / Belum disimpan / Menyimpan… / Gagal menyimpan).
- **Bilah alat kiri**: pilih, gambar kotak (atau gambar kontur), pilih cerdas SAM, urungkan, ulangi, salin anotasi gambar sebelumnya, interpolasi keyframe, lacak ke depan, sesuaikan dengan jendela. Arahkan mouse ke alat untuk melihat keterangan dan pintasannya.
- **Tengah**: kanvas gambar. Gulir roda mouse untuk zoom; tahan Spasi atau seret dengan klik kanan untuk menggeser gambar.
- **Kanan**: panel "Bantuan AI", "Kelas", "Objek di gambar ini" (proyek klasifikasi: "Kelas gambar ini"), dan "Selesai" (saat kolaborasi tim, panel ini bernama "Tinjau").
- **Di bawah kanvas**: petunjuk pintasan yang tersedia untuk proyek ini; tekan **?** untuk membuka panel semua pintasan.
- **Paling bawah**: strip thumbnail beberapa gambar sebelum dan sesudahnya; klik untuk langsung melompat. Titik kecil di pojok kanan atas thumbnail menunjukkan status: biru berarti sudah dianotasi, abu-abu berarti dilewati, tanpa titik berarti belum dianotasi.

Perubahan **disimpan otomatis**, tidak perlu menyimpan manual.

### 5.2 Menambah dan mengelola kelas

1. Di panel "Kelas" sebelah kanan, ketik di kotak "Nama kelas baru, tekan Enter untuk menambahkan", misalnya "helm", lalu tekan Enter.
2. Sembilan kelas pertama bisa diganti cepat dengan tombol angka **1–9**; kelas aktif disorot.
3. Klik tombol edit di samping kelas untuk:
   - mengubah nama dan warna;
   - mengisi **Prompt bahasa Inggris** (dipakai anotasi otomatis "Prompt teks"; boleh beberapa, pisahkan dengan koma, misalnya `helmet, hard hat`);
   - mengisi **Catatan pengenalan** (dipakai Xuntong AI "Kenali berdasarkan kelas proyek": apa yang dimaksud kelas ini, apa yang termasuk / tidak termasuk, misalnya "orang tanpa helm di kepala; memakai helm tetapi tali tidak dikaitkan juga termasuk");
   - menghapus kelas. Jika kelas ini sudah punya anotasi, Anda bisa memilih kelas lain di "Gabungkan ke…", dan anotasinya diubah ke kelas tersebut sehingga tidak hilang (berguna saat salah kelas atau ingin menggabungkan dua kelas menjadi satu); jika tidak dipilih, kelas langsung dihapus dan anotasinya ikut terhapus.

### 5.3 Deteksi objek: menggambar kotak

1. Tekan **1–9** untuk memilih kelas.
2. Tekan **R** (atau klik alat gambar kotak di kiri), lalu **tahan dan seret mouse untuk membuat kotak** di atas objek.
3. Menyesuaikan: tekan **V** untuk beralih ke alat pilih, klik kotak, lalu seret untuk memindahkan atau tarik sudut/tepi untuk mengubah ukuran.
4. Menghapus: pilih kotak lalu tekan **Del** atau **Backspace**; tekan **Esc** untuk membatalkan pilihan.
5. Mengganti kelas: pilih kotak lalu tekan tombol angka, atau ubah di "Objek di gambar ini" sebelah kanan.
6. Tekan **H** untuk menyembunyikan / menampilkan nama kelas di kotak; berguna saat kotak sangat rapat.

### 5.4 Segmentasi instans: menggambar kontur

1. Pilih kelas, tekan **R**.
2. **Klik titik demi titik** di sepanjang tepi objek.
3. **Klik ganda** atau tekan **Enter** untuk menutup kontur; jika salah klik, tekan **Backspace** untuk membatalkan titik terakhir.
4. Setelah kontur dipilih, seret titik sudutnya untuk menyesuaikan.
5. Cara yang lebih cepat: tekan **S** untuk pilih cerdas SAM; sekali klik langsung menghasilkan kontur (lihat Bab 6).

### 5.5 Klasifikasi gambar: satu tombol satu gambar

1. Lihat gambar, tekan tombol angka **1–9** untuk memilih kelas. Kelas saat ini tampil di kiri atas gambar.
2. Setelah sakelar **Otomatis lanjut** di kanan dinyalakan, setiap kali menekan angka aplikasi langsung pindah ke gambar berikutnya: satu tombol, satu gambar.
3. Tekan **Del** untuk menghapus kelas gambar ini; tekan **Ctrl+D** untuk memakai kelas gambar sebelumnya.

Dalam proyek **klasifikasi multi-label**, satu gambar bisa punya beberapa kelas: tekan **1–9** untuk mencentang kelas dan tekan lagi untuk menghapus centang, lalu **Enter**; **Del** menghapus semuanya, **Ctrl+D** memakai semua kelas dari gambar sebelumnya, dan **P** membuat model mencentang semua kelas yang skornya mencapai ambang keyakinan. Halaman Evaluasi memakai **mAP** sebagai metrik utama, ditambah porsi yang cocok persis, dan menampilkan kesalahan sebagai "Terlewat: … · Lebih: …".

Gambar yang sudah dianotasi untuk deteksi objek (atau segmentasi, titik kunci) tidak perlu diulang: di halaman **Data** proyek asal, pilih **Kelola → Ubah menjadi proyek klasifikasi multi-label**. Proyek multi-label baru dibuat dan setiap gambar diberi semua kelas yang dianotasi di dalamnya; gambar bertanda "Tidak ada objek" bisa diberi kelas seperti "Normal". Proyek asal tidak berubah.

Tiap kelas punya tingkat kemudahan dikenali yang berbeda (misalnya "debu dan noda" cenderung skornya lebih rendah), jadi tabel ambang rekomendasi di halaman Evaluasi menghitung satu untuk tiap kelas. Di halaman **Deploy**, verifikasi langsung, pengenalan massal, dan paket layanan inferensi secara bawaan mencentang **Pakai ambang rekomendasi masing-masing kelas**, sehingga tiap kelas dinilai dengan ambangnya sendiri; hapus centang untuk memakai satu ambang bagi semua kelas.

### 5.6 Keypoint

1. Lihat dulu **Templat keypoint** di kanan. Bawaannya "COCO tubuh manusia 17 titik" (hidung, mata kiri, mata kanan … pergelangan kaki kiri, pergelangan kaki kanan). Untuk mengubahnya, klik **Edit**:
   - **Nama templat**;
   - **Nama titik** (satu per baris; urutan titik adalah urutan klik saat anotasi);
   - **Sambungan** (satu pasang nomor per baris, misalnya `1-2`, untuk menggambar kerangka);
   - Anda juga bisa klik **Gunakan COCO tubuh manusia 17 titik** untuk kembali ke bawaan.
   - Setelah ada anotasi keypoint, hanya nama dan sambungan yang bisa diubah; jumlah titik tidak bisa ditambah atau dikurangi.
2. Pilih kelas, tekan **R** untuk menggambar kotak objek.
3. Setelah kotak jadi, ikuti petunjuk untuk **mengklik tiap keypoint secara berurutan** (di bawah gambar tampil titik mana yang harus diklik, misalnya "Klik bahu kiri (6/17)"):
   - Klik biasa: titik yang terlihat;
   - **Shift + klik**: titik yang terhalang;
   - **N**: lewati titik yang tidak terlihat;
   - **Backspace**: kembali ke titik sebelumnya;
   - **Esc**: selesaikan objek ini.
4. Menyesuaikan: setelah objek dipilih, seret keypoint secara langsung. Di kanan tercantum status tiap titik; klik nama untuk menempatkan ulang titik tersebut; klik status untuk beralih "terlihat / terhalang".
5. Setelah objek dipilih, klik **Tempatkan ulang keypoint** untuk menandai ulang mulai dari titik pertama.

### 5.7 Salin gambar sebelumnya, urungkan dan ulangi

- **Ctrl+D** (atau tombol salin di kiri): menyalin seluruh anotasi gambar sebelumnya. Sangat menghemat waktu untuk adegan yang mirip atau frame berurutan. Di proyek klasifikasi, kelas gambar sebelumnya yang dipakai.
- **Ctrl+Z** untuk urungkan, **Ctrl+Y** untuk ulangi.

### 5.8 Selesai, lewati

Saat menganotasi sendiri, tidak perlu peninjauan: gambar yang objeknya sudah dianotasi otomatis dihitung "Sudah dianotasi" dan langsung ikut pelatihan. Panel "Selesai" di kanan:

- **Selesai & berikutnya** (pintasan **Enter**): melompat ke gambar belum dianotasi berikutnya.
  - Jika gambar ini memang tidak berisi objek, menekan Enter akan mencatatnya sebagai "Tanpa objek", dan gambar ikut pelatihan sebagai **sampel negatif** (mengajari model agar tidak salah deteksi pada adegan seperti ini). Jika tidak sengaja menekan, klik **Batalkan status** di pesan yang muncul.
  - Gambar hasil pra-anotasi massal (kotak putus-putus) yang sudah diperiksa dan diperbaiki dihitung sudah dianotasi setelah menekan Enter.
- **Lewati** (pintasan **X**): ditandai "Dilewati", gambar ini tidak ikut pelatihan. Cocok untuk gambar buram atau tidak relevan.
- **Batalkan status**: mengembalikan "Tanpa objek" atau "Dilewati" ke status semula.
- **Shift+D**: langsung melompat ke gambar belum dianotasi berikutnya.

Setelah gambar terakhir selesai, muncul "Batch ini selesai" beserta jumlah gambar yang sudah dan belum dianotasi; Anda bisa klik **Ke pelatihan** atau **Lanjut ke yang belum dianotasi**.

Pilih "Dilewati" di filter atas untuk menemukan gambar yang dilewati dan memeriksanya kembali.

Alur peninjauan hanya ada saat kolaborasi tim (sudah menambahkan anggota atau mengaktifkan kolaborasi langsung). Saat itu panel ini menjadi "Tinjau", dengan tombol **Setujui & berikutnya** dan **Kembalikan**. Jika gambarnya banyak, meninjau secara massal di halaman **Tinjau** di kiri lebih cepat; lihat 9.4.

### 5.9 Frame video: interpolasi keyframe, lacak ke depan

Berlaku untuk proyek deteksi dan keypoint. Frame hasil ekstraksi video (dalam satu folder, berurutan sesuai nama file) tidak perlu digambar satu per satu.

**Interpolasi keyframe** (untuk potongan di mana objek bergerak dengan kecepatan tetap):

1. Buka frame di awal potongan dan anotasi semua objeknya (inilah sebuah "keyframe").
2. Buka frame di akhir potongan dan anotasi objek yang sama.
3. Di frame akhir ini, klik tombol **Interpolasi keyframe** di kiri.
4. Aplikasi mencocokkan objek di kedua ujung berdasarkan kelas dan posisi, lalu otomatis mengisi frame di antaranya. Muncul pesan "M objek diinterpolasi pada N frame di antaranya"; objek yang tidak cocok di kedua ujung dijelaskan terpisah.

**Lacak ke depan** (untuk objek yang bergerak tidak teratur):

1. Anotasi objek di frame saat ini.
2. Klik tombol **Lacak ke depan** di kiri, isi **Jumlah frame** di jendela kecil yang muncul (bawaan 30, maksimal 500), lalu klik **Lacak**.
3. Aplikasi mengikuti kotak dari frame ini, frame demi frame. Pelacakan berhenti jika objek terhalang atau hilang, dan juga berhenti di frame yang sudah dianotasi manual, sehingga anotasi manual tidak ditimpa.
4. Setelah selesai, aplikasi otomatis melompat ke frame terakhir yang terlacak. Jika kotak bergeser, seret hingga pas (kotak yang diseret menjadi anotasi manual, dan frame ini menjadi keyframe baru), lalu klik **Lacak ke depan** lagi untuk melanjutkan.

Kotak hasil interpolasi dan pelacakan tampil dengan sumber "Interpolasi" dan "Lacak" di "Objek di gambar ini" sebelah kanan. Interpolasi atau pelacakan ulang akan menggantinya, tetapi kotak yang dianotasi manual tidak diubah.

> Cara hemat tenaga: anotasi manual sebagian kecil dulu (puluhan hingga satu-dua ratus gambar), latih model versi awal, lalu gunakan model itu untuk pra-anotasi sisanya (Bab 12). Anda cukup memperbaiki kesalahannya.

## 6. Anotasi dengan bantuan AI

Saat belum punya model sendiri, Anda tetap bisa meminta AI membantu menganotasi.

### 6.1 Pilih cerdas SAM

1. Pilih kelas, tekan **S** (atau klik tombol SAM di kiri).
2. Pemakaian pertama akan menginstal komponen dan mengunduh model, mungkin butuh beberapa menit; di layar tampil "Menyiapkan SAM…", dan kanan bawah menampilkan "Mengunduh dan menginstal" beserta progres setiap file (jika terputus akan dilanjutkan; cukup sekali). Dengan GPU NVIDIA dipakai SAM ViT-B; jika tidak, dipakai SlimSAM yang ringan.
3. **Klik sekali** pada objek, dan kontur objek terpilih otomatis (pratinjau).
   - Terpilih terlalu banyak: **Shift + klik** bagian yang berlebih untuk mengecualikannya;
   - Terpilih terlalu sedikit: klik lagi bagian yang belum terpilih;
   - Salah klik: tekan **Backspace** untuk membatalkan titik terakhir;
   - Anda juga bisa **menyeret kotak** untuk membingkai objek.
4. Jika sudah pas, tekan **Enter** untuk menerimanya sebagai kelas saat ini; tekan **Esc** untuk membatalkan.
5. Hasil: proyek segmentasi mendapat poligon, proyek deteksi mendapat kotak yang pas di tepi objek, dan proyek keypoint mendapat objek baru (lalu klik "Tempatkan ulang keypoint" untuk menandai titiknya).

### 6.2 Prompt teks

Mencari objek di gambar secara otomatis berdasarkan nama kelas:

1. Di "Bantuan AI" sebelah kanan, pilih **Prompt teks**.
2. Model hanya memahami bahasa Inggris. Nama kelas umum dalam bahasa Mandarin (lebih dari seratus, seperti 安全帽, 人员, 电动车, 渣土车, 锥桶) otomatis dipetakan ke bahasa Inggris dan ditampilkan di belakang nama kelas, misalnya "安全帽 · helmet" (helm); nama kelas yang mengandung kata-kata tersebut juga bisa, misalnya "红色安全帽" (helm merah). Jika tidak cocok (misalnya nama kelas dalam bahasa Indonesia) atau ingin diubah, isi **Prompt bahasa Inggris** saat mengedit kelas.
3. Atur **Keyakinan**: naikkan jika yang ditemukan terlalu banyak, turunkan jika tidak menemukan apa-apa.
4. Klik **Anotasi gambar ini (P)** untuk gambar saat ini, atau klik **Pra-anotasi massal** untuk satu kumpulan sekaligus.
5. Pemakaian pertama perlu mengunduh model, butuh beberapa menit. Di proyek segmentasi, SAM juga dipakai untuk membuat kontur.

### 6.3 Xuntong AI

(Cara pakai Xuntong AI selengkapnya ada di Bab 16.)

1. Atur Xuntong AI dulu di **Pengaturan** (lihat 2.3).
2. Di "Bantuan AI", pilih **Xuntong AI**, lalu di "Pilih model pengenalan" pilih:
   - **Kenali berdasarkan kelas proyek (disarankan)**: hanya mencari kelas di proyek, nama kelas dipakai apa adanya, mengikuti catatan pengenalan tiap kelas dan aturan umum, dan tidak mengenali hal lain yang tidak Anda perlukan;
   - **Model khusus** yang diaktifkan di platform;
   - **Pengenalan umum LLM**: mencari berdasarkan kategori bahaya keselamatan (kebakaran, kelistrikan, sanitasi lingkungan, dll.).
3. Klik **Anotasi gambar ini (P)** atau **Pra-anotasi massal**. Pra-anotasi massal dengan model khusus (misalnya pemilahan sampah) sangat cepat: 8 gambar per kumpulan, dua kumpulan dikirim bersamaan; LLM dan pengenalan berdasarkan kelas proyek memproses satu per satu, jadi lebih lambat.
4. Xuntong AI menghitung 1 panggilan per gambar dan memakai kuota paket akun Anda; sebelum proses massal akan ada pemberitahuan.

### 6.4 Aturan pengenalan: jelaskan kepada AI cara mengenali

Dengan nama kelas saja, AI belum tentu tahu persis apa yang Anda maksud. Tuliskan aturannya dengan jelas, atau langsung mengobrol dengan AI:

1. Di samping judul "Bantuan AI", klik **Aturan pengenalan**; panel aturan pengenalan terbuka di kanan.
2. **Mengobrol dengan AI**: jelaskan dengan bahasa sehari-hari cara mengenalinya, misalnya "memakai helm tetapi tali tidak dikaitkan tetap dihitung tidak memakai helm", "rompi reflektif tidak termasuk", "hanya lihat lorong di bagian bawah gambar"; Anda juga bisa bertanya "kenapa orang di sebelah kiri gambar ini tidak dikenali?".
   - Secara bawaan **Lampirkan gambar saat ini** dicentang; AI akan mencoba mengenali gambar ini sesuai aturan baru.
   - Setelah AI menjawab, jika AI menyarankan perubahan aturan, akan tampil "AI menyarankan pembaruan aturan" beserta isinya; aturan baru disimpan hanya setelah Anda klik **Terapkan aturan ini**.
   - Jika uji pengenalan memberi hasil, klik **Tambahkan N kotak hasil uji pengenalan ke gambar ini** untuk langsung memakainya sebagai pra-anotasi.
   - `Ctrl+Enter` untuk mengirim. Setiap percakapan memakai kuota Xuntong AI.
3. **Aturan saat ini**: Anda bisa langsung mengubah **Aturan umum** (berlaku untuk semua kelas) dan **Catatan pengenalan per kelas**, lalu klik **Simpan aturan**.
4. Setelah itu, pra-anotasi dengan "Kenali berdasarkan kelas proyek" di Xuntong AI akan mengikuti aturan ini.
5. (Opsional) Di bagian paling bawah "Aturan saat ini", klik **Sinkronkan ke platform Xuntong**: kelas dan aturan disimpan ke platform Xuntong. Secara bawaan **tidak aktif**, jadi tidak memengaruhi pengenalan platform saat ini. Setelah terikat, setiap kali aturan disimpan atau diterapkan, isinya otomatis disinkronkan (status aktif/nonaktif dan skenario yang berlaku yang Anda atur di konsol Xuntong tidak diubah).
6. Jika ingin pengenalan milik platform Xuntong sendiri (asisten tangkapan, pengiriman alarm) juga hanya melaporkan kelas yang Anda perlukan, nyalakan **Pakai aturan ini juga untuk pengenalan di platform**. Perhatian: setelah dinyalakan, semua pengenalan di akun Xuntong mengikuti kelas proyek ini; skenario yang berlaku bisa diatur di "Aturan pengenalan" pada konsol Xuntong. Jika tidak ingin sinkron lagi, klik **Lepas ikatan** (aturan di platform tidak dihapus). Setiap akun Xuntong maksimal punya 20 set aturan pengenalan.

Batasan: pengenalan berdasarkan kelas proyek maksimal 30 kelas, nama kelas maksimal 30 karakter; aturan umum maksimal 1000 karakter, dan catatan pengenalan tiap kelas maksimal 500 karakter.

Saat berkolaborasi, anggota juga bisa membuka aturan pengenalan dan mengobrol dengan AI (jika host mengizinkan bantuan AI, yang dipakai adalah kuota host); boleh tidaknya mengubah aturan mengikuti sakelar "Anggota dapat menambah dan mengedit kelas".

Kotak dan kontur hasil AI tampil dengan **garis putus-putus**. Periksa sekali: hapus yang salah, seret yang bergeser hingga pas, tambahkan yang terlewat, lalu tekan **Enter** (Selesai & berikutnya).

## 7. Cek data

Klik **Cek data** di kiri untuk menemukan masalah dalam data sekali klik.

1. Pilih cara pemeriksaan:
   - Jika sudah punya model terlatih: pilih "Periksa dengan model: nama model · mAP50 …"; aturan dan model diperiksa bersama;
   - Jika belum punya model: pilih "Hanya pemeriksaan aturan (tanpa model)".
2. Klik **Mulai cek data**. Progres ditampilkan per tahap: "Cek duplikat: menghitung sidik jari" → "Cek duplikat: membandingkan berpasangan" → "Pemeriksaan dengan model". Jika gambarnya banyak, prosesnya butuh beberapa menit; Anda bisa klik **Hentikan** (hasil pemeriksaan yang dihentikan tidak disimpan). Jika Anda meninggalkan halaman cek data lalu kembali, progres yang masih berjalan tetap terlihat. Sidik jari gambar yang sudah diperiksa disimpan di cache, jadi lain kali hanya gambar baru yang dihitung.
3. Hasil ditampilkan per jenis masalah:

   | Masalah | Artinya | Perlu model |
   |---|---|---|
   | Kemungkinan terlewat | Model sangat yakin ada objek di sini, tetapi tidak ada anotasinya | Ya |
   | Kemungkinan salah kelas | Posisi kotak cocok, tetapi kelasnya berbeda dari penilaian model | Ya |
   | Kotak tidak akurat | Kelas sama, tetapi tumpang tindih kotak dengan prediksi model rendah | Ya |
   | Kemungkinan kotak berlebih | Ada kotak, tetapi model tidak melihat apa pun di posisi itu | Ya |
   | Kotak sangat kecil | Sisi pendek kurang dari 8 piksel; model hampir tidak bisa mempelajarinya | Tidak |
   | Kotak duplikat | Dua kotak kelas yang sama di satu gambar hampir sepenuhnya bertumpuk | Tidak |
   | Gambar duplikat | Gambar yang isinya hampir sama; membuat hasil evaluasi terlalu tinggi | Tidak |
   | Tanpa kelas | Kotak tidak punya kelas dan tidak ikut pelatihan | Tidak |

4. Untuk setiap masalah, Anda bisa:
   - **Perbaiki**: pindah ke halaman Anotasi dengan kotak tersebut disorot;
   - **Tambahkan sebagai anotasi**: untuk kemungkinan terlewat, langsung tambahkan kotak sesuai penilaian model;
   - **Bukan masalah**: abaikan, dan pemeriksaan berikutnya tidak akan menandainya lagi.
   Jika satu jenis masalah jumlahnya banyak, gunakan **Tambahkan semua sebagai anotasi** (kemungkinan terlewat) atau **Abaikan semua** untuk menyelesaikannya sekaligus. Masalah yang sudah diabaikan bisa dikembalikan dengan mengklik "N item diabaikan · Pulihkan".
5. Gambar yang sudah diperbaiki di halaman Anotasi akan ditandai "Sudah diubah" dan diciutkan secara bawaan saat kembali ke halaman cek data, jadi tidak perlu menjalankan cek ulang.
6. Gambar duplikat ditampilkan per grup, dan setiap gambar menampilkan status serta jumlah anotasinya. Gambar berbingkai hijau adalah yang dipertahankan; secara bawaan dipilih yang anotasinya paling lengkap (Disetujui > Sudah dianotasi > anotasi lebih banyak). Klik gambar lain untuk menggantinya, klik dua kali untuk melihatnya di halaman Anotasi. Klik **Sisakan satu per grup** untuk menghapus sisanya; gambar yang punya anotasi tidak akan terhapus tanpa sengaja.
7. Di bagian bawah halaman juga ada **Distribusi kelas** (jumlah kotak · jumlah gambar) dan **Distribusi ukuran kotak**; jika kelas terlalu sedikit atau kotak terlalu kecil, akan diberikan saran. Untuk proyek klasifikasi, hanya diperiksa kemungkinan salah kelas dan gambar duplikat.

## 8. Versi dataset

Simpan data pada satu titik waktu sebagai snapshot, agar mudah dibandingkan dan dikembalikan.

1. Di halaman **Data**, klik **Kelola → Versi dataset (simpan snapshot, bandingkan, pulihkan)**.
2. Isi **Nama versi** (misalnya v1, tambah gambar malam) dan **Catatan** (opsional), lalu klik **Simpan data saat ini sebagai versi baru**.
   - Versi menyimpan gambar yang sudah dianotasi saat ini (saat kolaborasi tim: yang menunggu tinjauan dan yang disetujui) beserta anotasinya, serta pembagian latih / validasi / uji.
3. Setiap baris di daftar versi bisa:
   - **Bandingkan dengan data saat ini**: melihat gambar yang ditambahkan, dikeluarkan, dan yang anotasinya berubah, serta perubahan jumlah anotasi per kelas;
   - **Ekspor versi ini**;
   - **Pulihkan ke versi ini**: sebelum dipulihkan, data saat ini otomatis disimpan sebagai versi "Cadangan otomatis sebelum pemulihan", jadi Anda selalu bisa kembali;
   - **Ganti nama, catatan**, **Hapus versi ini** (hanya snapshot yang dihapus; data saat ini dan model yang sudah dilatih tidak terpengaruh).
4. Di "Data pelatihan" pada halaman **Pelatihan**, Anda bisa memilih versi tertentu untuk pelatihan (lihat 10.1).

## 9. Kolaborasi tim

Jika gambarnya banyak dan satu orang tidak sanggup menyelesaikannya, ada dua cara:

- **Kolaborasi langsung**: beberapa orang menganotasi proyek yang sama secara bersamaan. Komputer Anda menjadi host; anggota membuka alamat di browser, masuk, lalu bisa langsung menganotasi, dan perubahan tersinkron secara langsung. Bisa lewat LAN maupun internet.
- **Paket offline**: jika tidak ada jaringan, atau data tidak boleh keluar dari kantor, bagi gambar menjadi paket anotasi, salin ke orang lain, lalu gabungkan kembali setelah selesai (lihat 9.10).

### 9.1 Memulai kolaborasi langsung

1. Klik **Kolaborasi** di kiri.
2. Tambahkan anggota dulu di "Anggota": isi **Nama** (untuk masuk), pilih **Peran**; kata sandi dibuat acak secara bawaan (bisa diubah), lalu klik **Tambah**. Salin akun dan kata sandi yang muncul lalu kirimkan kepadanya (hanya ditampilkan sekali; jika lupa, gunakan **Atur ulang kata sandi**).
   - **Anotator**: hanya bisa melihat dan mengubah gambar yang ditugaskan kepadanya;
   - **Peninjau**: bisa melihat semua gambar, bertugas menyetujui atau mengembalikan;
   - Anda sendiri adalah **Admin**.
3. Di "Berbagi", pilih cara berbagi:
   - **LAN**: anggota berada di jaringan kantor atau Wi-Fi yang sama dengan Anda. Paling cepat, dan data tidak keluar dari kantor.
   - **Online · Relay sendiri**: anggota berada di internet luar (outsourcing, kerja dari rumah). Diperlukan server cloud milik Anda sendiri yang dipasangi layanan relay Wulabel (panduan deploy ada di folder `relay/` di repositori); isi **Alamat relay** dan **Kunci rahasia**. Data hanya melewati server Anda sendiri.
   - **Online · Relay resmi Xuntong**: untuk anggota di internet luar ketika Anda tidak punya server sendiri. Menggunakan API Key Xuntong Anda untuk terhubung ke server relay Xuntong. Gambar dan anotasi diteruskan melalui server Xuntong (hanya diteruskan, tidak disimpan); untuk proyek dengan data sensitif, gunakan salah satu dari dua cara sebelumnya.
4. Isi **Nama Anda** (nama host yang dilihat anggota). **Port** biasanya tidak perlu diubah (bawaan 8765).
5. Opsi:
   - **Anggota dapat memakai bantuan AI**: pilih cerdas SAM, pra-anotasi model, dan prompt teks semuanya dihitung di komputer Anda; mengobrol dengan AI tentang aturan pengenalan memakai kuota Xuntong Anda.
   - **Anggota dapat menambah dan mengedit kelas serta catatan pengenalan**: menghapus kelas akan menghapus semua anotasinya, jadi hanya Anda yang bisa melakukannya.
   - **Tampilkan watermark berisi nama anggota di layarnya**: mencegah tangkapan layar disebarkan; cocok untuk outsourcing.
6. Klik **Mulai kolaborasi**. Halaman akan menampilkan **Alamat LAN** (misalnya `http://192.168.1.20:8765/`); mode online juga menampilkan **Alamat internet** (misalnya `https://relay.example.com/s/xxxxxxxxxxxx/`). Kirimkan alamat serta akun dan kata sandi masing-masing kepada anggota.
   - Saat pertama kali dimulai, Windows mungkin menampilkan peringatan firewall; klik **Izinkan**.
   - Selama kolaborasi berjalan, ketiga opsi bisa diubah kapan saja dan langsung berlaku.
   - Klik **Hentikan kolaborasi**: anggota langsung terputus, anotasi yang sudah disimpan tidak terpengaruh. Berganti proyek atau menutup Wulabel juga menghentikan kolaborasi.

### 9.2 Menugaskan pekerjaan

1. Di "Tugaskan pekerjaan", pilih anotator (bisa klik **Pilih semua anotator**).
2. Pilih cakupan:
   - **Gambar belum dianotasi yang belum ditugaskan** (paling sering dipakai);
   - **Semua gambar belum dianotasi** (yang sudah ditugaskan juga dibagi ulang);
   - **Gambar yang belum ditinjau** (belum dianotasi + menunggu tinjauan).
3. **Per orang** N gambar: jika dikosongkan, semua gambar dalam cakupan dibagi rata. Gambar ditugaskan berurutan sesuai urutan, sehingga frame video yang berurutan diberikan ke orang yang sama.
4. Klik **Tugaskan**. Tugas baru otomatis muncul di sisi anggota.
5. Di daftar anggota terlihat berapa gambar yang ditugaskan, dikirim, dan dikembalikan untuk tiap orang. Klik **Tarik kembali tugas** untuk menarik gambar yang belum ia kirim, lalu tugaskan ke orang lain.

### 9.3 Cara anggota menganotasi (browser)

1. Buka alamat dari host dengan Chrome atau Edge, isi **Nama** dan **Kata sandi** untuk masuk. Di komputer sendiri bisa mencentang **Ingat saya**. Tidak perlu memasang aplikasi.
2. Anotator setelah masuk langsung melihat halaman anotasi yang hanya berisi gambar yang ditugaskan kepadanya; peninjau masuk ke halaman Tinjau (lihat 9.4) dan bisa beralih ke **Anotasi** di bagian atas. Cara pakainya sama dengan di Wulabel: menggambar kotak, pintasan, bantuan AI (jika diizinkan host). Di kanan atas tampil jumlah gambar yang dikirim hari ini.
3. Setelah selesai, klik **Kirim & berikutnya** (`Enter`) dan tunggu peninjauan. Jika gambar memang tidak berisi objek, langsung kirim saja; gambar masuk ke Menunggu tinjauan sebagai sampel negatif (proyek klasifikasi harus memilih kelas dulu sebelum bisa mengirim).
4. Gambar yang dikembalikan ada di filter **Dikembalikan**, dengan alasan pengembalian tampil di atas gambar. Perbaiki lalu kirim lagi.
5. Gambar yang sedang dianotasi orang lain akan menampilkan pesan seperti: "Budi" sedang menganotasi gambar ini. Anda hanya bisa melihat, dan perubahannya tampil secara langsung; setelah ia pergi, gambar otomatis bisa diedit.
6. Jika jaringan putus, di kanan atas muncul "Koneksi langsung terputus, menyambung ulang…". Setelah pulih, pekerjaan otomatis berlanjut, dan yang sudah tersimpan tidak hilang.

### 9.4 Peninjauan

Saat kolaborasi tim, status gambar terbagi menjadi: **Belum dianotasi** → setelah dikirim anotator menjadi **Menunggu tinjauan** → setelah disetujui peninjau menjadi **Disetujui**; gambar yang dikembalikan ada di "Dikembalikan". Filter dan label status di halaman Data, Anotasi, dan Cek data memakai nama-nama ini. Saat menganotasi sendiri tidak ada langkah peninjauan; yang tampil hanya "Sudah dianotasi".

Peninjauan punya halaman **Tinjau** tersendiri, yang hanya muncul saat kolaborasi tim (sudah menambahkan anggota atau kolaborasi langsung sedang berjalan):

- Anda (admin): navigasi kiri bertambah satu item **Tinjau**; angka di sebelahnya adalah jumlah gambar yang menunggu tinjauan. Setelah kolaborasi dihentikan dan semua anggota dihapus, item ini otomatis hilang.
- Peninjau (browser): setelah masuk, yang terbuka secara bawaan adalah halaman Tinjau; di bagian atas bisa beralih antara **Tinjau / Anotasi**.
- Anotator tidak melihat halaman Tinjau.

**Filter**

1. **Anggota**: baris paling atas berisi setiap anggota, dengan jumlah gambarnya yang menunggu tinjauan dan tingkat persetujuannya (berapa kali disetujui ÷ berapa kali ditinjau); yang di bawah 80% ditandai kuning. Klik satu orang untuk hanya melihat gambarnya, klik **Semua anggota** untuk melihat gambar semua orang.
2. **Status**: bisa memilih beberapa, secara bawaan hanya **Menunggu tinjauan**. Bisa juga melihat gambar yang disetujui, dikembalikan, belum dianotasi, atau dilewati.
3. **Cari nama file**: ketik sebagian nama file.
4. **Urutan**: menurut waktu kirim (terbaru dulu) atau menurut nama file.
5. **Filter lainnya**: hanya yang berisi kelas tertentu, hanya yang tanpa objek (sampel negatif), hanya yang pernah dikembalikan; di sini juga bisa mengatur ukuran gambar di kisi. **Hapus filter** mengembalikan ke bawaan.

**Tinjauan massal (kisi)**

1. Setiap gambar di kisi sudah digambari kotak, kontur, atau keypoint-nya (proyek klasifikasi menampilkan nama kelas); di bawah gambar ada nama file, anotator, jumlah objek per kelas, dan waktu kirim; gambar yang pernah dikembalikan diberi tanda "Pernah dikembalikan".
2. Klik gambar untuk mencentangnya; tahan `Shift` lalu klik gambar lain untuk ikut memilih semua gambar di antaranya. Bisa juga klik **Pilih semua di halaman ini**, atau **Pilih semua hasil filter** (termasuk halaman-halaman berikutnya, cocok untuk "setujui semua gambar Budi yang menunggu tinjauan").
3. Klik **Setujui**: gambar yang dipilih menjadi "Disetujui".
4. Klik **Kembalikan…**: centang alasan umum (objek terlewat, kotak tidak akurat, salah kelas, anotasi berlebih, keypoint salah), atau tulis dengan jelas apa yang harus diperbaiki. Gambar-gambar ini memakai alasan yang sama, dan masing-masing kembali ke "Dikembalikan" milik anotator aslinya.
5. Gambar yang sedang diubah orang lain dan gambar yang tidak berstatus menunggu tinjauan otomatis dilewati; pesannya menyebutkan berapa yang dilewati.
6. Salah klik: tombol **Urungkan** di pesan berlaku selama 10 detik dan mengembalikan kumpulan gambar ini ke status semula (gambar yang setelah itu diubah orang lain tidak disentuh).
7. Ingin melihat satu gambar lebih jelas: pilih lalu tekan **Spasi** untuk memperbesar, tombol kiri/kanan untuk berpindah gambar, tekan Spasi lagi untuk menutup.

**Tinjauan satu per satu**

1. Klik ganda sebuah gambar, atau klik **Satu per satu**, untuk melihat gambar besar satu per satu; di kanan ada anotator, waktu kirim, pernah dikembalikan atau tidak, serta jumlah objek tiap kelas.
2. Jika tidak ada masalah, klik **Setujui** (`A`) dan otomatis lanjut ke gambar berikutnya; jika ada masalah, klik **Kembalikan** (`R`).
3. Ingin memperbaiki sendiri: klik **Perbaiki sendiri** (`E`); kumpulan gambar ini dibawa ke halaman Anotasi. Setelah selesai, klik **Kembali ke tinjauan** di halaman Anotasi; filter dan posisi tetap seperti semula.
4. Klik **Kembali ke kisi** (`Esc`).

**Tinjauan sampel**

Jika gambar seorang anggota sangat banyak, tidak perlu melihat semuanya:

1. Klik **Tinjau sampel…**, pilih anggota dan proporsinya (sampel 10% / 20% / 50%), lalu klik **Mulai tinjauan sampel**.
2. Aplikasi mengambil acak sejumlah itu dari gambarnya yang menunggu tinjauan, untuk ditinjau satu per satu (caranya sama seperti di atas).
3. Setelah selesai, tingkat lolos ditampilkan. Jika tinggi, klik **Setujui semua N gambar sisanya**; jika rendah, klik **Kembalikan semua N gambar sisanya** dengan alasan "Tidak lolos tinjauan sampel. Periksa kembali pekerjaan Anda lalu kirim ulang". Bisa juga dibiarkan dulu.

Cara lama juga tetap bisa: filter **Menunggu tinjauan** di halaman Anotasi, lihat satu per satu, lalu klik **Setujui & berikutnya** (`Enter`) atau **Kembalikan**.

### 9.5 Progres, beban kerja, dan log

- **Online**: daftar anggota menampilkan siapa yang online dan gambar mana yang sedang dilihat; klik untuk melompat ke sana. Di baris anotator, klik **Lihat gambarnya** untuk langsung membuka halaman Tinjau berisi gambarnya yang menunggu tinjauan. Titik hijau pada "Kolaborasi" di navigasi kiri menandakan kolaborasi sedang berjalan.
- **Progres dan beban kerja**: berdasarkan hari ini / 7 hari terakhir / 30 hari terakhir / semua, menghitung per orang jumlah gambar yang dikirim, jumlah objek yang dianotasi, berapa kali disetujui dan dikembalikan, tingkat persetujuan, jumlah peninjauan, dan durasi kerja (jeda antara dua tindakan yang tidak lebih dari 5 menit dijumlahkan). Klik **Ekspor CSV** dan buka di Excel, praktis untuk membayar outsourcing per gambar.
- **Log aktivitas**: siapa yang masuk, mengirim, meninjau, mengembalikan, mengubah kelas, atau menugaskan pekerjaan, dan kapan. Klik nomor gambar untuk melompat ke sana. Centang **Sertakan setiap simpan otomatis** untuk melihat lebih rinci.

### 9.6 Memilih di antara tiga cara berbagi

| | LAN | Online · Relay sendiri | Online · Relay resmi Xuntong |
|---|---|---|---|
| Cocok untuk | Jaringan kantor yang sama, Wi-Fi yang sama | Outsourcing, kerja dari rumah, punya server cloud sendiri | Outsourcing, kerja dari rumah, tanpa server |
| Alamat yang dibuka anggota | `http://<IP-komputer-Anda>:8765/` | `https://<relay-Anda>/s/<ID>/` | `https://xuntongai.com/wulabel-relay/s/<ID>/` |
| Kecepatan | Paling cepat | Tergantung bandwidth server | Tergantung bandwidth server Xuntong |
| Data melewati | Hanya jaringan internal kantor | Server Anda sendiri (hanya diteruskan, tidak disimpan) | Server Xuntong (hanya diteruskan, tidak disimpan) |
| Yang perlu disiapkan | Tidak ada | Satu server cloud, pasang layanan relay sesuai `relay/README.md` | Akun Xuntong AI (masuk di Pengaturan) |

- Dengan ketiga cara ini, gambar dan anotasi hanya tersimpan di komputer Anda; server relay hanya meneruskan.
- ID berbagi untuk mode online selalu tetap: saat dimulai lagi, alamatnya tetap sama, jadi anggota cukup menyimpannya sekali.
- Komputer Anda harus tetap menyala dan Wulabel harus tetap menjalankan kolaborasi agar anggota bisa terhubung; jika komputer tidur, anggota akan melihat "Host sedang offline". Sebaiknya matikan mode tidur otomatis di pengaturan daya.

|---|---|---|---|
| Gambar yang terlihat | Semua | Semua | Hanya yang ditugaskan kepadanya |
| Menggambar kotak, mengubah anotasi | ✓ | ✓ | ✓ (hanya gambarnya sendiri) |

### 9.8 Contoh lengkap

Contoh: "tim outsourcing menganotasi 2000 gambar pemilahan sampah, dan tim Anda sendiri meninjaunya":

1. **Persiapan**: di Wulabel, buat proyek deteksi, impor 2000 gambar, lalu tambahkan kelas di kanan (sampah daur ulang, sampah organik, sampah B3, sampah lainnya). Anda bisa melakukan pra-anotasi massal dulu dengan model khusus Xuntong AI (lihat 16.4), sehingga anotator cukup memperbaiki kesalahan, jauh lebih cepat.
2. **Tambah anggota**: di halaman "Kolaborasi", tambahkan 3 anotator (Budi, Siti, Andi dari tim outsourcing) dan 1 peninjau (Rina dari tim Anda), lalu kirimkan akun dan kata sandi kepada masing-masing.
3. **Mulai kolaborasi**: pilih "Online · Relay resmi Xuntong" (atau relay sendiri), centang "Watermark", mulai, lalu kirim alamat internet kepada 4 orang tersebut.
4. **Tugaskan**: pilih semua anotator, cakupan "Gambar belum dianotasi yang belum ditugaskan", kosongkan jumlah per orang, klik Tugaskan; tiap orang mendapat sekitar 666 gambar.
5. **Anotasi**: anotator membuka alamat di browser dan masuk, hanya melihat gambarnya sendiri, dan menekan `Enter` untuk mengirim setiap gambar yang selesai.
6. **Tinjau**: Rina membuka halaman Tinjau, mengklik anggota "Budi", lalu memindai sekilas gambarnya yang menunggu tinjauan di kisi. Yang tidak bermasalah dipilih semua lalu klik "Setujui"; yang bermasalah dicentang, klik "Kembalikan", centang "Objek terlewat" dan tulis "masih ada satu botol di kanan bawah". Gambar yang dikembalikan masuk ke "Dikembalikan" milik anotator aslinya, yang memperbaikinya lalu mengirim lagi. Jika gambarnya terlalu banyak, gunakan "Tinjau sampel" untuk mengambil 20%; jika tingkat lolosnya tinggi, setujui sisanya sekaligus.
7. **Pantau progres**: di halaman "Kolaborasi", lihat siapa yang online, siapa yang cepat, dan siapa yang sering dikembalikan; jika seseorang tertinggal, gunakan "Tarik kembali tugas" untuk menarik gambar yang belum ia kerjakan, lalu tugaskan ke orang lain.
8. **Pembayaran**: di "Progres dan beban kerja", pilih rentang waktu, klik "Ekspor CSV", lalu hitung biaya outsourcing berdasarkan jumlah gambar yang dikirim dan tingkat persetujuan.
9. **Penutup**: setelah semuanya disetujui, hentikan kolaborasi, lalu kembali ke Wulabel untuk melatih, mengevaluasi, dan deploy seperti biasa.

### 9.9 Pertanyaan umum

- **Anggota tidak bisa membuka alamat LAN**:
  - Pastikan ia berada di jaringan yang sama dengan Anda (tersambung ke jaringan kantor atau Wi-Fi yang sama; jaringan tamu biasanya tidak bisa);
  - Saat pertama kali dimulai, klik "Izinkan" pada peringatan firewall Windows. Jika terlanjur mengklik "Batal", buka "Windows Security → Firewall & network protection → Allow an app through firewall" dan centang Wulabel;
  - Jika port sudah dipakai, ganti port lain, misalnya 8766.
- **Anggota melihat "Host sedang offline"**: Wulabel Anda tidak menjalankan kolaborasi, komputer sedang tidur, atau jaringan terputus. Setelah dimulai lagi, minta ia memuat ulang halaman.
- **Alamat internet terus menampilkan "Menghubungkan ke server relay…"**:
  - Relay sendiri: periksa apakah alamat dan kunci rahasia sama dengan saat deploy;
  - Relay resmi: pastikan Anda sudah masuk ke akun Xuntong AI.
- **Anggota mendapat pesan "gambar ini tidak ditugaskan kepada Anda"**: anotator hanya bisa membuka gambar yang ditugaskan kepadanya. Minta admin menugaskan gambar itu kepadanya, atau biarkan orang lain yang menganotasinya.
- **Dua orang ingin mengubah gambar yang sama bersamaan**: tidak bisa; orang yang membuka belakangan hanya bisa melihat. Tunggu orang pertama pindah ke gambar berikutnya, baru bisa diubah.
- **Saat menyetujui secara massal muncul pesan bahwa beberapa gambar dilewati**: gambar yang sedang diubah orang lain dan gambar yang sudah tidak menunggu tinjauan tidak ikut diproses secara massal. Tunggu sampai ia selesai dan mengirimnya, baru tinjau.
- **Jika anggota terputus dari jaringan, apakah anotasinya hilang?**: yang sudah tersimpan tidak hilang (setiap perubahan otomatis disimpan ke komputer Anda). Setelah jaringan pulih, halaman otomatis tersambung lagi.
- **Bisakah menganotasi di ponsel?**: bisa dibuka dan dilihat, tetapi untuk menggambar kotak sebaiknya tetap memakai komputer.
- **Maksimal berapa orang?**: tidak ada batas pasti; belasan orang menganotasi bersamaan tidak masalah. Jika orangnya banyak, komputer Anda harus tetap menyala dan jaringannya stabil.
- **Apa yang terjadi jika kolaborasi dihentikan atau Wulabel ditutup?**: anggota langsung terputus dan melihat "Host telah menghentikan kolaborasi"; anotasi yang sudah tersimpan tetap ada. Setelah dimulai lagi, mereka cukup memuat ulang halaman untuk melanjutkan.
- **Berganti proyek**: kolaborasi otomatis berhenti. Kolaborasi berlaku untuk proyek yang sedang dibuka.
### 9.10 Paket offline

Dipakai jika tidak ada jaringan, atau data tidak boleh keluar dari kantor. Setiap paket adalah proyek Wulabel yang berdiri sendiri; salin ke orang lain untuk dianotasi, lalu gabungkan kembali setelah selesai.

**Bagi paket:**

1. Di halaman **Data**, klik **Kelola → Kolaborasi tim (bagi paket, gabungkan kembali)**, lalu beralih ke **Bagi paket**.
2. **Simpan di**: pilih folder tempat paket anotasi dibuat.
3. Isi **Anotator**, satu per baris (atau pisahkan dengan koma), misalnya "Budi" dan "Siti". Jumlah orang menentukan jumlah paket.
4. Pilih cakupan: **Hanya gambar yang belum dianotasi** / **Belum ditinjau** (belum dianotasi + menunggu tinjauan) / **Semua** (kecuali yang dilewati).
5. Centang **Sertakan anotasi yang sudah ada**: gambar yang sudah dipra-anotasi model bisa langsung diperbaiki anotator, lebih cepat.
6. (Opsional) Centang **Anonimkan gambar**, untuk menyamarkan area privat seperti wajah dan pelat nomor sebelum dikirim (lihat 13.2).
7. Klik **Bagi menjadi N paket**. Setelah selesai, folder penyimpanan otomatis terbuka. Salin folder paket ke orang yang bersangkutan; ia cukup memakai **Buka proyek…** di Wulabel untuk mulai menganotasi.

**Gabungkan kembali:**

1. Salin kembali folder paket yang sudah selesai dianotasi.
2. Buka **Kolaborasi tim**, beralih ke **Gabungkan kembali** (atau langsung klik **Gabungkan** pada paket tersebut di daftar "Paket yang dibagikan").
3. Pilih folder paket. Opsi: **Saat konflik, timpa dengan versi paket** (gambar yang juga diubah di proyek asli setelah dibagi; secara bawaan tidak ditimpa), **Impor juga gambar yang ditambahkan anotator ke paket**.
4. Klik **Gabungkan**; progres penggabungan tampil di bawahnya. Hasilnya menampilkan berapa gambar yang digabung, tidak berubah, baru ditambahkan, dan berkonflik. Jika ada konflik, klik **Periksa satu per satu**.

## 10. Pelatihan

### 10.1 Mengatur parameter pelatihan

Di bagian atas halaman tampil jumlah "Gambar yang dapat dilatih" (gambar yang sudah dianotasi; saat kolaborasi tim: menunggu tinjauan + disetujui). Gambar yang belum dibagi akan otomatis dibagi 8:2 ke set latih dan set validasi saat pelatihan dimulai; gambar yang sudah dibagi tidak berubah sendiri, sehingga beberapa kali pelatihan bisa langsung dibandingkan.

Klik **Lihat dan atur** di samping "Gambar yang dapat dilatih" untuk melihat setiap gambar masuk ke set mana:

- **Set pelatihan**: model belajar dari gambar-gambar ini;
- **Set validasi**: tidak dipakai untuk belajar; setiap selesai satu epoch, model dievaluasi dengan set ini, dan epoch dengan hasil terbaik yang disimpan;

Di dialog, klik gambar untuk memilihnya (klik dua kali untuk membukanya di anotasi), lalu klik **Pindahkan ke set pelatihan / Pindahkan ke set validasi / Pindahkan ke set uji** untuk mengatur secara manual. Di bawahnya Anda bisa mengubah rasio pelatihan / validasi / uji, lalu klik **Bagi sekarang N gambar yang belum dibagi**, atau **Bagi ulang semua** (pembagian sebelumnya diacak ulang, sehingga pelatihan sebelum dan sesudahnya tidak bisa langsung dibandingkan). ### 10.2 Model YOLOX

YOLOX adalah model deteksi seri YOLO yang dirilis open source oleh Megvii (Apache-2.0, aman untuk penggunaan komersial), satu seri dengan model khusus di platform Xuntong AI.

- **Bobot pralatih**: pada pelatihan pertama, bobot pralatih COCO resmi diunduh otomatis (Nano sekitar 8 MB, S sekitar 70 MB, L sekitar 430 MB), pertama dari situs resmi, dan jika gagal dari GitHub. Setelah sekali diunduh, tidak perlu mengunduh lagi.
- **Augmentasi data**: mengikuti cara resmi YOLOX. Mosaic, MixUp, skala dan rotasi acak, perubahan warna, flip horizontal, dan pelatihan multiskala semuanya aktif otomatis, dan sekitar 10% epoch terakhir mematikan augmentasi kuat untuk penyelesaian. Karena itu, saat memilih YOLOX, pengaturan "Augmentasi data" di bawah tidak ditampilkan.
- **Jumlah epoch**: YOLOX membutuhkan lebih banyak epoch daripada Faster R-CNN; disarankan 50 epoch ke atas, dan sekitar 100 epoch jika datanya sedikit (beberapa ratus gambar).
- **Learning rate**: otomatis disesuaikan dengan ukuran batch; tidak perlu diatur.
- **Ukuran input**: Nano dan Tiny bawaannya 416, S, M, L bawaannya 640. Bisa diubah, dan akan dibulatkan ke kelipatan 32.
- **YOLOX atau YOLOv8 / 11**: keduanya bisa dilatih. YOLOX berlisensi Apache-2.0, sama seperti Wulabel; model hasil pelatihannya boleh dipakai di produk apa pun dan juga bisa diunggah ke Xuntong. YOLOv8 / 11 dan model Ultralytics lain berlisensi AGPL-3.0: untuk dipakai sendiri atau di internal perusahaan tidak ada batasan, tetapi untuk dimasukkan ke produk sumber tertutup yang dijual, Anda perlu membeli lisensi dari Ultralytics; lihat 10.7.

Model YOLOX yang sudah dilatih dipakai sama seperti model lain: evaluasi, pra-anotasi model, uji positif palsu, uji langsung, ekspor untuk deploy, dan unggah ke Xuntong semuanya didukung.

### 10.3 Augmentasi data

Mengubah gambar secara acak selama pelatihan agar model melihat lebih banyak variasi; efeknya terasa saat data sedikit.

1. Di "Augmentasi data", pilih preset: **Mati**, **Bawaan**, **Ringan**, **Standar**, **Kuat (untuk data sedikit)**.
2. Untuk penyesuaian detail, buka bagian ini dan ubah **Flip horizontal**, **Flip vertikal**, **Kecerahan**, **Kontras**, **Saturasi**, **Hue**, **Buram** (mensimulasikan fokus meleset dan blur gerak), **Noise** (mensimulasikan cahaya rendah di malam hari), **Multiskala** (membantu untuk objek yang ukurannya sangat bervariasi karena jarak), **Rotasi**, **Potong acak**. Setelah diubah, preset tampil sebagai "Kustom".
3. Klik **Pratinjau efek** untuk melihat beberapa gambar setelah augmentasi acak (tiap gambar diubah acak dua kali; kotak merah menunjukkan posisi anotasi setelah transformasi), dan pastikan hasilnya tidak berlebihan.

### 10.4 Memulai pelatihan, memantau proses

1. Sebelum mulai, lihat "~N langkah per epoch · total ~M" di atas tombol. Jika gambarnya terlalu sedikit (set pelatihan kurang dari 20 gambar) atau total langkahnya terlalu sedikit (kurang dari sekitar 300), mengklik **Mulai pelatihan** akan memunculkan peringatan lebih dulu: pelatihan seperti ini kemungkinan besar tidak mempelajari apa-apa, dan metriknya bisa tetap 0. Sebaiknya anotasi lebih banyak gambar, atau naikkan jumlah epoch sesuai saran; jika datanya sangat sedikit, Anda juga bisa mulai dengan Faster R-CNN MobileNetV3. Jika memang hanya ingin mencoba, klik **Tetap mulai**. Peringatan juga muncul jika set validasi hanya berisi satu atau dua gambar: metrik akan sangat fluktuatif dan tidak bisa dipercaya. Jika ada kelas yang terlalu sedikit anotasinya (kurang dari 20 gambar untuk klasifikasi, atau kurang dari 30 kotak untuk tugas lain), kelas tersebut ditampilkan di atas tombol dan Anda akan diingatkan sebelum mulai: model sulit mempelajarinya dan mudah melewatkannya. Jika tetap kurang, hapus kelas ini di halaman Anotasi sambil menggabungkan anotasinya ke kelas yang mirip. Gambar beranotasi yang hanya berisi pra-anotasi yang belum diubah juga ditandai di atas tombol; klik **Lihat** untuk melihat gambar-gambar itu saja. Jika jumlahnya 30% atau lebih, Anda akan diingatkan sebelum mulai: jika dikonfirmasi tanpa dicek teliti, model ikut mempelajari kesalahannya sendiri dan makin melenceng setiap dilatih. Setelah diperiksa, klik **Sudah dicek** agar pengingat tidak muncul lagi.
2. Klik **Mulai pelatihan**. Data pelatihan disiapkan dulu (jika gambarnya banyak, di bawah tombol tampil "Menyiapkan data pelatihan N/M"). Saat pertama kali memakai suatu model, bobot pralatihnya akan diunduh: halaman Pelatihan menampilkan "Mengunduh bobot pralatih nama file: terunduh / total MB · kecepatan", dan di kanan bawah juga ada bilah progres. Jika jaringan terputus, unduhan dilanjutkan, dan setelah sekali terunduh tidak perlu diunduh lagi.
3. Selama pelatihan tampil "Epoch N / M · progres epoch ini · loss · perkiraan sisa waktu", dan di bawahnya ada kurva **Loss**, kurva metrik **Set validasi**, dan **Log**.
   - "Info penting" di atas log selalu menampilkan beberapa baris pertama log: perangkat yang dipakai, jumlah gambar set pelatihan dan set validasi, serta apakah bobot pralatih berhasil dimuat. Baris kesalahan dan peringatan ditandai kuning.
   - Saat menggulir log ke atas, tampilan tidak akan ditarik kembali ke bawah; saat berada di paling bawah, log ikut bergulir.
   - Jika bobot pralatih gagal diunduh (biasanya masalah jaringan), atau metrik bernilai 0 selama 10 epoch berturut-turut, bilah peringatan kuning muncul di bagian atas halaman, berisi kemungkinan penyebab dan langkah yang harus diambil.
4. Untuk berhenti lebih awal, klik **Hentikan** lalu konfirmasi; pelatihan berhenti setelah batch saat ini selesai. Epoch yang sudah selesai dan model terbaik sejauh ini tetap disimpan.
   - Jika Anda menutup aplikasi saat pelatihan masih berjalan, akan muncul konfirmasi "Pelatihan belum selesai. Menutup aplikasi akan menghentikan pelatihan" agar tidak tertutup tanpa sengaja.
5. **Lanjutkan dari titik simpan**: setelah pelatihan dihentikan, aplikasi ditutup, atau terhenti karena error, entri tersebut akan menampilkan tombol **Lanjutkan pelatihan**. Klik tombol itu untuk melanjutkan di entri yang sama, mulai dari epoch terakhir yang selesai hingga sisa epoch; grafik dan log bersambung dari sebelumnya, tanpa perlu mengulang dari awal. Setelah pelatihan selesai dengan normal, titik simpan otomatis dihapus (titik simpan model besar bisa beberapa ratus MB).
   - Ini berbeda dengan opsi "Lanjutkan pelatihan dari …" di Titik awal: opsi itu memakai model hasil suatu pelatihan sebagai titik awal untuk pelatihan baru, cocok untuk melatih ulang setelah menambah data baru.
6. Saat pelatihan selesai, muncul notifikasi sistem dan ikon di taskbar berkedip (Anda tetap tahu meski aplikasi di latar belakang); di dalam aplikasi, kanan bawah menampilkan "Pelatihan selesai" beserta metrik terbaik dan penilaiannya (kurang / cukup / layak):
   - jika hasilnya bagus, Anda bisa langsung klik **Evaluasi** atau **Pra-anotasi**;
   - jika hasilnya sangat buruk, Anda akan diarahkan untuk klik **Lihat penyebab** dan kembali ke halaman Pelatihan untuk memeriksanya;
   - jika pelatihan gagal, pesan tetap muncul meski Anda tidak sedang di halaman Pelatihan; klik **Lihat kesalahan** untuk melihatnya.
7. Saat pelatihan error, kesalahan umum dijelaskan dengan bahasa sederhana dan disertai tombol perbaikan: driver GPU tidak cocok dengan PyTorch (**Ganti versi PyTorch di Pengaturan**), memori GPU atau RAM tidak cukup (**Pakai CPU**), disk penuh, unduhan jaringan gagal, atau file gambar tidak ditemukan (**Ke halaman Data**). Klik **Detail** untuk membuka pesan kesalahan lengkap.

### 10.5 Riwayat pelatihan dan perbandingan pelatihan

Setiap pelatihan otomatis disimpan sebagai satu entri **Riwayat pelatihan**, berisi waktu, model, data, jumlah epoch, metrik, dan status (Sedang dilatih / Selesai / Dihentikan / Gagal). Setiap entri bisa:

- **Lihat evaluasi** (membuka evaluasi untuk pelatihan yang satu ini), **Ekspor ONNX** (hanya untuk model bawaan, progres ditampilkan saat mengekspor; model Ultralytics dan model eksternal sudah berupa ONNX), **Buka folder pelatihan**, hapus. Entri yang masih dalam pelatihan baru bisa dievaluasi dan di-deploy setelah selesai.
- Entri yang dihentikan, terputus, atau gagal memiliki tombol **Lanjutkan pelatihan** (lihat 10.4).

**Hapus massal**: centang beberapa entri di riwayat pelatihan, klik **Hapus yang dipilih (N)**, lalu konfirmasi untuk menghapus semuanya sekaligus (file model, log, dan salinan dataset yang dipakai pelatihan itu ikut dihapus dan tidak bisa dipulihkan). Entri yang masih dalam pelatihan tidak bisa dipilih.

**Bandingkan pelatihan**:

1. Di riwayat pelatihan, **centang dua pelatihan atau lebih** (maksimal 8 sekaligus).
2. Klik **Bandingkan yang dipilih (N)**.
3. Di jendela perbandingan: parameter dan data berdampingan (yang berbeda dicetak tebal), setiap metrik, dan kurva loss yang ditumpuk; hasil per kelas menandai pelatihan terbaik.

### 10.6 Impor model eksternal

Model yang dilatih di tempat lain (misalnya Ultralytics YOLO) bisa diekspor ke ONNX lalu diimpor, dan dipakai seperti model hasil pelatihan di sini: pra-anotasi, cek data, evaluasi, uji positif palsu, uji langsung, dan deploy (ekspor, paket layanan inferensi). Proyek deteksi, segmentasi, keypoint, dan klasifikasi didukung (mulai v0.6.5; sebelumnya hanya deteksi dan tidak bisa di-deploy), dan tugas model harus sama dengan proyek. Pelatihannya tidak bisa dilanjutkan (untuk itu, pilih .pt lewat "File model lokal" di 10.7).

1. Di atas riwayat pelatihan, klik **Impor model eksternal**.
2. Klik **Pilih file .onnx**.
3. Aplikasi otomatis mengenali:
   - **Tugas** dan **Format**: YOLOv8 / v11 (Ultralytics, termasuk segmentasi, keypoint, dan klasifikasi), YOLOv5 / v7, model end-to-end seperti YOLOv10, YOLOX, RT-DETR, DETR / RF-DETR, dan model yang diekspor Wulabel. Jika format salah dikenali, bisa diubah manual;
   - **Ukuran input**;
   - **Nama kelas** (satu per baris, urutannya harus sama dengan model). Ganti nama kelas bahasa Inggris menjadi nama kelas di proyek agar cocok, misalnya ubah person menjadi "orang".
4. **Kelas yang dipakai**: kelas yang tidak dicentang tidak akan ditambahkan saat pra-anotasi; kelas yang namanya sama dengan kelas proyek dicentang secara bawaan.
5. Klik **Impor**. Riwayat pelatihan akan bertambah satu entri "… (eksternal)".

### 10.7 Melatih dengan YOLOv8 / YOLO11 dan model Ultralytics lain

Mulai v0.6.5, selain model bawaan, Anda juga bisa melatih model Ultralytics langsung di Wulabel tanpa keluar dari aplikasi.

**Model yang bisa dipilih**

- Daftar dropdown model disusun per seri: YOLO11, YOLO26, YOLOv8 (deteksi, segmentasi, keypoint, dan klasifikasi, masing-masing lima ukuran N / S / M / L / X), YOLO12, YOLOv10, YOLOv5u, RT-DETR (deteksi), YOLOv9 (deteksi; ukuran C dan E juga punya versi segmentasi). Di proyek segmentasi, namanya langsung tampil seperti "YOLO11-S segmentasi", dan hanya model yang bisa dipakai untuk tugas itu yang ditampilkan.
- **Masukkan nama model…**: untuk model yang tidak ada di daftar, nama apa saja yang dikenali Ultralytics bisa dipakai, misalnya `yolo11x-seg.pt`, `yolo12m.pt`; bisa juga menulis nama file struktur untuk melatih dari awal, misalnya `yolo11s.yaml`. Nama yang mengandung -seg, -pose, -cls masing-masing adalah model segmentasi, keypoint, dan klasifikasi.
- **File model lokal…**: pilih `.pt` yang pernah Anda latih untuk melanjutkan pelatihan (pelatihan penguatan), atau file struktur `.yaml` untuk melatih dari awal. Jika tugasnya tidak cocok (misalnya model deteksi dipakai di proyek segmentasi), akan muncul peringatan setelah pelatihan dimulai.
- Tidak bisa dipakai di proyek klasifikasi multi-label (model klasifikasi Ultralytics hanya mendukung satu label).

**Pemakaian pertama**

Saat Anda mengklik **Mulai pelatihan**, aplikasi lebih dulu menginstal komponen Ultralytics secara otomatis (progres "Menginstal komponen" tampil di kanan bawah, hanya sekali), lalu mengunduh bobot pralatih resmi (progres juga di kanan bawah; setelah sekali diunduh tidak perlu mengunduh lagi). Jika tidak bisa mengunduh, unduh sendiri file bobotnya ke komputer, lalu pilih lewat "File model lokal".

**Parameter**

- Jumlah epoch: untuk model Ultralytics disarankan sekitar 100; saat beralih dari model bawaan dan jumlah epoch kurang dari 50, nilainya otomatis diubah menjadi 100.
- Ukuran batch: bisa diisi 0 agar dipilih otomatis sesuai memori GPU. Jika memori GPU tidak cukup, sama seperti model bawaan: ukuran batch otomatis dibagi dua dan pelatihan diulang dari awal.
- Augmentasi data: memakai augmentasi milik Ultralytics sendiri (Mosaic, skala dan geser acak, variasi warna, flip horizontal, dll.); pengaturan "Augmentasi data" bawaan tidak ditampilkan.
- **Parameter lain** (di "Pengaturan lanjutan"): satu `key=value` per baris, diteruskan apa adanya ke pelatihan Ultralytics, misalnya `cos_lr=True`, `patience=30`, `optimizer=AdamW`, `mosaic=0.5`. "Penjelasan parameter" di sebelahnya membuka dokumentasi resmi. Lokasi data dan lokasi output diatur oleh aplikasi; jika ditulis pun tidak berpengaruh.

**Selama dan setelah pelatihan**

- Progres, kurva loss dan metrik, log, menghentikan, dan melanjutkan dari titik simpan sama seperti model bawaan.
- Setelah selesai, model otomatis diekspor ke ONNX, lalu evaluasi milik Wulabel sendiri dijalankan pada set validasi dan set uji. Jadi metrik, contoh kesalahan, dan ambang yang disarankan memakai algoritma yang sama dengan model bawaan dan bisa dibandingkan berdampingan. Metrik model segmentasi dan keypoint juga dihitung berdasarkan kotak, sama seperti model bawaan.
- Setelah itu, pra-anotasi, cek data, pengenalan massal, uji positif palsu, uji langsung, ekspor (ONNX, OpenVINO, paket konversi TensorRT / RKNN), dan paket layanan inferensi bisa langsung dipakai.
- Titik awal bisa diisi "Lanjutkan pelatihan dari …": daftarnya berisi pelatihan Ultralytics sebelumnya di proyek ini; jika kelas berubah, lapisan output diganti otomatis.
- Untuk sementara belum bisa diunggah ke platform Xuntong (saat ini Xuntong hanya mendukung model deteksi yang dilatih dengan model bawaan).

**Lisensi**

Model Ultralytics berlisensi AGPL-3.0: untuk dipakai sendiri atau di internal perusahaan tidak ada batasan; untuk memasukkan model hasil pelatihan ke **produk sumber tertutup yang dijual**, Ultralytics mewajibkan pembelian lisensi perusahaan. Wulabel tidak berisi kode Ultralytics; kode itu baru diinstal dari PyPI saat Anda memilih model tersebut, dan Wulabel sendiri tetap Apache-2.0. Jika perlu penggunaan komersial tanpa kekhawatiran sama sekali, pilih model bawaan (YOLOX, dll.).

## 11. Evaluasi

Klik **Evaluasi** di kiri, lalu pilih satu entri riwayat pelatihan (jika masuk dari "Lihat evaluasi" di halaman Pelatihan, entri itu sudah terpilih). Entri yang masih dalam pelatihan menampilkan "Sedang dilatih" dan baru bisa dipilih setelah selesai.

### 11.1 Melihat metrik

- Bagian atas menjelaskan model terbaik dari epoch mana yang dipakai untuk evaluasi ini; Anda bisa beralih antara **Set validasi** dan **Set uji**.
- Baris paling atas adalah **Kesimpulan**: penilaian "kurang / cukup / layak" berdasarkan metrik utama (jenis deteksi memakai mAP50: di bawah 0.3 kurang, 0.3~0.6 cukup, di atas 0.6 layak; klasifikasi memakai akurasi: di bawah 0.6 kurang, 0.6~0.85 cukup, di atas 0.85 layak), sekaligus menunjukkan **kelas terlemah**. Di sampingnya ada tombol langkah berikutnya: lihat contoh deteksi terlewat, kirim contoh kesalahan ke anotasi, tambah data lalu latih ulang / ganti ke model yang lebih besar; jika hasilnya layak, ada **Ke deploy**. Jika gambar yang dievaluasi kurang dari 10, akan muncul peringatan bahwa metrik sangat fluktuatif.
- Proyek deteksi, segmentasi, dan keypoint: **mAP50** (metrik deteksi yang paling umum), **mAP50-95** (menuntut kotak yang lebih akurat), **Presisi** (proporsi kotak yang dilaporkan yang benar; jika rendah, berarti banyak positif palsu), **Recall** (proporsi objek sebenarnya yang ditemukan; jika rendah, berarti banyak deteksi terlewat). Segmentasi dan keypoint dihitung berdasarkan kotak objek.
- Proyek klasifikasi: **Akurasi**, **F1 makro**, presisi rata-rata, recall rata-rata.
- Arahkan mouse ke metrik untuk melihat penjelasannya.
- Tabel **Per kelas**: jumlah gambar, jumlah kotak sebenarnya, dan setiap metrik untuk tiap kelas.

### 11.2 Matriks konfusi

Baris adalah kelas sebenarnya, kolom adalah prediksi model. Diagonal adalah yang benar; sel lain berarti satu kelas salah diprediksi sebagai kelas lain. Kolom terakhir "Latar belakang" adalah deteksi terlewat, baris terakhir "Latar belakang" adalah positif palsu. Arahkan mouse untuk melihat angka pastinya.

### 11.3 Contoh kesalahan

- Menampilkan gambar yang bermasalah; bisa difilter berdasarkan **Terlewat**, **Positif palsu**, **Salah kelas**.
- **Klik satu contoh kesalahan** untuk langsung pindah ke halaman Anotasi dan memeriksa serta memperbaikinya. Setelah diperbaiki, latih lagi; begitulah siklusnya tertutup.

### 11.4 Ambang keyakinan

Ambang berapa yang dipakai untuk alarm saat deploy? Lihat di sini:

1. Aplikasi menyarankan ambang dengan F1 tertinggi, dan menampilkan presisi serta recall pada ambang tersebut.
2. Kurva menampilkan perubahan presisi, recall, dan F1 terhadap ambang. **Seret slider** untuk melihat efek ambang yang berbeda: berapa yang benar, berapa positif palsu, berapa yang terlewat.
3. Cara memilih: jika banyak positif palsu, naikkan ambang; jika banyak yang terlewat, turunkan.
4. Tabel di bawah adalah **ambang yang disarankan per kelas**.
5. Ambang yang disarankan otomatis dibawa ke uji langsung dan paket layanan inferensi di halaman "Deploy" sebagai ambang keyakinan bawaan.

### 11.5 Evaluasi dengan data saat ini

Setelah menambah data atau memperbaiki anotasi, Anda tidak perlu melatih ulang: klik **Evaluasi dengan data saat ini** untuk menghitung ulang metrik dengan data beranotasi saat ini (set validasi / set uji); layar menampilkan "Mengevaluasi set validasi: N/M gambar". Model eksternal yang diimpor juga dievaluasi dengan cara ini.

### 11.6 Uji positif palsu

Gunakan video yang **seharusnya tidak memicu alarm** (tanpa objek, atau hanya berisi hal yang mudah salah dikenali, misalnya lorong kosong atau area pabrik di malam hari) untuk menguji berapa kali model memberi positif palsu:

1. Di "Uji positif palsu", klik **Pilih file video**, atau isi alamat `rtsp://` / `http(s)://`.
2. Pengaturan: **Deteksi** N frame per detik, N deteksi **berturut-turut** dihitung sebagai satu alarm, **durasi uji** N menit (untuk stream video).
3. Klik **Mulai uji**; Anda bisa klik **Akhiri lebih awal** kapan saja.
4. Hasil: berapa lama diuji, berapa kali alarm, berapa kali **Setara per jam**, dengan statistik per kelas; di bawahnya ada **frame positif palsu** (kotak merah adalah yang dilaporkan model; hanya 60 terbaru yang disimpan).
5. Klik **Tambahkan frame ini ke dataset sebagai sampel negatif**: frame ditambahkan sebagai gambar "Tanpa objek", sehingga pada pelatihan berikutnya model belajar untuk tidak memicu alarm pada adegan seperti ini. Jika ternyata ada objek sungguhan di antaranya, lengkapi anotasinya di halaman Anotasi setelah ditambahkan.

### 11.7 Ekspor laporan serah terima

1. Klik **Ekspor laporan** dan pilih lokasi penyimpanan (nama file bawaan `<nama proyek>_<nama pelatihan>_laporan_model.html`).
2. Laporan berupa satu file HTML yang berisi kondisi data, parameter pelatihan, metrik, kurva, matriks konfusi, contoh kesalahan, ambang yang disarankan, dan hasil uji positif palsu. Langsung dibuka di browser, dan bisa dikirim ke klien untuk penerimaan proyek.

## 13. Ekspor dataset (termasuk anonimisasi)

### 13.1 Ekspor

1. Di halaman **Data**, klik **Ekspor dataset**.
2. **Format** (sesuai tugas proyek):

   - Segmentasi: YOLO-seg, COCO, VOC (hanya kotak pembatas);

3. **Cakupan**: gambar yang belum dianotasi dan yang dilewati tidak diekspor; gambar yang ditandai "Tanpa objek" diekspor sebagai sampel negatif. Saat kolaborasi tim, Anda juga bisa mencentang **Ekspor hanya gambar yang disetujui**.
4. **Rasio latih / validasi / uji (%)**: gambar yang belum dibagi akan dibagi dengan rasio ini. Untuk membagi ulang semuanya, klik **Bagi ulang semua** (hasil pelatihan sebelumnya tidak bisa langsung dibandingkan dengan pembagian baru).

Untuk mengekspor salah satu versi dataset: di daftar versi dataset, klik **Ekspor versi ini**; pembagiannya tetap mengikuti pembagian di versi tersebut.

### 13.2 Anonimisasi

Saat mengekspor dataset, mengekspor versi, atau membagi paket, Anda bisa mencentang **Anonimkan gambar**:

1. **Per kelas**: pilih kelas yang akan dianonimkan di daftar pilihan, misalnya kelas "wajah" atau "pelat nomor" yang Anda anotasi. Kelas yang namanya mengandung "wajah" atau "pelat nomor" dipilih secara bawaan.
2. **Deteksi otomatis**: centang **Deteksi wajah otomatis** dan **Deteksi pelat nomor otomatis**; aplikasi menemukannya dengan model deteksi kosakata terbuka (pertama kali perlu mengunduh model; dengan GPU jauh lebih cepat).
3. **Cara**: **Mosaik**, **Buram**, **Hitamkan**.
4. Saat ekspor, progres akan bertambah satu tahap "Anonimkan".

Anonimisasi hanya mengubah salinan yang diekspor; gambar asli di proyek tidak diubah. Deteksi otomatis bisa melewatkan objek yang sangat kecil, wajah dari samping, atau yang jauh; untuk data penting, periksa beberapa sampel.

## 14. Deploy

Klik **Deploy** di kiri dan pilih model yang sudah dilatih. Halaman ini punya lima tab: **Uji langsung**, **Pengenalan massal**, **Ekspor model**, **Paket layanan inferensi**, **Data balik dari lapangan**.

### 14.1 Uji langsung

Hubungkan kamera atau video untuk melihat hasil model secara nyata:

1. Pilih **Stream video** atau **Video lokal**.
2. Isi alamat stream: kamera RTSP (misalnya `rtsp://admin:<sandi>@192.168.1.64:554/Streaming/Channels/101`), atau alamat HTTP-FLV, HLS (m3u8), atau MP4 lewat http. Bisa juga klik **Pilih file video**.
3. Klik **Mulai**. Saat memulai, berturut-turut tampil "Menyiapkan lingkungan runtime…", "Memuat model…", "Menghubungkan ke sumber video…"; setelah gambar muncul, hasil digambar secara real-time di atas video: kotak untuk model deteksi, kontur untuk model segmentasi, titik dan kerangka untuk model keypoint, dan kelas dengan probabilitas tertinggi di pojok kiri atas untuk model klasifikasi. Bagian atas menampilkan resolusi serta apakah inferensi berjalan di GPU atau CPU.
4. Seret slider **Keyakinan** untuk mengatur ambang. Bawaannya memakai ambang yang disarankan dari halaman Evaluasi; setelah diubah, klik "Pakai nilai disarankan 0.xx" untuk mengembalikannya.
5. Jika melihat frame dengan deteksi terlewat atau positif palsu, klik **Tambahkan tangkapan ke dataset**. Gambar ditambahkan sebagai "Belum dianotasi"; anotasi lalu latih ulang.
6. Klik **Hentikan** untuk selesai.

### 14.2 Ekspor model

1. Pilih format:
   - **ONNX (ukuran dinamis)**: format serbaguna; berjalan dengan onnxruntime di Windows / Linux / ARM;
   - **ONNX (ukuran tetap)**: input tetap [1,3,N,N], untuk framework inferensi yang membutuhkan bentuk tetap;
   - **OpenVINO**: akselerasi untuk CPU Intel, GPU terintegrasi, dan PC industri; dikonversi dan diverifikasi langsung di aplikasi (pemakaian pertama otomatis menginstal OpenVINO; jika gagal dipasang, hanya format ini yang dilewati dan format lain tetap diekspor seperti biasa);
   - **Paket konversi TensorRT**: GPU NVIDIA, Jetson; skrip harus dijalankan di perangkat target untuk membuat engine;
   - **Paket konversi RKNN**: Rockchip RK3588 / 3568, dll.; skrip harus dijalankan di Ubuntu untuk konversi.
2. Jika butuh ukuran tetap, atur ukurannya.
3. Pilih lokasi **Ekspor ke** dan **Nama folder**, lalu klik **Ekspor**. Secara bawaan hanya ONNX yang dicentang. Selama ekspor tampil "Langkah N / M" dan format yang sedang diproses; setelah selesai, setiap format menampilkan berhasil atau gagal; klik **Buka** untuk melihat.

Faster R-CNN bawaan adalah model dua tahap; dukungan NPU (RKNN) dan TensorRT versi lama terhadapnya terbatas, sehingga konversi bisa gagal atau kecepatannya kurang memuaskan. Untuk perangkat seperti ini, sebaiknya latih YOLOX atau model satu tahap lain (RetinaNet, FCOS, SSDLite). ONNX dan OpenVINO aman digunakan.

Saat mengekspor model YOLOX: ONNX (ukuran dinamis) dan OpenVINO sama seperti model lain; scaling, decoding, dan penghapusan kotak duplikat (NMS) sudah ada di dalam model, jadi hasilnya langsung keluar. ONNX (ukuran tetap), paket konversi TensorRT, dan RKNN memakai format resmi YOLOX (input BGR 0~255, padding 114 di kiri atas, output tanpa NMS). Semua operatornya konvolusi biasa, sehingga NPU dan TensorRT bisa menjalankannya sepenuhnya; pascapemrosesan dijelaskan di README dalam paket konversi.

Model segmentasi dan keypoint (Mask R-CNN, Keypoint R-CNN) juga bisa diekspor ke ONNX, OpenVINO, dan format lain: model segmentasi punya output tambahan `masks` (probabilitas mask tiap objek; nilai di atas 0.5 adalah objek), model keypoint punya tambahan `keypoints` (x, y, dan visibilitas tiap titik) serta `keypoints_scores`. Uji langsung dan paket layanan inferensi mendukung model deteksi, segmentasi, keypoint, dan klasifikasi.

### 14.3 Paket layanan inferensi

Membuat layanan inferensi yang langsung berjalan begitu disalin ke komputer di lapangan. Mendukung model deteksi, segmentasi, keypoint, dan klasifikasi:

1. **Stream video**: isi nama dan alamat; klik **Tambah stream** untuk menambah beberapa stream. Alamatnya bisa berupa:
   - kamera RTSP: `rtsp://…`;
   - FLV / m3u8 / MP4 lewat http(s): `http(s)://…`;
   - file video lokal: isi sampai ke file-nya sendiri, misalnya `D:\test\video1.mp4`, jangan hanya foldernya. Video lokal diputar berulang dengan kecepatan aslinya, dan satu video memakai satu stream.
2. **Interval deteksi (dtk)**: seberapa sering satu frame dideteksi dari tiap stream video.
3. **Aturan alarm**:
   - **Kelas alarm** (jika tidak dipilih, semua kelas memicu alarm);
   - **Ambang keyakinan** (bawaannya memakai ambang yang disarankan di halaman Evaluasi);
   - **Interval deduplikasi (dtk)**: untuk stream dan kelas yang sama, alarm hanya dipicu sekali dalam rentang waktu ini;
   - **Jam aktif**: sepanjang hari, atau misalnya `07:00-19:00`;
   - **Simpan tangkapan alarm (dengan kotak)**.
4. **Pengiriman alarm**:
   - Webhook: saat alarm, JSON dikirim dengan POST ke alamat ini; opsional **Sertakan tangkapan (base64)**;
   - MQTT: alamat server, topik, nama pengguna, kata sandi (jika tidak diisi, tidak dikirim).
5. **Layanan**: **Port API HTTP**; **Inferensi dengan GPU** (komputer di lapangan harus memasang onnxruntime-gpu; jika tidak, otomatis memakai CPU).
6. **Data balik dari lapangan**: frame yang membuat model ragu (keyakinan dalam rentang yang diatur) disimpan ke folder `reflux/` di paket layanan.
7. Pilih lokasi **Hasilkan ke**, lalu klik **Buat paket layanan inferensi**; selama pembuatan tampil "Langkah N / M".
8. Salin seluruh folder ke komputer di lapangan: di Windows klik dua kali `run.bat`, di Linux jalankan `sh run.sh`. Konfigurasi ada di `config.json`, penjelasan di `README.md`. Komputer di lapangan tidak memerlukan PyTorch maupun GPU; hanya bergantung pada onnxruntime, OpenCV, dan numpy. Saat pertama dijalankan, perlu Python 3.9 ke atas dan koneksi internet untuk memasang dependensi tersebut; jika pemasangan gagal di tengah jalan, dependensi akan dipasang ulang otomatis saat dijalankan berikutnya.

### 14.4 Data balik dari lapangan

1. Saat paket layanan berjalan di lapangan, frame yang membuat model ragu disimpan ke folder `reflux/`.
2. Salin `reflux/` kembali secara berkala, lalu di tab **Data balik dari lapangan** klik **Impor gambar dari lapangan** dan pilih folder tersebut. Progres ditampilkan selama impor, dan bisa dihentikan.
3. Klik **Anotasi batch ini** untuk mengirim hanya batch yang baru diimpor ke halaman Anotasi, lakukan pra-anotasi dengan model, lalu perbaiki.
4. Latih ulang, buat paket layanan baru, dan ganti `model.onnx` di lapangan. Model akan makin akurat seiring pemakaian.

### 14.5 Unggah ke platform Xuntong AI

Jika tidak ingin men-deploy layanan sendiri, unggah model ke platform Xuntong AI, lalu hubungkan kamera dan atur alarm di platform (saat ini mendukung model deteksi objek):

1. Atur Xuntong AI dulu di **Pengaturan** (lihat 2.3).
2. Di bagian paling bawah **Deploy → Ekspor model**, pada "Unggah ke platform Xuntong AI", sesuaikan **Nama model**, lalu klik **Unggah**. Jika ONNX belum diekspor, akan diekspor otomatis lebih dulu.
3. Setelah diunggah, platform memvalidasi selama beberapa detik hingga satu menit dan menampilkan bahwa platform sedang memvalidasi; setelah lolos, status menjadi "Lolos validasi" (jika gagal, alasannya ditampilkan). Ambang yang disarankan dari halaman Evaluasi ikut diunggah sebagai ambang bawaan di platform.
4. Klik **Buka konsol**, lalu di "Model kustom" klik **Aktifkan**; setelah itu Anda bisa menghubungkan kamera dan mengatur alarm.
5. Di bawahnya, "Model kustom di platform" menampilkan model yang sudah diunggah, status validasi, dan apakah sudah diaktifkan. Akun tanpa layanan hosting hanya bisa menyimpan 1 model; untuk mengunggah versi baru, **hapus** dulu versi lama.
6. Gambar alarm yang dihasilkan platform bisa diambil kembali untuk dianotasi (lihat 4.7).

### 14.6 Mengenali satu folder sekaligus

Tanpa men-deploy layanan, Anda bisa langsung mengenali semua gambar dalam satu folder di komputer. Misalnya, setiap hari foto barang retur dimasukkan ke satu folder, lalu setelah dikenali langsung terpilah per kelas:

1. Di **Deploy → Pengenalan massal**, pilih **Folder yang akan dikenali** (gambar di subfolder juga ikut dikenali) dan folder tujuan di **Simpan hasil ke**. Folder hasil boleh berada di dalam folder yang akan dikenali (asal bukan folder itu sendiri); aplikasi menandai folder hasil dan otomatis melewatinya saat pengenalan berikutnya.
2. Atur **Ambang keyakinan**; bawaannya memakai ambang yang disarankan dari halaman Evaluasi:
   - Klasifikasi gambar: jika skor kelas yang paling mirip di bawah ambang, gambar dicatat sebagai "Belum pasti" untuk diperiksa orang;
   - Klasifikasi multi-label: semua kelas yang skornya mencapai ambang dihitung ada; jika tidak ada satu pun, gambar dicatat sebagai "Belum pasti";
   - Deteksi, segmentasi, keypoint: objek dengan skor di bawah ambang tidak dihitung; jika tidak ditemukan satu pun, gambar dicatat sebagai "Tanpa objek".
3. Jika **Salin ke folder per kelas** dicentang, gambar disalin ke folder bernama kelas di dalam folder hasil (gambar dengan beberapa kelas disalin sebanyak jumlah kelasnya; gambar asli tidak diubah). Gambar dari subfolder diberi awalan nama subfolder pada nama filenya agar tidak bentrok.
4. Klik **Mulai**. Anda bisa klik **Hentikan** kapan saja; gambar yang sudah dikenali tetap ditulis ke tabel.
5. Setelah selesai, jumlah gambar untuk tiap kelas ditampilkan. File "hasil.csv" di folder hasil bisa langsung dibuka dengan Excel: satu baris per gambar, berisi file, hasil, dan skor tertinggi, lalu satu kolom untuk tiap kelas (skor untuk klasifikasi, jumlah yang ditemukan untuk deteksi). Gambar yang tidak bisa dibaca ditandai "Galat".
6. Jika ada gambar "belum pasti" ("tanpa objek" untuk deteksi), klik **Tambahkan N gambar yang belum pasti ke proyek untuk dianotasi** untuk mengimpornya ke proyek saat ini, lalu klik **Anotasi batch ini** untuk melihat gambar-gambar itu saja. Anotasi lalu latih ulang, model akan makin akurat seiring dipakai.

**Mengenali video**: video di dalam folder (mp4, mov, mkv, avi, dan lainnya) juga ikut dikenali. Cocok untuk pola seperti "satu folder per nomor pesanan, isinya satu video barang retur":

1. Di bagian **Video**, atur **tiap berapa detik satu frame dilihat** (bawaannya 1 detik) dan **minimal berapa frame cocok agar kelas dihitung** (bawaannya 1 frame; kalau sering ada salah deteksi di satu frame saja, naikkan ke 2–3).
2. Setiap video hanya dilihat sekali. Di tabel, satu video satu baris; kolom "Folder" berisi subfolder tempat video berada (misalnya nomor pesanan), dan hasilnya ditulis seperti "Bilah kipas rusak (3 frame)", artinya kelas itu terdeteksi di sekian frame.
3. Untuk setiap kelas yang ditemukan disimpan satu tangkapan layar (frame dengan skor tertinggi). Kotaknya digambar seperti di halaman Anotasi (untuk model segmentasi, garis tepinya), dengan kelas dan skor di pojok kiri atas tiap kotak; untuk model klasifikasi, kelas yang ditemukan ditulis di pojok kiri atas. Tangkapan layar disimpan di folder hasil, di dalam subfolder yang namanya sama dengan subfolder video, misalnya `hasil/1367524416106/Bilah kipas rusak_00m12s_0.93.jpg`; untuk video yang ada langsung di folder paling luar, dibuatkan folder sesuai nama file videonya.
   - Jika **Simpan tangkapan layar video di samping tiap video** dicentang, tangkapan layar disimpan di folder "Tangkapan pengenalan" di samping tiap video, misalnya `1367524416106/Tangkapan pengenalan/Bilah kipas rusak_00m12s_0.93.jpg`, jadi tidak perlu disalin balik secara manual. Folder-folder ini otomatis dilewati saat pengenalan berikutnya.
   - Jika **Salin ke folder per kelas** dicentang, untuk video yang disalin adalah tangkapan layar tiap kelas, dengan nomor pesanan di depan nama filenya, misalnya `hasil/Bilah kipas rusak/1367524416106_Bilah kipas rusak_00m12s_0.93.jpg`; videonya sendiri tidak disalin.
4. Saat pertama kali mengenali video, ffmpeg (sekitar 90 MB) akan diunduh otomatis.

### 14.7 Pertanyaan umum

- **Log paket layanan terus menampilkan "[Kamera 1] Gagal terhubung, mencoba lagi dalam 10 detik"**: alamat stream ini tidak bisa dibuka.
  - Video lokal: periksa apakah yang diisi adalah path lengkap file video (dengan ekstensi seperti `.mp4`); kalau hanya diisi folder, pesan ini akan muncul. Jika path mengandung karakter khusus atau non-Latin dan tetap tidak bisa terhubung, pindahkan video ke path yang hanya berisi huruf dan angka biasa, misalnya `D:\test\1.mp4`, lalu coba lagi.
  - Kamera: periksa nama pengguna, sandi, IP, dan port, serta apakah komputer di lapangan bisa ping ke kamera; bisa juga coba buka alamat yang sama di VLC terlebih dulu.
- **Ingin mengenali semua gambar atau video dalam satu folder**: gunakan 14.6 Mengenali satu folder sekaligus. Setiap video hanya dilihat sekali, dan tangkapan layarnya disimpan per subfolder (misalnya nomor pesanan). Paket layanan dibuat untuk memantau kamera terus-menerus, jadi video lokal secara bawaan diputar berulang; kalau ingin diputar sekali saja, tambahkan `"loop": false` untuk stream tersebut di `config.json`. Untuk menyambungkannya ke sistem sendiri, panggil API HTTP paket layanan `POST /predict` dan kirim gambar satu per satu. Penjelasannya ada di `README.md` di dalam paket layanan.

## 16. Panduan Xuntong AI

Xuntong AI ([xuntongai.com](https://xuntongai.com)) adalah platform pengenalan AI: tersedia model pengenalan khusus siap pakai (pemilahan sampah, helm, asap dan api, dll.) dan pengenalan dengan LLM, serta bisa meng-hosting model Anda sendiri, menghubungkan kamera, dan mengirim alarm. Dengan Wulabel yang terhubung ke platform ini, **anotasi, pelatihan, peluncuran, dan data balik dari lapangan** bisa menjadi satu siklus tertutup. Cara pakainya sudah dibahas terpisah di bab-bab sebelumnya; bab ini merangkumnya dengan jelas.

Tempat Xuntong AI dipakai di Wulabel:

| Di mana | Fungsinya | Lihat |
|---|---|---|
| Pengaturan → Xuntong AI | Masuk ke akun, melihat kuota | 16.1, 16.2 |
| Halaman Anotasi → Bantuan AI → Xuntong AI | Anotasi otomatis dengan model khusus / LLM / berdasarkan kelas proyek | 16.3–16.5 |
| Halaman Anotasi → Bantuan AI → Aturan pengenalan | Menulis catatan pengenalan, mengobrol dengan AI tentang cara mengenali, sinkron ke platform | 16.5 |
| Deploy → Ekspor model → Unggah ke platform Xuntong AI | Memakai model yang sudah dilatih di platform | 16.6 |
| Data → Opsi impor lainnya → Ambil gambar alarm dari Xuntong AI | Mengambil positif palsu dan objek terlewat dari lapangan untuk dianotasi ulang | 16.7 |
| Kolaborasi → Online · Relay resmi Xuntong | Anggota dari internet luar terhubung dan menganotasi bersama | 16.8 |

### 16.1 Masuk ke akun

1. Buka **Pengaturan**, lalu di bagian "Xuntong AI" klik **Masuk ke akun Xuntong AI**.
2. Browser akan membuka halaman Xuntong AI:
   - Jika belum masuk, masuk dulu (sama seperti biasa masuk ke Xuntong; bisa dengan kode verifikasi maupun SMS);
   - Pastikan kode konfirmasi di halaman web sama dengan yang ada di jendela pop-up Wulabel, lalu klik **Izinkan**.
3. Kembali ke Wulabel. Beberapa detik kemudian tampil **Masuk sebagai** beserta nama akun dan paket, sisa kuota, serta metode pengenalan yang tersedia.

Catatan:

- Tidak perlu membuat atau menyalin API Key di konsol: saat masuk, platform memberikan Key khusus untuk komputer ini dengan nama "Wulabel · nama komputer". Key ini terlihat di halaman "API Key" pada konsol Xuntong dan bisa dinonaktifkan di sana.
- Jika masuk lagi di komputer yang sama, Key lama otomatis diganti. Akun pribadi maksimal punya 2 Key; jika sudah penuh, tombol "Izinkan" di halaman web tidak bisa diklik. Nonaktifkan Key yang tidak dipakai di konsol, lalu coba lagi.
- Jika browser tidak terbuka otomatis: klik **Buka kembali** di jendela pop-up, atau salin alamatnya dan buka sendiri. Kode masuk berlaku 10 menit.
- **Keluar**: Key di komputer ini dihapus, dan Key yang diberikan saat masuk dinonaktifkan di platform.
- Jika sudah punya API Key, atau Xuntong dipasang secara privat: klik **Lanjutan: isi API Key secara manual, alamat platform untuk deployment privat**.

### 16.2 Kuota dan biaya

- Halaman Pengaturan menampilkan sisa tiap jenis kuota dan kapan berakhirnya: pengenalan LLM, pengenalan model khusus, pengenalan model sendiri, paket tambahan, dan lainnya, sesuai paket Anda.
- Cara penghitungan: mengenali satu gambar dihitung 1 gambar. Sebelum pra-anotasi massal, total gambar ditampilkan; setiap putaran obrolan dengan AI tentang aturan pengenalan dihitung 1 gambar kuota LLM.
- Hanya kuota akun Anda sendiri yang dipakai; saat anggota kolaborasi mengobrol dengan AI, yang dipakai adalah kuota host (host bisa mematikan "Anggota dapat memakai bantuan AI" di halaman Kolaborasi).
- Jika kuota habis, akan muncul pesan bahwa kuota tidak cukup; pra-anotasi massal berhenti, dan gambar yang sudah dianotasi tetap tersimpan.

### 16.3 Memilih di antara empat metode pengenalan

Di "Bantuan AI" sebelah kanan halaman Anotasi, pilih **Xuntong AI**; daftar "Pilih model pengenalan" berisi:

| Metode pengenalan | Cocok untuk | Kecepatan | Kuota |
|---|---|---|---|
| Model khusus (misalnya pemilahan sampah, helm) | Kelas proyek sesuai dengan model siap pakai di platform | **Paling cepat**; saat massal 8 gambar per kumpulan, dua kumpulan dikirim bersamaan | Pengenalan model khusus |
| Model sendiri yang Anda unggah dan aktifkan | Model yang Anda latih sendiri dan unggah ke platform | Sama seperti di atas | Pengenalan model sendiri |
| Kenali berdasarkan kelas proyek (disarankan) | Platform tidak punya model yang sesuai; Anda hanya ingin mencari beberapa kelas di proyek | Satu per satu, lebih lambat | Pengenalan LLM |
| Pengenalan umum LLM | Mencari berdasarkan kategori besar bahaya keselamatan (kebakaran, kelistrikan, sanitasi lingkungan, dll.) | Satu per satu | Pengenalan LLM |

Cara memilihnya sederhana: **jika ada model khusus yang sesuai, pakai model khusus** (cepat dan akurat); jika tidak ada, pakai **Kenali berdasarkan kelas proyek**, dan tulis catatan pengenalan tiap kelas dengan jelas (16.5).

### 16.4 Anotasi otomatis massal dengan model khusus

Contoh dengan pemilahan sampah:

1. Buat proyek deteksi dan impor gambar. Kelas boleh belum dibuat: nama kelas yang dikenali model (misalnya "sampah daur ulang") yang belum ada di proyek akan dibuat otomatis.
2. Buka halaman Anotasi, di "Bantuan AI" sebelah kanan pilih **Xuntong AI**, dan pilih model **pemilahan sampah**.
3. Atur **Keyakinan**: pakai nilai bawaan dulu; naikkan jika kotaknya terlalu banyak, turunkan jika banyak yang terlewat.
4. Tekan `P` dulu untuk menganotasi gambar saat ini dan melihat hasilnya; jika sudah puas, klik **Pra-anotasi massal**. Semua gambar "Belum dianotasi" yang belum punya anotasi akan dikenali per kumpulan, dan bilah progres menampilkan progresnya.
5. Kotak hasil pengenalan bergaris putus-putus (sumber "Xuntong"). Periksa satu per satu: hapus yang salah, seret yang bergeser hingga pas, tambahkan yang terlewat, lalu tekan `Enter` (Selesai & berikutnya).
6. Ingin lebih cepat: setelah menganotasi beberapa ratus gambar, latih model sendiri dengan data tersebut (Bab 10); setelah itu pra-anotasi berjalan di komputer Anda tanpa memakai kuota.

Saat proses massal, jika muncul pesan permintaan terlalu sering, aplikasi otomatis memperlambat dan mencoba lagi tanpa memotong kuota dua kali; untuk error seperti kuota tidak cukup atau model belum diaktifkan, proses berhenti dan memberi tahu berapa gambar yang sudah dianotasi.

### 16.5 Pengenalan berdasarkan kelas proyek dan aturan pengenalan

Jika platform tidak punya model yang sesuai, gunakan "Kenali berdasarkan kelas proyek": platform hanya mencari kelas di proyek Anda, nama kelas dipakai apa adanya, dan **apa pun di luar daftar tidak dilaporkan**. Bagus tidaknya hasil sangat bergantung pada seberapa jelas aturan Anda.

**Menulis catatan pengenalan:**

1. Di tombol edit samping kelas, isi **Catatan pengenalan**: apa yang dimaksud kelas ini, apa yang termasuk / tidak termasuk. Misalnya:
   - Tidak memakai helm: orang tanpa helm di kepala; memakai helm tetapi tali tidak dikaitkan juga termasuk; bingkai hanya kepala dan tubuh bagian atas.
   - Sepeda listrik: sepeda motor listrik roda dua, sepeda listrik; sepeda biasa dan sepeda motor tidak termasuk.
2. Atau di samping judul "Bantuan AI" klik **Aturan pengenalan**, lalu di **Aturan saat ini** ubah sekaligus **Aturan umum** (berlaku untuk semua kelas, misalnya "hanya lihat lorong di bagian bawah gambar, abaikan isi poster dan layar") dan catatan tiap kelas, lalu klik **Simpan aturan**.

**Mengobrol dengan AI:** jika tidak tahu cara menulis aturan, jelaskan dengan bahasa sehari-hari di **Aturan pengenalan → Mengobrol dengan AI**:

- "Memakai helm tetapi tali tidak dikaitkan juga dihitung tidak memakai helm"
- "Rompi reflektif bukan helm"
- "Kenapa orang di sebelah kiri gambar ini tidak dikenali?"

Secara bawaan gambar saat ini dilampirkan; setelah AI menjawab, AI mencoba mengenali gambar ini sesuai aturan baru. Jika AI menyarankan perubahan aturan, isinya ditampilkan, dan aturan baru disimpan hanya setelah Anda klik **Terapkan aturan ini**; jika uji pengenalan memberi hasil, klik **Tambahkan kotak hasil uji pengenalan ke gambar ini** untuk langsung memakainya.

**Sinkronkan ke platform Xuntong (opsional):** di bagian paling bawah "Aturan saat ini", klik **Sinkronkan ke platform Xuntong**, dan aturan disimpan ke platform. Secara bawaan tidak aktif, jadi tidak memengaruhi pengenalan platform saat ini.

Jika ingin pengenalan milik platform Xuntong sendiri (tangkapan, pengiriman alarm) juga hanya melaporkan kelas di proyek Anda, nyalakan **Pakai aturan ini juga untuk pengenalan di platform**. Perhatian: setelah dinyalakan, semua pengenalan di akun Xuntong mengikuti aturan ini; skenario yang berlaku bisa diatur di halaman "Aturan pengenalan" pada konsol Xuntong.

Setelah terikat, setiap kali aturan disimpan atau diterapkan, isinya otomatis disinkronkan, tetapi status aktif/nonaktif dan skenario yang Anda atur di konsol tidak diubah. Jika tidak ingin sinkron lagi, klik **Lepas ikatan**; aturan di platform tidak dihapus.

**Batasan:** maksimal 30 kelas, nama kelas maksimal 30 karakter; aturan umum maksimal 1000 karakter, catatan pengenalan tiap kelas maksimal 500 karakter; setiap akun Xuntong maksimal 20 set aturan.

### 16.6 Mengunggah model terlatih ke Xuntong

1. Latih model **Deteksi objek** di Wulabel (saat ini Xuntong hanya menerima model deteksi).
2. Buka **Deploy → Ekspor model**, di bagian paling bawah "Unggah ke platform Xuntong AI" ubah nama model, lalu klik **Unggah**. Jika ONNX belum diekspor, akan diekspor otomatis lebih dulu; ambang yang disarankan dari halaman Evaluasi ikut diunggah.
3. Platform memvalidasi selama beberapa detik hingga satu menit: tampil "Memvalidasi" → "Lolos validasi" (atau "Validasi gagal" beserta alasannya).
4. Klik **Buka konsol**, lalu di "Model kustom" klik **Aktifkan**. Setelah diaktifkan, Anda bisa menghubungkan kamera dan mengatur alarm di platform, dan model ini juga bisa dipilih di daftar model halaman Anotasi.
5. Di bawahnya, "Model kustom di platform" menampilkan model yang sudah diunggah, status validasi, dan apakah sudah diaktifkan. Akun tanpa layanan hosting hanya bisa menyimpan 1 model; sebelum mengunggah versi baru, **hapus** dulu versi lama. Ukuran file model maksimal 200 MB.

### 16.7 Mengambil gambar alarm dari lapangan untuk perbaikan berkelanjutan

Setelah model berjalan, tangkapan alarm dari lapangan berisi positif palsu dan objek terlewat, dan itulah data yang paling layak ditambahkan:

1. **Data → Opsi impor lainnya → Ambil gambar alarm dari Xuntong AI**.
2. Pilih rentang waktu (1 / 3 / 7 hari terakhir), alarm dari model mana, dan jumlah gambar maksimal. Secara bawaan dicentang **Gunakan kotak hasil deteksi platform sebagai pra-anotasi**.
3. Gambar yang diambil disimpan di folder `images/xuntong_<waktu>/` dalam proyek, dan kotaknya bergaris putus-putus (sumber "Xuntong").
4. Perbaiki satu per satu: hapus kotak positif palsu (gambar yang memang tidak berisi objek cukup tekan **Enter** (Selesai) agar disimpan sebagai sampel negatif), tambahkan yang terlewat.
5. Latih ulang, evaluasi, lalu unggah versi baru untuk menggantikan model lama di platform.

Perhatian: platform menyimpan gambar alarm selama 7 hari, jadi ambil secara rutin; hanya akun yang sudah mengatur saluran pengiriman yang menghasilkan catatan alarm.

Inilah siklus tertutupnya: **anotasi → pelatihan → unggah ke Xuntong → alarm di lapangan → ambil dan perbaiki → latih lagi**, dan model makin akurat seiring pemakaian.

### 16.8 Xuntong AI dalam kolaborasi

- **Relay resmi**: di halaman Kolaborasi, pilih cara berbagi **Online · Relay resmi Xuntong**; anggota dari internet luar terhubung melalui server Xuntong tanpa memerlukan server Anda sendiri. Anda harus masuk ke akun Xuntong dulu. Setiap akun maksimal menjalankan 3 sesi berbagi sekaligus; gambar dan anotasi diteruskan melalui server Xuntong dan tidak disimpan. Untuk proyek dengan data sensitif, gunakan LAN atau relay sendiri.
- **Apa yang bisa dipakai anggota**: anggota tidak bisa langsung melakukan pra-anotasi dengan Xuntong AI (karena akan memakai kuota Anda); jika "Anggota dapat memakai bantuan AI" dinyalakan, anggota bisa membuka aturan pengenalan dan mengobrol dengan AI (memakai kuota Anda). Boleh tidaknya mengubah aturan mengikuti sakelar "Anggota dapat menambah dan mengedit kelas".

### 16.9 Pertanyaan umum

- **Browser tidak merespons setelah klik masuk**: klik **Buka kembali** di jendela pop-up, atau salin alamatnya dan buka di browser. Lakukan hal yang sama jika komputer kantor melarang browser terbuka otomatis.
- **Tombol "Izinkan" di halaman web tidak bisa diklik**: jumlah Key akun sudah penuh; nonaktifkan Key yang tidak dipakai di halaman "API Key" pada konsol Xuntong.
- **Muncul pesan koneksi gagal**:
  - Lihat alasan di pesan tersebut;
  - Untuk Key yang diisi manual, periksa apakah disalin lengkap (diawali `sk-live-`), apakah diaktifkan di konsol, dan apakah ada daftar IP yang diizinkan (Key yang diberikan saat masuk tidak punya daftar IP);
  - Anda juga bisa keluar lalu masuk lagi.
- **Muncul pesan "kuota habis atau permintaan terlalu sering"**: lihat sisa kuota di halaman Pengaturan; jika kuota habis, perpanjang atau beli paket tambahan di Xuntong. Kecepatan anotasi massal sudah diatur oleh aplikasi.
- **Model khusus tertentu tidak ada di daftar model**: berarti akun belum mengaktifkannya; aktifkan paket yang sesuai di Xuntong AI.
- **Nama kelas hasil pengenalan berbeda dengan nama di proyek**: model khusus memakai nama kelasnya sendiri, dan kelas yang belum ada di proyek dibuat otomatis. Untuk menyeragamkan nama, gunakan "Kenali berdasarkan kelas proyek", atau ganti nama kelas saat mengedit kelas setelah pengenalan.
- **Xuntong yang dipasang secara privat**: di bagian "Lanjutan" pada Pengaturan, isi alamat platform dan API Key milik Anda sendiri.
