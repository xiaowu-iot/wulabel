## 1. Installation and first launch

### 1.1 Download and install

1. Open the website <https://wulabel.xiaowuiot.com> and click **Download** in the top-right corner, or download from the GitHub Releases page.
2. Windows: download `Wulabel_<version>_x64-setup.exe`, double-click it and follow the prompts. When it's done, open **Wulabel** from the Start menu or the desktop.
3. Mac: download `Wulabel_<version>_universal.dmg`, double-click to open it, and drag Wulabel into the Applications folder.
4. Linux (from v0.4.0): download `Wulabel_<version>_amd64.deb` and run `sudo apt install ./Wulabel_<version>_amd64.deb` in a terminal, then open **Wulabel** from the app menu. You can also download the `.AppImage`, run `chmod +x Wulabel_<version>_amd64.AppImage`, and double-click it to run without installing. On ARM computers (Phytium, Kunpeng), download `Wulabel_<version>_arm64.deb` or `Wulabel_<version>_aarch64.AppImage` (from v0.4.2). Usage is the same.

- System requirements: Windows 10 / 11 (64-bit); macOS 11 or later (Apple silicon and Intel); Linux x86_64 (Ubuntu 22.04 or later, Debian 12, UOS, Kylin on x86 computers, etc.); Linux ARM64 (from v0.4.2: Kylin, UOS and others on Phytium and Kunpeng computers; download the files with `arm64` or `aarch64` in the name).
- Not supported yet: Loongson, HarmonyOS. HarmonyOS devices can join team collaboration in a browser.
- If Windows says WebView2 is missing the first time you open the app, install it as prompted (most Windows 10 / 11 systems already have it).
- On Mac, the first launch says the developer cannot be verified (the app isn't signed with an Apple developer certificate). In Applications, **right-click** Wulabel → Open → click Open again. On macOS 15 and later, double-click the app once, then go to System Settings → Privacy & Security and click Open Anyway at the bottom. If it says the app is damaged, run `xattr -cr /Applications/Wulabel.app` in Terminal and open it again. You only need to do this the first time.

### 1.2 The main window

The first page you see is **Projects**. Once you open a project, the navigation bar on the left shows, from top to bottom:

| Page | What it's for |
|---|---|
| Projects | Create, open and switch projects |
| Data | Import images / videos / datasets, manage images, export datasets |
| Annotate | Draw boxes and polygons, pick classes, place keypoints, AI assist and pre-labeling |
| Health check | Find missed labels, wrong labels, duplicate images and other problems |
| Train | Choose a model, set parameters, start training, view training runs |
| Evaluate | Metrics, confusion matrix, errors, recommended threshold, false-positive tests, reports |
| Deploy | Live test, export models, build inference service packages, import field data |
| Review | Only with team collaboration: filter by member and status, approve or reject in bulk, spot check |
| Collaborate | Live team collaboration: start sharing (LAN / online), members, task assignment, progress stats |
| Settings | Install the training environment, download sources, Xuntong AI |

The **Feedback** button and **Close project** are in the top-right corner.

## 2. Settings: training environment, download sources, Xuntong AI

If you only annotate and import/export without training, you can skip this chapter for now.

### 2.1 One-click training environment install

1. Click **Settings** on the left.
2. Look at the "Training environment" section:
   - The **GPU** row shows the detected GPU, VRAM, driver and supported CUDA version. Without an NVIDIA GPU it says "No NVIDIA GPU detected; training can only use the CPU (much slower)".
   - The **PyTorch version** drop-down picks the recommended version automatically (marked "Recommended"). You usually don't need to change it:
     - CUDA 12.8: newer GPUs such as the RTX 50 series;
     - CUDA 13.0: requires a recent driver;
     - CUDA 11.8: older GPUs and drivers;
     - CPU version: no NVIDIA GPU.
3. (Optional) **Install location**: by default it goes into the local app data folder on drive C. If drive C is low on space, click to choose a drive with more space, then click **Save**.
4. Click **Install**. The GPU version is about 3 GB. uv, Python 3.11 and PyTorch are downloaded automatically, and the screen shows "Step N / 5" along with the download progress and time remaining. You only need to install it once.
   - If the network drops, the download resumes where it left off, and a slow network won't make it fail halfway; to stop, click **Cancel**.
   - If the selected PyTorch version doesn't match your GPU or driver (for example, the GPU version without an NVIDIA GPU, a CUDA version newer than your driver supports, or an older version on an RTX 50 series card), you're warned before it starts.
   - If the driver is too old and only the CPU version can be installed, it tells you which driver version or later you need to train on the GPU.
5. When it's done, the status changes to **Ready** and shows "GPU available (cuda)" below.
   - If components such as numpy, onnx or opencv are missing, they're listed; click **Install missing components** to install only the missing ones.
   - If the GPU version is installed but the GPU can't be used, a yellow notice shows "GPU unavailable, training on CPU for now".
6. If installation fails, you can click **Report this issue** right in the failure dialog; the install log is attached automatically.

> The training environment is self-contained and doesn't affect any other Python on your system.

### 2.2 Download sources

1. If you haven't chosen one yet, the Chinese interface uses the China mirrors by default, and other languages use the official sources.
2. In the "Download source" section, click **Test speed and recommend**. The app downloads a few MB from the official sources and the China mirrors, then selects the faster one automatically.
3. When "China mirrors" is selected, helper models such as SAM and text prompt are also downloaded from a China mirror (hf-mirror.com).
4. uv (the tool used to install Python) and ffmpeg (used to extract video frames) are usually downloaded automatically. If the automatic download doesn't work, you can install them yourself and point to their locations under "uv and ffmpeg (advanced)".

### 2.3 Xuntong AI (optional)

You only need this if you want to auto-label with models from the Xuntong AI platform, upload models, fetch alert images, or collaborate online through the "Xuntong official relay":

1. In the "Xuntong AI" section, click **Sign in to Xuntong AI**.
2. Your browser opens the Xuntong AI web page. Sign in first if you aren't already (the same way you normally sign in to Xuntong), check that the confirmation code on the page matches the one shown in Wulabel, and click **Allow**.
3. Back in Wulabel, after a few seconds it shows **Signed in as** with your account name, plan and remaining quota, plus the available recognition methods (recognize by project classes, dedicated models enabled on the platform, general LLM recognition). No need to copy and paste a key.
4. If the browser didn't open, click **Reopen**, or copy the address from the dialog and open it yourself.
5. **Sign out**: the key on this computer is deleted, and the key created automatically at sign-in is revoked on the platform.

If you already have an API key, or your Xuntong platform is self-hosted, click **Advanced: enter an API key manually or a self-hosted platform address**, fill it in, and click **Save and test connection**. The connection status stays visible in this section.

### 2.4 Use an existing Python environment (advanced)

If you already have a Python environment with PyTorch installed, you can skip the download:

1. Expand "Use an existing Python environment (advanced)".
2. Click **Choose python.exe** and select the environment's `python.exe` (e.g. `D:\envs\torch\Scripts\python.exe`).
3. Click **Save**. The environment needs torch, torchvision, numpy and pillow; exporting ONNX also needs onnx.
4. To switch back to the app's own environment, clear the path and save.

### 2.5 Check for updates

The app checks once for a new version at startup and shows a notice in the bottom-right corner if there is one. Click **Update now**, and the app downloads the new version in the background, verifies it, installs it and reopens itself, with no buttons to click along the way (Windows only shows an install progress bar; Linux installs from .deb can also update automatically from v0.4.2, and you may be asked for your system password once during install). Your projects and data are kept (from v0.4.1). You can also click "Download" to open the download page. To stop seeing the notice for a version, click "Don't remind me about this version". If you click update while training, a training environment install, a live test or collaboration sharing is running, these tasks are listed first and you can choose **Not now**. While an update downloads, you can close the dialog; the download continues in the background and installs automatically when it's done. You can also click **Check for updates** manually under "About & updates" at the bottom of the Settings page.

The update check only sends the app version, OS type and a random anonymous ID, used to estimate roughly how many people use the app. It contains no images, projects or personal information. If you don't want it to go online, turn off **Check for updates at startup** under "About & updates".

### 2.6 Language, appearance and the Xuntong AI switch

At the top of the Settings page you can change:

- **语言 / Language** (from v0.5.0): the interface is available in 简体中文, 繁體中文, English, 日本語, 한국어, Español, Português, Русский, Deutsch, Français, Tiếng Việt, Bahasa Indonesia. By default it uses **Follow system** (Chinese on a Chinese system, English for languages that aren't included); the interface reloads after you change it. Training logs, error messages, delivery reports and the inference service package's instructions use this language too.
- **Appearance** (from v0.5.1): **Follow system**, **Light** or **Dark**. By default it follows your system's light or dark mode. Image areas such as the annotation canvas and image preview always stay dark so images are easy to see.
- **Xuntong AI switch** (from v0.5.2): the switch in the top-right corner of the "Xuntong AI" card. It's on by default for Simplified Chinese and off for other languages. When it's off, Xuntong AI and the recognition rules on the Annotate page, fetching alert images on the Data page, uploading to Xuntong on the Deploy page and the Xuntong official relay on the Collaborate page are hidden; turn it on if you need them.

## 3. Create and open projects

**A project is just a folder**: images (copied in), annotations, models and training runs are all inside it. Copy the whole folder to another computer and it opens directly.

The first time you use the app, the top of the "Projects" page shows a **getting started guide**. It walks you through six steps: install the training environment, create a project, import images, annotate a small batch, train, then pre-label and deploy. Finished steps are checked off automatically. Click × in the top-right corner to close it; click "Show getting started guide" to bring it back later.

The cards under "Recent projects" show the project cover, the number of images, how many are labeled (progress bar) and how many times it has been trained, so you can see at a glance how far each project has come.

### 3.1 Create a project

1. On the **Projects** page, click **New project**.
2. **Project name**: e.g. "Construction site helmet detection".
3. **Location**: the default is "Documents/Wulabel"; you can also click **Browse** to choose another folder. The project will be created inside it.
4. **Task type** (can't be changed after creation):

   | Task | Annotation | Good for |
   |---|---|---|
   | Object detection | Rectangle boxes | Locating hard hats, vehicles, smoke and fire |
   | Instance segmentation | Polygon outlines | Precise shapes: puddles, garbage piles, defect areas |
   | Image classification | One class per image | "Normal / abnormal" scenes, scene categories |
   | Multi-label classification | Several classes per image | Several things in one image: multiple kinds of product damage, several scene attributes |
   | Keypoints | Object box + points placed by template | Human pose (falls, climbing), key parts of objects |

5. **Classes** (optional): write down the classes you want to label in advance, separated with commas or new lines, e.g. "Helmet, Person, Reflective vest". If you leave it empty, you can add them on the Annotate page at any time.
6. Click **Create**. You'll see "Project "…" created" and it opens automatically.

### How to choose a task type

The task type can't be changed after the project is created, so think through these three questions first:

1. **Do you need to know where things are in the image?** If you need their positions or a count, choose object detection, instance segmentation or keypoints. If you only care about "what this image shows, or what's wrong with it", choose image classification or multi-label classification.
2. **How precise does the position need to be?** If a rough position (a box) is enough, choose **Object detection**; for exact shapes, areas or boundaries, choose **Instance segmentation**; to know where each part of a person or object is (head, hands, feet), choose **Keypoints**.
3. **How many conclusions does one image have?** If there's only one and the options exclude each other (good or defective, day or night), choose **Image classification**; if several can be true at once (scratched and missing an accessory), choose **Multi-label classification**.

What to choose for common scenarios:

| Scenario | Recommended type | How to annotate |
|---|---|---|
| Hard hats, reflective vests and head counts on construction sites | Object detection | Draw one box around each head and each reflective vest |
| Smoke, open flames, vehicles, pedestrians | Object detection | Box each object; smoke and fire have irregular shapes, so boxing the rough area is enough |
| Extent and area of puddles, oil leaks, garbage piles | Instance segmentation | Trace the outline |
| Location of cracks, scratches and chips on product surfaces | Instance segmentation (if you need the shape) or Object detection (if you only need the position) | Outlines for long, thin or irregular defects; boxes otherwise |
| Poses such as falling, climbing or raising a hand | Keypoints | Draw a box around the person first, then place the 17 points by template |
| Good / defective parts on a production line, gauge normal / abnormal | Image classification | Press a number key to pick one class for each image |
| Scene categories: day / night, indoor / outdoor | Image classification | Same as above |
| E-commerce returns: identifying the damage (fan blade damage, dust/stains, missing accessories…) | Multi-label classification | Tick every kind of damage you see in each image; tick "Brand new" when there's no problem |
| Product photo attributes (color, style, packaged or not) | Multi-label classification | Tick every attribute that applies to each image |

Common mix-ups:

- **Classification or detection**: if an image has several objects, the objects are small, or you need to report positions or counts, use detection. If the whole image has one main subject and you only care what it is, use classification. It's much faster to annotate (one key per image).
- **Single-label or multi-label**: if the classes exclude each other and each image can only be one of them, use image classification; if several can apply at once, use multi-label classification. In a multi-label project every image needs at least one class, so add a class such as "Brand new" or "Normal" for images with no problems.
- **Detection or segmentation**: if you only need alerts, counts or positions, use detection; use segmentation only when you need areas or exact boundaries. Segmentation takes much longer to annotate than drawing boxes.
- **Tiny problems**: when a defect covers only a small part of the image, whole-image classification may not catch it. Switch to detection and box the defect, or shoot closer so the defect fills more of the frame.
- **Training images**: don't train directly on stitched side-by-side comparison images or on images with red circles or text drawn on them. The model may learn that "a red circle means a problem". Use the original images whenever you can.

If you're not sure, create a small project, annotate a few dozen images, train once, and decide after looking at the evaluation results.

### 3.2 Open a project

- Click a project in the **Recent projects** list to open it. The list shows when each project was last opened.
- If it isn't in the list, click **Open project…** and choose the project folder.
- If a project folder has been moved, the list shows "Folder not found": click **Locate…** and choose its new location to keep using it. If the folder has been deleted, click "Remove from list" (files are not deleted).

## 4. Import data

Click **Data** on the left.

### 4.1 Import images or folders

1. First choose the import mode at the top of the page:
   - **Copy into project**: images are copied into the project folder, so the whole project can be moved (recommended);
   - **Reference original paths**: only the images' original locations are recorded. No extra space is used, but the originals must not be moved.
2. Import:
   - Click **Import folder** and choose a folder (images in subfolders are found automatically);
   - Or click **More import options → Import image files** and select some images;
   - Or just **drag** images and folders **into the window** and let go when you see "Release to import images or videos". If you drag in a video file, the "Extract frames from video" dialog opens directly (see 4.2).
3. Progress is shown in two stages during import: first "Processed N / M images (computing fingerprints, generating thumbnails)", then "Copying and writing: N / M images" ("Writing to project" when only referencing original paths). Importing tens of thousands of images at once won't freeze the app, and thumbnails can still be viewed during the import. If you picked the wrong thing, click **Stop**; images already processed are still added. When it's done, it tells you how many were added and how many duplicates were skipped; click **Start annotating** in the message to go straight to the Annotate page.

Imports are automatically **deduplicated by content** (the same image is never imported twice), and photos are **rotated upright** based on their EXIF data.

### 4.2 Import videos (extract frames)

1. Click **More import options → Import videos (extract frames)** and select one or more video files.
2. In the "Extract frames from video" dialog, set:
   - **Every N seconds, extract 1 frame**: if things change slowly, use a longer interval to avoid piles of nearly identical images;
   - **Max N frames per video** (0 = unlimited).
3. Click **Start extracting**. The first time, ffmpeg (about 90 MB) is downloaded automatically. You won't need to download it again. If you set the wrong parameters, click **Stop**; frames already extracted are still imported.
4. Extracted frames are copied into the project and deduplicated by content automatically. When it's done, you'll see "Extracted M frames from N videos: added K images".

### 4.3 Extract frames from a video stream (RTSP / live / playback)

1. Click **More import options → Extract frames from a video stream (RTSP / live / playback)**.
2. Enter the address: an RTSP camera (`rtsp://…`), or an http(s) live, playback or on-demand address (mp4, m3u8, flv).
   - Hikvision: `rtsp://username:password@IP:554/Streaming/Channels/101` (main stream) or `102` (sub stream)
   - Dahua: `rtsp://username:password@IP:554/cam/realmonitor?channel=1&subtype=0`
3. Click **Test connection**. It shows the resolution and whether it's a "Live stream (endless, set a limit)" or a "Playback stream · Duration …".
4. Settings:
   - **Every N seconds, extract 1 frame**;
   - **Extract up to N frames**, **Capture for up to N minutes** (0 = unlimited, live only). **A live stream never ends, so set at least one of these**;
   - Check **Skip nearly identical frames** to save fewer duplicates when the scene is still.
5. Click **Start capture**. Images are added as they are captured, and you can watch them appear one by one on the Data page.
6. During capture, click **Minimize** to do other things. The bottom-right corner shows "Capturing · N frames extracted"; click **Expand** to come back. Click **Stop capture** to finish at any time. Images already captured are kept.
7. Captured images are saved in the project's `images/stream_<address>_<time>/` folder. When it's done, click **Open folder** to view them.

> The account and password are only used during capture. The app never writes an address containing a password into the project's folder names.

### 4.4 Import an annotated dataset

If you already have data labeled elsewhere, you can import it together with its annotations:

1. Click **More import options** and choose by project type:
   - Detection / segmentation projects: **Import annotated dataset (YOLO / COCO / VOC)**. Supports YOLO (including seg), COCO (including segmentation) and VOC;
   - Keypoint projects: **Import annotated dataset (YOLO-pose / COCO keypoints)**;
   - Classification projects: **Import classification dataset (one folder per class)**. Each subfolder of the selected folder is one class (there can also be a train / val level in between).
2. Select the dataset's root folder. The format is detected automatically.
3. When it's done, you'll see "Imported YOLO dataset" or similar, plus which classes were added.

### 4.5 Bulk actions, undo, delete, clear

The stat cards at the top of the Data page (Unlabeled, Labeled, Skipped) are clickable: click one to show only that kind of image, and click it again to go back to all images. The filter buttons below work the same way.

These are all in the **Manage** menu:

- **Select multiple**: enters selection mode. Click images to select them; hold **Shift** and click another image to select everything in between. "Select all on page" selects this page, and "Select all N images" selects every image under the current filter. Then you can:
  - **Mark as skipped**: these images are left out of training;
  - **Restore to unlabeled**: images that already have annotations go back to Labeled;
  - **Go to annotation**: sends only the selected images to the Annotate page to label one by one;
  - **Split**: move them to the training, validation or test set (only works on labeled images; see 10.1);
  - **Delete**.
  Changing the filter or the page clears the selection, so you never delete images you can't see. Finally, click **Done** to exit.
- **Undo last import (N images)**: if you just imported the wrong thing, delete the last import's images in one click (one video stream capture counts as one import).
- **Clear all images**: deletes every image in the project.

Deleting an image also deletes its annotations, and this can't be undone. Image copies made inside the project are deleted; the original images on your computer are not affected. When deleting many images, the dialog shows the deletion progress.

### 4.6 Image quality check

Blurry, too dark or overexposed images are hard to annotate and can mislead the model in training. You can filter them out first:

1. Click **Manage → Image quality check (blurry, too dark, overexposed)**.
2. **Unlabeled images only** is checked by default. Uncheck it to check everything.
3. Click **Start check**.
4. Results are grouped by problem: **Blurry**, **Too dark**, **Overexposed**, **Low contrast**. Click the tags at the top to filter. Each image shows its sharpness, brightness, overexposed ratio and contrast values.
5. What to do with them:
   - **Review one by one**: go to the Annotate page and look at each image yourself;
   - **Mark as skipped**: mark them as "Skipped" so they're left out of training (the images stay and you can undo this later);
   - **Delete**: delete them outright.

### 4.7 Fetch alert images from Xuntong AI

Once a model is deployed on the Xuntong AI platform, the on-site alert snapshots (especially false positives and missed detections) are exactly the data most worth adding:

1. First set up Xuntong AI in **Settings** (see 2.3).
2. On the **Data** page, click **More import options → Fetch alert images from Xuntong AI**.
3. Choose the time range (last 1 / 3 / 7 days; the platform keeps alert images for 7 days, so fetch regularly), the model (all or a specific one), and **Up to N images**. Only Xuntong accounts with a push channel configured generate alert records.
4. **Use the platform's detected boxes as pre-labels** is checked by default: boxes are matched to project classes by class name, and missing classes are created.
5. Click **Start fetching**. Images are saved in the project's `images/xuntong_<time>/` folder, and the detected boxes appear as dashed lines (source "Xuntong").
6. Review them on the Annotate page: delete false-positive boxes (for an image with no objects, just press **Enter** (Done) to keep it as a negative sample), add what was missed, then retrain.

## 5. Annotate

Click **Annotate** on the left.

### 5.1 The Annotate page

- **Top**: left/right arrows to browse images, the current image name and position (image N of M; click the number to type an image number and jump straight to it), resolution, and a status tag (Unlabeled / Labeled / Skipped; images with no objects show "No objects"); the filter buttons **All / Unlabeled / Labeled / Skipped** (with team collaboration, they become **All / Unlabeled / Pending review / Approved / Skipped / Rejected**, and the status tags are also called "Pending review" and "Approved"; see 9.4); on the far right, the zoom level and save status (Saved / Unsaved / Saving… / Save failed).
- **Left toolbar**: Select, Draw box (or Draw polygon), SAM smart select, Undo, Redo, Copy previous image, Keyframe interpolation, Track forward, Fit to window. Hover over a tool to see what it does and its shortcut.
- **Center**: the image canvas. Scroll to zoom; hold Space or right-drag to pan.
- **Right**: the "AI assist", "Class", "Objects in this image" ("Image class" in classification projects) and "Done" panels (with team collaboration, the last one is called "Review").
- **Below the canvas**: hints for the shortcuts available in the current project; press **?** to open the panel with all shortcuts.
- **Very bottom**: a thumbnail strip of the nearby images. Click one to jump straight to it. The small dot in the top-right corner of a thumbnail shows its status: blue is Labeled, gray is Skipped, no dot is Unlabeled.

Changes are **saved automatically**. There's no need to save manually.

### 5.2 Add and manage classes

1. In the "Class" panel on the right, type in the "New class name, press Enter to add" box, e.g. "Helmet", and press Enter.
2. The first 9 classes can be switched quickly with the number keys **1–9**. The current class is highlighted.
3. Click the edit button next to a class to:
   - Change its name and color;
   - Fill in an **English prompt** (used by "Text prompt" auto-annotation; separate multiple terms with commas, e.g. `helmet, hard hat`);
   - Fill in **Recognition notes** (used by Xuntong AI "Recognize by project classes": what exactly this class means, and what does / doesn't count, e.g. "A person without a helmet on; wearing a helmet without fastening the strap also counts");
   - Delete the class. If the class already has annotations, you can choose another class under "Merge into…", and its annotations are changed to that class instead of being lost (handy when you used the wrong class or want to combine two classes into one). If you don't choose one, the class is simply deleted along with its annotations.

### 5.3 Object detection: draw boxes

1. Press **1–9** to pick a class.
2. Press **R** (or click the Draw box tool on the left), then **hold the mouse button and drag a box** over the object.
3. Adjust: press **V** to switch to the Select tool, click a box, then drag it to move it or drag its edges and corners to resize it.
4. Delete: select a box and press **Del** or **Backspace**; press **Esc** to deselect.
5. Change the class: select a box and press a number key, or change it under "Objects in this image" on the right.
6. Press **H** to hide / show the class names on boxes, which helps when boxes are crowded.

### 5.4 Instance segmentation: draw polygons

1. Pick a class and press **R**.
2. **Click point by point** along the object's edge.
3. **Double-click** or press **Enter** to close the polygon; if you click in the wrong place, press **Backspace** to remove the last point.
4. Select a polygon to drag its vertices for fine-tuning.
5. A faster way is to press **S** for SAM smart select: one click gives you an outline automatically (see Chapter 6).

### 5.5 Image classification: one key per image

1. Look at the image and press a number key **1–9** to pick its class. The current class is shown in the top-left corner of the image.
2. Turn on the **Auto-advance** switch on the right, and each number key press jumps to the next image automatically: one key per image.
3. Press **Del** to clear this image's class; press **Ctrl+D** to reuse the previous image's class.

In a **multi-label classification** project an image can have several classes: press **1–9** to tick a class and again to untick it, then **Enter** when done; **Del** clears them all, **Ctrl+D** reuses all classes of the previous image, and **P** lets the model tick every class whose score reaches the confidence. The Evaluate page uses **mAP** as the main metric, plus the exact-match share, and lists errors as "Missed: … · Extra: …".

Images you already annotated for object detection (or segmentation, keypoints) don't need to be redone: on the original project's **Data** page, choose **Manage → Convert to a multi-label classification project**. It creates a new multi-label project where each image is tagged with every class annotated on it; images marked "No objects" can all get a class such as "Normal". The original project is unchanged.

Some classes are harder to recognize than others (for example, "dust and stains" tends to score lower), so the recommended-threshold table on the Evaluate page computes one for each class. Live verification, batch recognition and the inference service package on the **Deploy** page have **Use each class's own recommended threshold** checked by default, so each class is judged against its own threshold; uncheck it to use one threshold for all classes.

### 5.6 Keypoints

1. First look at the **Keypoint template** on the right. The default is "COCO person 17 points" (nose, left eye, right eye … left ankle, right ankle). To change it, click **Edit**:
   - **Template name**;
   - **Point names** (one per line; the order of the points is the order you click them when annotating);
   - **Connections** (one pair of numbers per line, e.g. `1-2`, used to draw the skeleton);
   - You can also click **Use COCO person 17 points** to restore the default.
   - Once keypoint annotations exist, you can only change names and connections, not add or remove points.
2. Pick a class and press **R** to draw the object box.
3. After drawing the box, **click each keypoint in turn** as prompted (the bottom of the canvas tells you which point is next, e.g. "Click Left shoulder (6/17)"):
   - Normal click: a visible point;
   - **Shift + click**: an occluded point;
   - **N**: skip a point you can't see;
   - **Backspace**: go back to the previous point;
   - **Esc**: finish this object.
4. Fine-tune: select an object and drag its keypoints directly. The right panel lists each point's status. Click a name to re-place that point on its own; click the status to toggle between "Visible / Occluded".
5. Select an object and click **Re-place keypoints** to redo it from the first point.

### 5.7 Copy previous image, undo and redo

- **Ctrl+D** (or the copy button on the left): brings over the previous image's whole set of annotations, which saves a lot of time on similar scenes and consecutive frames. In classification projects it reuses the previous image's class.
- **Ctrl+Z** to undo, **Ctrl+Y** to redo.

### 5.8 Done and skip

When you annotate on your own, there's no review step: an image with objects labeled automatically counts as "Labeled" and is used in training directly. In the "Done" panel on the right:

- **Done & next** (shortcut **Enter**): jumps to the next unlabeled image.
  - If this image really has no objects, pressing Enter records it as "No objects", and it's used in training as a **negative sample** (teaching the model not to raise false positives on scenes like this). If you pressed it by mistake, click **Undo status** in the message.
  - For images from batch pre-labeling (dashed boxes), once you've checked and fixed them, press Enter and they count as Labeled.
- **Skip** (shortcut **X**): marks it as "Skipped", so this image is left out of training. Good for blurry or irrelevant images.
- **Undo status**: changes "No objects" or "Skipped" back to the previous status.
- **Shift+D**: jumps straight to the next unlabeled image.

When you finish the last image, you'll see "This batch is done" with the number of labeled images and the number still to label. You can click **Go to training** or **Keep labeling unlabeled**.

Choose "Skipped" in the filter at the top to find skipped images and check them again.

The review workflow only exists with team collaboration (when you've added members or started live collaboration). Then this panel becomes "Review", and the buttons are **Approve & next** and **Reject**; when there are many images, the **Review** page on the left is faster for reviewing in bulk (see 9.4).

### 5.9 Video frames: keyframe interpolation and track forward

This works in detection and keypoint projects. Frames extracted from a video (in the same folder, ordered by file name) don't have to be labeled one by one.

**Keyframe interpolation** (for segments where objects move at a steady pace):

1. Go to the first frame of the segment and label all the objects (this is a "keyframe").
2. Go to the last frame of the segment and label the same objects.
3. On this last frame, click the **Keyframe interpolation** button on the left.
4. The app matches the objects at both ends by class and position and fills in the frames in between automatically. It shows "Interpolated M objects across N in-between frames"; objects that don't match at both ends are reported separately.

**Track forward** (when objects move irregularly):

1. Label the objects on the current frame.
2. Click the **Track forward** button on the left, enter the number of **Frames** in the small pop-up (default 30, max 500), and click **Track**.
3. The app follows the boxes from this frame onward, frame by frame. It stops when an object is blocked or lost, and also stops when it reaches a later frame you labeled manually, so it never overwrites manual annotations.
4. When it's done, it jumps to the last tracked frame. If a box has drifted, drag it back into place (a box you've dragged becomes a manual annotation, and this frame becomes a new keyframe), then click **Track forward** again to keep going.

Boxes created by interpolation and tracking show their source as "Interpolated" or "Track" under "Objects in this image" on the right. Interpolating or tracking again replaces them; manually drawn boxes are never changed.

> Time-saving tip: label a small batch by hand first (a few dozen to a couple hundred images), train a first model, then use it to pre-label the rest (Chapter 12). You only need to fix the mistakes.

## 6. AI-assisted annotation

Even before you have your own model, AI can help you annotate.

### 6.1 SAM smart select

1. Pick a class and press **S** (or click the SAM button on the left).
2. The first time, it installs components and downloads the model, which may take a few minutes. The canvas shows "Preparing SAM…", and the bottom-right corner shows "Downloading and installing" with the progress of each file (it resumes if interrupted, and is only needed once). With an NVIDIA GPU it uses SAM ViT-B; otherwise it uses the compact SlimSAM.
3. **Click once** on an object to select its outline automatically (preview).
   - Selected too much: **Shift + click** the extra area to exclude it;
   - Selected too little: click the part that was missed;
   - Clicked in the wrong place: press **Backspace** to remove the last point;
   - You can also **drag a box** around the object.
4. When you're happy with it, press **Enter** to accept it as the current class; press **Esc** to discard.
5. Result: segmentation projects get a polygon, detection projects get a tight box, and keypoint projects get a new object (then click "Re-place keypoints" to place its points).

### 6.2 Text prompt

Finds objects in the image by class name automatically:

1. In the "AI assist" panel on the right, choose **Text prompt**.
2. The model only understands English. Over a hundred common Chinese class names (such as 安全帽 "helmet", 人员 "person", 电动车 "e-bike", 渣土车 "dump truck", 锥桶 "traffic cone") are mapped to English automatically, and the English name is shown after the class name, e.g. "安全帽 · helmet". It also works if a Chinese class name contains one of these words, e.g. 红色安全帽 ("red helmet"). If a name isn't mapped or you want to change it, fill in the **English prompt** when editing the class.
3. Adjust **Confidence**: raise it if it finds too much, lower it if it finds nothing.
4. Click **Annotate this image (P)** to label the current image, or click **Batch pre-label** to label a batch at once.
5. The first time, the model has to be downloaded, which takes a few minutes. Segmentation projects also use SAM to produce outlines.

### 6.3 Xuntong AI

(For the full Xuntong AI guide, see Chapter 16.)

1. First set up Xuntong AI in **Settings** (see 2.3).
2. In "AI assist", choose **Xuntong AI**, then choose under "Select a recognition model":
   - **Recognize by project classes (recommended)**: finds only the project's classes, with class names matched exactly, following each class's recognition notes and the overall rules, so it won't pick up things you don't need;
   - **Dedicated models** enabled on the platform;
   - **General LLM recognition**: finds hazards by safety hazard category (fire safety, electrical, sanitation, etc.).
3. Click **Annotate this image (P)** or **Batch pre-label**. Batch pre-labeling with a dedicated model (e.g. waste sorting) is fast: 8 images per batch, two batches sent at a time. The LLM and recognize-by-project-classes methods go one image at a time, so they're slower.
4. Xuntong AI counts 1 call per image and uses your account's plan quota. You'll be told before a batch starts.

### 6.4 Recognition rules: tell AI how to recognize

A class name alone doesn't always tell the AI exactly what you want. You can spell out the rules, or just chat with the AI:

1. Click **Recognition rules** next to the "AI assist" title to open the recognition rules panel on the right.
2. **Chat with AI**: describe in plain words how to recognize things, e.g. "a helmet with the strap undone still counts as no helmet", "reflective vests don't count", "only look at the walkway in the lower half of the frame". You can also ask "why wasn't the person on the left of this image recognized?"
   - **Attach the current image** is checked by default, and the AI tries recognizing this image with the new rules.
   - After the AI replies, if it suggests updating the rules, you'll see "AI suggests updating rules" with the details. They're only saved when you click **Apply these rules**.
   - If the trial recognition found something, click **Add the N trial boxes to this image** to use them directly as pre-labels.
   - `Ctrl+Enter` sends. Each message uses Xuntong AI quota.
3. **Current rules**: you can edit the **Overall rules** (apply to all classes) and the **Recognition notes per class** directly, then click **Save rules**.
4. From then on, pre-labeling with Xuntong AI "Recognize by project classes" follows these rules.
5. (Optional) At the bottom of "Current rules", click **Sync to Xuntong platform** to store the classes and rules on the Xuntong platform. They're **disabled** by default, so the platform's current recognition is unaffected. Once bound, every time you save or apply rules the content syncs automatically (it won't change the on/off state or the scenes you set in the Xuntong console).
6. To make the Xuntong platform's own recognition (snapshot assistant, alert push) report only the classes you want, turn on **Use these rules for platform recognition**. Note: once on, recognition for your whole Xuntong account follows this project's classes; the scenes it applies to can be adjusted under "Recognition rules" in the Xuntong console. To stop syncing, click **Unbind** (the rules on the platform are not deleted). Each Xuntong account can have up to 20 rule sets.

Limits: recognize by project classes supports up to 30 classes, with class names of at most 30 characters; overall rules can be up to 1000 characters, and each class's recognition notes up to 500 characters.

During collaboration, members can also open recognition rules and chat with the AI (using the host's quota, if the host has enabled AI assist); whether they can edit the rules follows the "Members can add and edit classes" switch.

### 6.5 Check the AI results

Boxes and polygons added by AI are shown as **dashed lines**. Go through them: delete the wrong ones, drag the off ones into place, add what was missed, then press **Enter** (Done & next).

## 7. Health check

Click **Health check** on the left to find problems in your data in one go.

1. Choose how to check:
   - If you have a trained model: choose "Check with model: <model name> · mAP50 …" to run the rule checks and the model checks together;
   - If you have no model: choose "Rule checks only (no model)".
2. Click **Start health check**. Progress is shown by stage: "Duplicate check: computing fingerprints" → "Duplicate check: comparing pairs" → "Model check". With many images it takes a few minutes; you can click **Stop** (results of a stopped run aren't saved). If you leave the Health check page and come back, you can still see the progress of a check that's running. Image fingerprints are cached, so next time only newly added images are computed.
3. Results are grouped by problem:

   | Problem | Meaning | Needs a model |
   |---|---|---|
   | Possibly unlabeled | The model is confident there's an object here, but it isn't annotated | Yes |
   | Possibly wrong class | The box position matches, but the class differs from the model's prediction | Yes |
   | Inaccurate box | Same class, but the box overlaps poorly with the model's prediction | Yes |
   | Possibly extra box | There's a box, but the model sees nothing at this location | Yes |
   | Tiny box | Short side under 8 pixels; the model can barely learn from it | No |
   | Duplicate box | Two boxes of the same class in one image almost completely overlap | No |
   | Duplicate images | Nearly identical images, which inflate evaluation results | No |
   | No class | Boxes without a class aren't used in training | No |

4. For each issue you can:
   - **Fix**: jump to the Annotate page with this box highlighted;
   - **Add as annotation**: for a possibly unlabeled object, add a box based on the model's prediction directly;
   - **Not an issue**: ignore it, and future health checks won't flag it again.
   When one kind of issue has many entries, use **Add all as annotations** (possibly unlabeled) or **Ignore all** to handle them in one go. Ignored issues can be brought back by clicking "Ignored N items · Restore".
5. Images you fixed on the Annotate page are marked "Edited" and collapsed by default when you come back to the health check page, so you don't need to run the health check again.
6. Duplicate images are shown in groups, and each image shows its status and number of annotations. The one with the green border is kept; by default it's the one with the most complete annotations (Approved > Labeled > more annotations). Click another image to switch, or double-click to view it on the Annotate page. Click **Keep one per group** to delete the rest; images with annotations won't be deleted by mistake.
7. Further down the page are the **Class distribution** (boxes · images) and the **Box size distribution**. If a class has too few annotations or boxes are too small, you'll get suggestions. Classification projects are only checked for possibly wrong class and duplicate images.

## 8. Dataset versions

Save your data at a point in time as a snapshot, so you can compare and roll back.

1. On the **Data** page, click **Manage → Dataset versions (snapshot, compare, restore)**.
2. Fill in a **Version name** (e.g. v1, added night images) and a **Note** (optional), then click **Save current data as new version**.
   - A version stores the currently labeled images (with team collaboration, the pending review and approved ones) and annotations, plus the train / val / test split.
3. Each row in the version list lets you:
   - **Compare with current data**: see added images, removed images, images with changed annotations, and how the annotation count of each class has changed;
   - **Export this version**;
   - **Restore to this version**: before restoring, the current data is saved automatically as an "Auto backup before restore" version, so you can always go back;
   - **Rename, edit note**, **Delete this version** (only deletes the snapshot; current data and trained models are not affected).
4. Under "Training data" on the **Train** page, you can choose a version to train on (see 10.1).

## 9. Team collaboration

When there are too many images for one person, there are two ways to share the work:

- **Live collaboration**: several people annotate the same project at the same time. Your computer is the host; members open an address in a browser, sign in and start annotating, and changes sync in real time. Works on a LAN or over the internet.
- **Offline packages**: when there's no network, or data can't leave the company, split the images into annotation packages, copy them to other people, and merge them back when they're done (see 9.10).

### 9.1 Start live collaboration

1. Click **Collaborate** on the left.
2. First add members under "Members": enter a **Name** (used to sign in) and choose a **Role**. A random password is generated by default (you can change it). Click **Add**. Copy the account and password shown and send them to the member (they're only shown this once; if forgotten, use **Reset password**).
   - **Annotator**: can only see and edit images assigned to them;
   - **Reviewer**: can see all images and approves or rejects them;
   - You are the **Admin**.
3. Under "Sharing", choose how to share:
   - **LAN**: members are on the same company network or the same Wi-Fi as you. Fastest, and data never leaves your company.
   - **Online · Self-hosted relay**: members are on the internet (outsourcing, working from home). Requires your own cloud server running the Wulabel relay service (see the `relay/` folder in the repository for deployment instructions). Enter the **Relay URL** and **Secret**. Data only passes through your own server.
   - **Online · Xuntong official relay**: for members on the internet when you don't have your own server. Connects to Xuntong's relay server with your Xuntong API key. Images and annotations are forwarded through Xuntong's servers (forwarded only, not stored). For sensitive data, use one of the first two options.
4. Enter **Your name** (the host name members will see). The **Port** usually doesn't need changing (default 8765).
5. Options:
   - **Members can use AI assistance**: SAM smart select, model pre-labeling and text prompts all run on your computer; chatting with AI about recognition rules uses your Xuntong quota.
   - **Members can add and edit classes and recognition notes**: deleting a class removes all its annotations, so only you can do that.
   - **Overlay a watermark with the member's name on their screen**: deters leaked screenshots; good for outsourcing.
6. Click **Start collaboration**. The page shows the **LAN address** (e.g. `http://192.168.1.20:8765/`); in online mode it also shows the **Internet address** (e.g. `https://relay.example.com/s/xxxxxxxxxxxx/`). Send the address and each member's account and password to them.
   - The first time you start, Windows may show a firewall prompt. Click **Allow**.
   - While collaboration is running, you can change the three options at any time, and they take effect immediately.
   - Click **Stop collaboration** to disconnect members immediately. Saved annotations are not affected. Switching projects or closing Wulabel also stops it.

### 9.2 Assign tasks

1. Under "Assign tasks", select annotators (you can click **Select all annotators**).
2. Choose the scope:
   - **Unlabeled images not yet assigned** (most common);
   - **All unlabeled images** (reassign assigned ones too);
   - **Not yet reviewed** (unlabeled + pending review).
3. **N per person**: leave it empty to split all images in the scope evenly. Images are assigned in order, so consecutive video frames go to the same person.
4. Click **Assign**. Members' task lists refresh automatically with the new tasks.
5. The member list shows how many images each person was assigned, has submitted, and has had rejected. Click **Take back tasks** to take back the images they haven't submitted yet, so you can assign them to someone else.

### 9.3 How members annotate (in a browser)

1. Open the address from the host in Chrome or Edge, and sign in with your **Name** and **Password**. On your own computer, you can check **Keep me signed in**. No software install needed.
2. Annotators land on the Annotate page, which only shows the images assigned to them; reviewers land on the Review page (see 9.4) and can switch to **Annotate** at the top. It works the same as in Wulabel: drawing boxes, shortcuts, AI assist (if the host has enabled it). The top-right corner shows how many images you submitted today.
3. When you finish an image, click **Submit & next** (`Enter`) and wait for review. If an image really has no objects, just click Submit; it goes to pending review as a negative sample (in classification projects, you have to pick a class before you can submit).
4. Rejected images are under the **Rejected** filter, with the reason shown above the image. Fix them and submit again.
5. If someone else is working on an image, you'll see ""<name>" is annotating this image". You can only view it, and their changes show up live. Once they leave, it becomes editable automatically.
6. If the network drops, the top-right corner shows "Live connection lost, reconnecting". It continues automatically once the connection is back, and nothing already saved is lost.

### 9.4 Review

With team collaboration, image statuses go like this: **Unlabeled** → **Pending review** once the annotator submits → **Approved** once a reviewer approves; rejected images are under "Rejected". The filters and status tags on the Data, Annotate and Health check pages all use these names. When you annotate on your own there is no review step, so images just show "Labeled".

There's a separate **Review** page for this, which only appears with team collaboration (when you've added members or live collaboration is running):

- You (admin): the left navigation gets a **Review** item, and the number next to it is how many images are pending review. Once you stop collaboration and remove all members, it disappears automatically.
- Reviewers (in a browser): after signing in they land on the Review page by default, and can switch between **Review / Annotate** at the top.
- Annotators don't see the Review page.

**Filters**

1. **Members**: the top row shows each member, with their pending review count and approval rate (approvals ÷ times reviewed); an approval rate below 80% is shown in yellow. Click a person to see only their images, or click **All members** to see everyone's.
2. **Status**: you can pick more than one; by default only **Pending review** is shown. You can also look at Approved, Rejected, Unlabeled and Skipped images.
3. **Search file name**: type part of a file name.
4. **Sort**: by submit time (newest first) or by file name.
5. **More filters**: only images with a certain class, only images with no objects (negative samples), only previously rejected images; you can also change the size of the images in the grid. **Clear filters** restores the defaults.

**Batch review (grid)**

1. Each image in the grid shows its boxes, polygons or keypoints (classification projects show the class name). Below each image are the file name, annotator, count per class and submit time; images that were rejected before are tagged "Rejected before".
2. Click an image to select it; hold `Shift` and click another to select both and everything in between. You can also click **Select all on page**, or **Select all filtered** (including later pages; handy for "approve all of Alice's pending images").
3. Click **Approve**: the selected images become "Approved".
4. Click **Reject…**: check the common reasons (Missed objects, Inaccurate box, Wrong class, Extra annotations, Wrong keypoints), or describe what needs fixing. These images all get the same reason, and each one goes back to "Rejected" for its original annotator.
5. Images someone is editing right now, and images that aren't pending review, are skipped automatically; the message tells you how many were skipped.
6. Clicked the wrong thing: **Undo** in the message works for 10 seconds and restores this batch of images to how they were (images someone else changed in the meantime are left alone).
7. To take a closer look at an image: select it and press **Space** to enlarge it, use the left and right arrow keys to flip through images, and press Space again to close.

**One-by-one review**

1. Double-click an image, or click **One by one**, to go through large images one at a time. On the right are the annotator, submit time, whether it was rejected before, and how many objects of each class were annotated.
2. If it's fine, click **Approve** (`A`) and it moves to the next image automatically; if not, click **Reject** (`R`).
3. To fix it yourself: click **Edit it yourself** (`E`). This takes the current batch of images to the Annotate page; when you're done, click **Back to review** on the Annotate page to come back, with your filters and position kept.
4. Click **Back to grid** (`Esc`).

**Spot check**

When a member has a lot of images, you don't have to look at every one:

1. Click **Spot check…**, choose the member and the ratio (Sample 10% / 20% / 50%), and click **Start spot check**.
2. Wulabel randomly picks that many of their pending images, and you review them one by one (same as above).
3. When you're done, it shows the pass rate. If the pass rate is high, click **Approve the other N**; if it's low, click **Reject the other N**, with the reason "Failed spot check. Please check your work and resubmit". You can also leave them for now.

You can still filter by **Pending review** on the Annotate page as before, go through the images one by one, and click **Approve & next** (`Enter`) or **Reject**.

### 9.5 Progress, workload and activity

- **Online**: the member list shows who's online and which image they're viewing; click to jump there. In an annotator's row, click **View their images** to go straight to their pending images on the Review page. A green dot on "Collaborate" in the left navigation means collaboration is running.
- **Progress and workload**: for Today / Last 7 days / Last 30 days / All, it shows each person's submitted images, objects annotated, approvals and rejections, approval rate, reviews, and active time (adding up gaps of no more than 5 minutes between actions). Click **Export CSV** and open it in Excel, which makes per-piece billing for outsourcing easy.
- **Activity log**: who signed in, submitted, reviewed, rejected, changed classes or assigned tasks, and when. Click an image number to jump to it. Check **Include every autosave** for more detail.

### 9.6 Choosing a sharing method

| | LAN | Online · Self-hosted relay | Online · Xuntong official relay |
|---|---|---|---|
| Good for | Same company network, same Wi-Fi | Outsourcing, working from home, with your own cloud server | Outsourcing, working from home, no server |
| Address members open | `http://<your-computer-IP>:8765/` | `https://<your-relay>/s/<id>/` | `https://xuntongai.com/wulabel-relay/s/<id>/` |
| Speed | Fastest | Depends on server bandwidth | Depends on Xuntong server bandwidth |
| Data passes through | Company intranet only | Your own server (forwarded only, not stored) | Xuntong's servers (forwarded only, not stored) |
| What you need | Nothing | A cloud server with the relay service installed per `relay/README.md` | A Xuntong AI account (sign in under Settings) |

- With all three methods, images and annotations are stored only on your computer; the relay server just forwards them.
- The share ID for online modes stays the same: next time you start, it's the same address, so members only need to bookmark it once.
- Your computer must stay on, with Wulabel collaboration running, for members to connect; if your computer goes to sleep, members will see "The host's Wulabel is offline right now". Consider turning off automatic sleep in your power settings.

### 9.8 A complete example

Say an outsourcing team labels 2,000 waste sorting images and your own team reviews them:

1. **Prepare**: create a detection project in Wulabel, import the 2,000 images, and add the classes on the right (Recyclables, Food waste, Hazardous waste, Other waste). You can first batch pre-label them with a Xuntong AI dedicated model (see 16.4), so annotators only need to fix mistakes, which is much faster.
2. **Add members**: on the "Collaborate" page, add 3 annotators (Alice, Bob and Carol from the outsourcing team) and 1 reviewer (Chris from your own team), and send each of them their account and password.
3. **Start collaboration**: choose "Online · Xuntong official relay" (or a self-hosted relay), check "Watermark", start it, and send the internet address to all 4 people.
4. **Assign**: select all annotators, scope "Unlabeled images not yet assigned", leave the per-person count empty, and click Assign. Each person gets about 666 images.
5. **Annotate**: annotators open the address in a browser and sign in. They only see their own images, and press `Enter` to submit each one when done.
6. **Review**: Chris opens the Review page and clicks the member "Alice" to scan all of Alice's pending images in the grid at a glance. Select all the good ones and click "Approve"; check the ones with problems, click "Reject", check "Missed objects" and write "There's another bottle in the bottom-right corner". The rejected images go back to "Rejected" for the original annotator, who fixes them and submits again. When there are too many images, use "Spot check" to sample 20%, and if the pass rate is high, approve the rest together.
7. **Track progress**: on the "Collaborate" page you can see who's online, who's fast and who gets rejected a lot. If someone falls behind, use "Take back tasks" to take back their unfinished images and assign them to someone else.
8. **Settle up**: under "Progress and workload", choose a time period, click "Export CSV", and pay the outsourcing team based on submitted images and approval rate.
9. **Wrap up**: once everything is approved, stop collaboration and go back to training, evaluating and deploying in Wulabel as usual.

### 9.9 FAQ

- **A member can't open the LAN address**:
  - Make sure they're on the same network as you (the same company network or Wi-Fi; guest networks usually don't work);
  - The first time you start, click "Allow" on the Windows Firewall prompt. If you clicked "Cancel", go to "Windows Security → Firewall & network protection → Allow an app through firewall" and check Wulabel;
  - If the port is in use, switch to another, e.g. 8766.
- **A member sees "The host's Wulabel is offline right now"**: your Wulabel isn't running collaboration, your computer went to sleep, or the network is down. Start it again and ask them to refresh the page.
- **The internet address keeps showing "Connecting to relay server…"**:
  - Self-hosted relay: check that the address and secret match what you used when deploying;
  - Official relay: make sure you're signed in to your Xuntong AI account.
- **A member sees "This image isn't assigned to you"**: annotators can only open images assigned to them. Have the admin assign the image to them, or let someone else annotate it.
- **Two people want to edit the same image at once**: not possible; whoever opens it second gets read-only access. Once the first person moves to the next image, it can be edited.
- **Batch approve says some images were skipped**: images someone is editing right now, or that are no longer pending review, aren't included in batch actions. Wait until they've finished and submitted, then review them.
- **If a member loses their connection, is their work lost?**: nothing saved is lost (every change is saved to your computer automatically). Once the network is back, the page reconnects automatically.
- **Can members annotate on a phone?**: they can open and view, but a computer is still recommended for drawing boxes.
- **How many people at most?**: there's no hard limit; a dozen or so people annotating at once is fine. With many people, keep your computer on and your network stable.
- **What happens when I stop collaboration or close Wulabel?**: members are disconnected immediately and see "The host has stopped collaboration"; all saved annotations are kept. Next time you start it, they can refresh the page and continue.
- **Switched projects**: collaboration stops automatically. Collaboration applies to the project that's currently open.

### 9.10 Offline packages

Use this when there's no network or data can't leave the company. Each package is a standalone Wulabel project that you copy to someone to annotate, then merge back when they're done.

**Split into packages:**

1. On the **Data** page, click **Manage → Team collaboration (split into packages, merge back)** and switch to **Split into packages**.
2. **Save to**: choose a folder where the annotation packages will be created.
3. Enter the **Annotators**, one per line (or separated by commas), e.g. "Alice", "Bob". One package is created per person.
4. Choose the scope: **Unlabeled images only** / **Not yet reviewed** (unlabeled + pending review) / **All** (except skipped).
5. Check **Include existing annotations**: for images pre-labeled by a model, annotators can correct them, which is faster.
6. (Optional) Check **Anonymize images** to anonymize faces, license plates and other private areas before sending (see 13.2).
7. Click **Split into N packages**. When it's done, the destination folder opens automatically. Copy each package folder to the right person, who uses **Open project** in Wulabel to start annotating.

**Merge back:**

1. Copy the finished package folders back.
2. Open **Team collaboration** and switch to **Merge back** (or click **Merge** for that package directly in the "Packages sent out" list).
3. Select the package folder. Options: **On conflict, overwrite with the package version** (images that were also changed in the original project after splitting are not overwritten by default), **Also import images the annotator added to the package**.
4. Click **Merge**; the merge progress is shown below. The result shows how many images were merged, how many were unchanged, how many were added, and how many conflicts there were. If there are conflicts, click **Review one by one**.

## 10. Train

Click **Train** on the left. Before your first training run, install the training environment (see Chapter 2). If it isn't installed, the page shows **Install**.

### 10.1 Set training parameters

The top of the page shows the number of "Trainable images" (labeled images; with team collaboration, pending review + approved). Images that haven't been split yet are split 8:2 into the training and validation sets automatically when training starts. Images that have already been split stay where they are, so you can compare training runs directly.

Click **View and adjust** next to "Trainable images" to see which set each image is in:

- **Training set**: the model learns from these images;
- **Val set**: not used for learning; after each epoch the model is evaluated on it, and the best epoch is saved;
- **Test set**: not used at all during training. After training, it's scored separately on the "Evaluate" page, which is the closest to how the model will perform once deployed.

In the dialog, click images to select them (double-click to open them for annotation), then click **Move to training set / Move to val set / Move to test set** to adjust by hand. Below, you can change the training / validation / test ratios, then click **Assign the N unassigned images now** or **Re-split all** (the previous split is reshuffled, so earlier and later training runs can't be compared directly). If the training set ends up empty, you'll be warned and training can't start.

| Option | Description |
|---|---|
| Starting point | Default is "Start from pretrained weights (from scratch)". After adding new data, you can choose "Continue from "<run>"", which is faster and more stable than training from scratch. If the classes have changed, the classification part is relearned. |
| Model | The dropdown lists models by project task: built-in models, Ultralytics models such as YOLO11 / YOLO26 / YOLOv8 (see 10.7), and at the end "Enter a model name…" and "Local model file…". You can type a name to search. The one marked "Recommended" is based on this computer: for detection projects, YOLOX-Tiny without a dedicated GPU, YOLOX-S with 4 GB+ VRAM, YOLOX-M with 8 GB+, and YOLOX-S on Mac; for segmentation projects, YOLO11 Segmentation (S with 4 GB+ VRAM or on Mac, otherwise N). New detection projects default to YOLOX-S, and new segmentation projects to YOLO11-S Segmentation. When continuing training, that run's model is reused. |
| Epochs | The less data you have, the more epochs you need; usually 20–50. |
| Input size | Use a larger size for small objects (distant people, hard hats); it will be slower. Classification usually uses 224. |
| Batch size | Lower it if you get out-of-memory errors. For Ultralytics models you can enter 0 to pick it automatically based on GPU memory. |
| Training data | "Current data" or a dataset version. |
| Device | "Auto (use GPU if available)" or "CPU only". |
| Use approved images only | Only with team collaboration: when checked, only "Approved" images are used for training; images pending review are left out this time. |

Input size, batch size, augmentation, device and "Use approved images only" (only with team collaboration) are under "Advanced settings", collapsed by default. Click "Advanced settings" to expand it; the app remembers whether you last left it expanded or collapsed.

If GPU memory runs out during training (from v0.4.2), the app automatically halves the batch size and restarts training from the beginning, down to a minimum of 1. You'll see a one-time notice, and the training run also records "Batch size 2 (reduced from 8 automatically due to low GPU memory)". Smaller batch sizes train more slowly; if memory is really tight, you can also switch to a smaller model or reduce the input size.

Available models:

| Task | Model | Notes |
|---|---|---|
| Detection | YOLOX-Nano | The lightest of the YOLO family, for CPUs, phones and very weak edge devices; 416 input by default |
| Detection | YOLOX-Tiny | Very light, for real-time inference on CPUs and NPU edge boxes; 416 input by default |
| Detection | YOLOX-S | Best balance of speed and accuracy; start with this for most projects |
| Detection | YOLOX-M | Higher accuracy; 6 GB+ VRAM recommended |
| Detection | YOLOX-L | Highest accuracy, slowest; 8 GB+ VRAM recommended |
| Detection | Faster R-CNN MobileNetV3 | Fast with low GPU memory use; good for beginners and computers without a dedicated GPU |
| Detection | Faster R-CNN ResNet50 | Higher accuracy, slower; 6 GB+ VRAM recommended |
| Detection | RetinaNet | Single-stage, accuracy close to Faster R-CNN, converts to TensorRT more smoothly |
| Detection | FCOS | Single-stage, anchor-free, simple structure; good for deployment |
| Detection | SSDLite | Single-stage, very light, for CPUs and NPU edge devices; fixed 320 input, so-so on small objects |
| Segmentation | Mask R-CNN | Instance segmentation; 6 GB+ VRAM recommended |
| Keypoints | Keypoint R-CNN | Uses COCO pretraining for 17-point human pose |
| Classification | MobileNetV3 / EfficientNet-B0 / ResNet50 | From light and fast to more accurate |
| Detection, segmentation, keypoints, classification | YOLO11, YOLO26, YOLOv8 (N / S / M / L / X) | Ultralytics models, available for all four tasks; see 10.7 |

### 10.2 YOLOX models

YOLOX is a YOLO-family detection model open-sourced by Megvii (Apache-2.0, safe for commercial use), from the same family as the dedicated models on the Xuntong AI platform.

- **Pretrained weights**: the official COCO pretrained weights are downloaded automatically on your first training run (Nano about 8 MB, S about 70 MB, L about 430 MB), first from the official website and then from GitHub if that fails. Once downloaded, they don't need to be downloaded again.
- **Augmentation**: uses the official YOLOX recipe. Mosaic, MixUp, random scaling and rotation, color jitter, horizontal flip and multi-scale training are all turned on automatically, and strong augmentation is turned off for roughly the last 10% of epochs to finish up. That's why the "Augmentation" settings below aren't shown when YOLOX is selected.
- **Epochs**: YOLOX needs somewhat more epochs than Faster R-CNN; 50+ is recommended, or around 100 with little data (a few hundred images).
- **Learning rate**: scaled automatically by batch size. There's nothing to set.
- **Input size**: Nano and Tiny default to 416; S, M and L default to 640. You can change it; it's rounded to a multiple of 32.
- **YOLOX or YOLOv8 / 11**: you can train both. YOLOX is licensed under Apache-2.0, the same as Wulabel, so the models you train can go into any product and can be uploaded to Xuntong. YOLOv8 / 11 and other Ultralytics models are AGPL-3.0: personal and internal company use is unrestricted, but putting them into a closed-source product you sell requires buying a license from Ultralytics; see 10.7.

Trained YOLOX models work like any other model: evaluation, model pre-labeling, false-positive tests, live test, export for deployment, and uploading to Xuntong are all supported.

### 10.3 Augmentation

Randomly altering images during training shows the model more variety, which helps noticeably when you have little data.

1. Under "Augmentation", choose a preset: **Off**, **Default**, **Light**, **Standard**, **Strong (for small datasets)**.
2. To fine-tune, expand it and change **Horizontal flip**, **Vertical flip**, **Brightness**, **Contrast**, **Saturation**, **Hue**, **Blurry** (simulates out-of-focus and motion blur), **Noise** (simulates low-light night shots), **Multi-scale** (helps with objects whose size varies a lot with distance), **Rotation**, **Random crop**. Once you change anything, the preset shows "Custom".
3. Click **Preview** to see a few images after random augmentation (each image is randomly altered twice, and the red boxes are the annotations following the transforms), to make sure it isn't too extreme.

### 10.4 Start training and watch progress

1. Before you start, check "~N steps per epoch · ~M total" above the button. If there are too few images (fewer than 20 in the training set) or too few total steps (fewer than about 300), clicking **Start training** first shows a warning: training like this will most likely learn nothing, and the metrics may stay at 0. Label more images, or increase the epochs as suggested; with very little data you can also start with Faster R-CNN MobileNetV3. If you really just want to try it, click **Start anyway**. You'll also be warned when the val set has only one or two images: the metrics will swing a lot and can't be trusted. If a class has too few annotations (fewer than 20 images for classification, or fewer than 30 boxes for the other tasks), those classes are listed above the button and you'll be warned before training starts: the model will struggle to learn them and may miss them. If you can't get enough, delete the class on the Annotate page and merge its annotations into a similar class. Annotated images whose labels are all unedited pre-labels are also flagged above the button; click **Review them** to go through just those images. If they make up 30% or more, you'll be warned before training starts: if they were confirmed without a close look, the model learns its own mistakes and drifts further with each training. Once you've checked them, click **All checked** to stop the reminder.
2. Click **Start training**. The training data is prepared first (with many images, "Preparing training data N/M" is shown below the button). The first time you use a model, its pretrained weights are downloaded: the Train page shows "Downloading pretrained weights <file name>: downloaded / total MB · speed", and there's also a progress bar in the bottom-right corner. If the network drops, the download resumes, and once downloaded it never needs downloading again.
3. During training it shows "Epoch N / M · progress in this epoch · loss · ETA", with the **Loss** curve, the **Val set** metric curves and the **Log** below.
   - "Key info" above the log always shows the first few lines of the log: the device used, the number of images in the training and val sets, and whether the pretrained weights were loaded. Error and warning lines are highlighted in yellow.
   - Scrolling up in the log won't pull you back to the bottom; when you're at the bottom, it follows new lines.
   - If the pretrained weights couldn't be downloaded (usually a network problem), or the metrics stay at 0 for 10 epochs in a row, a yellow banner appears at the top of the page with the likely cause and what to do.
4. To finish early, click **Stop** and confirm; it stops after the current batch finishes. The finished epochs and the best model so far are both kept.
   - If you close the app while training is still running, it first asks you to confirm ("Training isn't finished. Closing the app will interrupt it"), so you don't close it by mistake.
5. **Resume from a checkpoint**: after training is stopped, the app is closed, or an error interrupts it, a **Resume training** button appears on that run. Clicking it continues on the same run from the last finished epoch through the remaining epochs, with the curves and log picking up where they left off, so you don't have to start over. When training finishes normally, the checkpoint is deleted automatically (checkpoints of large models are several hundred MB).
   - This is different from "Continue from "<run>"" under Starting point: that option uses a trained model as the starting point for a new training run, which suits retraining after you've added new data.
6. When training ends, a system notification pops up and the taskbar icon flashes (so you'll know even if the app is in the background). Inside the app, the bottom-right corner shows "Training finished" with the best metric and a rating (poor / fair / good enough):
   - If the results are fine, you can click **Evaluate** or **Pre-label** directly;
   - If the results are poor, you'll be prompted to click **See why** to go back to the Train page and take a look;
   - If training fails, you'll get a notice even when you're not on the Train page; click **View error** to see it.
7. When training fails, common errors are explained in plain words with a button to fix them: the GPU driver and PyTorch don't match (**Change PyTorch version in Settings**), not enough GPU memory or RAM (**Use CPU**), the disk is full, a network download failed, or image files can't be found (**Go to Data**). Click **Details** to expand the full error message.

### 10.5 Training runs and comparison

Each training run is saved automatically as an entry under **Training runs**, listing the time, model, data, epochs, metrics and status (Training / Done / Stopped / Failed). For each entry you can:

- **View evaluation** (opens the evaluation of this particular run), **Export ONNX** (built-in models only, with progress shown while exporting; Ultralytics models and external models are already ONNX), **Open training folder**, or delete it. Runs still in training can't be evaluated or deployed until they finish.
- Runs that were stopped, interrupted or failed have **Resume training** (see 10.4).

**Bulk delete**: check several entries in Training runs, click **Delete selected (N)**, and confirm to delete them all at once (the model files, logs and the copy of the dataset used for those runs are all deleted, and this can't be undone). Runs still in training can't be selected.

**Compare training runs**:

1. In Training runs, **check two or more** runs (up to 8 can be compared at once).
2. Click **Compare selected (N)**.
3. The comparison window shows the parameters and data side by side (differences in bold), each metric, and the loss curves overlaid, and marks the best run for each class.

### 10.6 Import an external model

Models trained elsewhere (e.g. Ultralytics YOLO) can be exported to ONNX and imported here, then used just like trained models for pre-labeling, health checks, evaluation, false-positive tests, live test and deployment (export, inference service package). Detection, segmentation, keypoint and classification projects are all supported (from v0.6.5; before that, only detection, without deployment). The model's task must match the project's. Imported models can't be trained further (to continue training, choose the .pt via "Local model file…" in 10.7).

1. Click **Import external model** above Training runs.
2. Click **Select .onnx file**.
3. The app detects automatically:
   - **Task** and **Format**: YOLOv8 / v11 (Ultralytics, including segmentation, keypoint and classification), YOLOv5 / v7, YOLOv10 and other end-to-end models, YOLOX, RT-DETR, DETR / RF-DETR, and models exported from Wulabel. If the format is detected wrong, change it manually;
   - **Input size**;
   - **Class names** (one per line, in the model's order). Rename the model's class names to your project's class names to map them, e.g. change "person" to your project's "Person" class.
4. **Classes to use**: unchecked classes are skipped during pre-labeling; classes matching project class names are checked by default.
5. Click **Import**. A new "… (external)" entry appears in Training runs.

### 10.7 Train with Ultralytics models such as YOLOv8 / YOLO11

From v0.6.5, besides the built-in models, you can train Ultralytics models right in Wulabel, without leaving the app.

**Which models you can choose**

- The model dropdown lists them by series: YOLO11, YOLO26, YOLOv8 (detection, segmentation, keypoints and classification, each in five sizes N / S / M / L / X); YOLO12, YOLOv10, YOLOv5u, RT-DETR (detection); YOLOv9 (detection; sizes C and E also have segmentation). In a segmentation project the names read like "YOLO11-S Segmentation", and only models for that task are listed.
- **Enter a model name…**: for models not in the list, any name Ultralytics recognizes works, e.g. `yolo11x-seg.pt`, `yolo12m.pt`. You can also enter a structure file name to train from scratch, e.g. `yolo11s.yaml`. Names with -seg, -pose or -cls are segmentation, keypoint and classification models.
- **Local model file…**: choose a `.pt` you trained before to keep training it (further training), or a `.yaml` structure file to train from scratch. If the task doesn't match (e.g. a detection model in a segmentation project), you'll be told after training starts.
- Not available for multi-label classification projects (Ultralytics classification models only support single-label).

**First use**

When you click **Start training**, the app first installs the Ultralytics component automatically (the bottom-right corner shows "Installing component" progress; this happens only once), then downloads the official pretrained weights (also with progress in the bottom-right corner; once downloaded, they don't need to be downloaded again). If the download fails, you can download the weights file yourself and choose it via "Local model file…".

**Parameters**

- Epochs: around 100 is recommended for Ultralytics models. When you switch from a built-in model and the epochs are below 50, they're changed to 100 automatically.
- Batch size: you can enter 0 to pick it automatically based on GPU memory. If GPU memory runs out, it works like the built-in models: the batch size is halved and training restarts from the beginning.
- Augmentation: Ultralytics' own augmentation is used (Mosaic, random scaling and translation, color jitter, horizontal flip, etc.), so the built-in "Augmentation" settings aren't shown.
- **More parameters** (under Advanced settings): one `key=value` per line, passed to Ultralytics training as is, e.g. `cos_lr=True`, `patience=30`, `optimizer=AdamW`, `mosaic=0.5`. "Parameter docs" next to it opens the official documentation. Data and output locations are managed by the app; setting them here has no effect.

**During and after training**

- Progress, loss and metric curves, the log, stopping, and resuming from a checkpoint all work the same as for built-in models.
- When training finishes, the model is exported to ONNX automatically and Wulabel's own evaluation runs on the val and test sets, so metrics, errors and recommended thresholds use the same algorithms as for built-in models and can be compared side by side. As with built-in models, metrics for segmentation and keypoint models are computed on boxes.
- After that, pre-labeling, health checks, batch recognition, false-positive tests, live test, export (ONNX, OpenVINO, TensorRT / RKNN conversion packages) and inference service packages all work directly.
- Under Starting point you can choose "Continue from "<run>"": it lists earlier Ultralytics runs in this project. If the classes have changed, the output layer is replaced automatically.
- They can't be uploaded to the Xuntong platform yet (Xuntong currently only supports detection models trained with the built-in models).

**License**

Ultralytics models are licensed under AGPL-3.0: personal and internal company use is unrestricted; if you put a trained model into a **closed-source product you sell**, Ultralytics requires an enterprise license. Wulabel doesn't include any Ultralytics code; it's installed from PyPI only when you choose an Ultralytics model, and Wulabel itself remains Apache-2.0. For commercial use with no concerns at all, choose a built-in model (YOLOX, etc.).

## 11. Evaluate

Click **Evaluate** on the left and choose a training run (if you came from "View evaluation" on the Train page, that run is already selected). Runs still in training show "Training" and can only be chosen once they finish.

### 11.1 Metrics

- The top says which epoch's best model this evaluation uses. You can switch between the **Val set** and the **Test set**.
- The very first line is the **Verdict**: a rating of "poor / fair / good enough" based on the main metric (detection-type projects use mAP50: below 0.3 is poor, 0.3–0.6 fair, above 0.6 good enough; classification uses accuracy: below 0.6 is poor, 0.6–0.85 fair, above 0.85 good enough), and it points out the **worst class**. Next to it are buttons for the next step: view the missed-detection errors, send the errors to annotation, add data and retrain / switch to a bigger model; when the results are good enough, there's **Go to deployment**. If fewer than 10 images were evaluated, you'll be warned that the metrics fluctuate a lot.
- Detection, segmentation and keypoint projects: **mAP50** (the most common detection metric), **mAP50-95** (demands more accurate boxes), **Precision** (the share of predicted boxes that are correct; low means many false positives), **Recall** (the share of real objects that are found; low means many missed detections). Segmentation and keypoints are computed on bounding boxes.
- Classification projects: **Accuracy**, **Macro F1**, mean precision, mean recall.
- Hover over a metric for an explanation.
- **Per class** table: each class's image count, GT box count and metrics.

### 11.2 Confusion matrix

Rows are actual classes, columns are model predictions. The diagonal is correct; other cells are one class mistaken for another. The last column "Background" is missed detections, and the last row "Background" is false positives. Hover to see the exact numbers.

### 11.3 Errors

- Lists the images with problems. You can filter by **Missed**, **False positive** and **Wrong class**.
- **Click an error** to jump straight to the Annotate page to check and fix it. Fix, retrain, and the loop is closed.

### 11.4 Confidence threshold

Which threshold to alert at when deployed? Look here:

1. The app recommends the threshold with the highest F1 and shows the precision and recall at that threshold.
2. The curves show how precision, recall and F1 change with the threshold. **Drag the slider** to see results at different thresholds: how many correct, how many false positives, how many missed.
3. How to choose: too many false positives, raise the threshold; too many missed detections, lower it.
4. The table below shows the **recommended threshold per class**.
5. The recommended threshold is carried over automatically to the live test and the inference service package on the "Deploy" page as the default confidence threshold.

### 11.5 Evaluate with current data

After adding data or fixing annotations, you don't need to retrain. Click **Evaluate with current data** to recompute the metrics with the current annotated data (val set / test set); the screen shows "Evaluating val set: N/M images". Imported external models are evaluated this way too.

### 11.6 False-positive test

Use a video that **shouldn't trigger alerts** (no objects, or only things that are easy to mistake, such as an empty walkway or a factory at night) to test how many false alarms the model raises:

1. Under "False-positive test", click **Choose video file**, or enter an `rtsp://` / `http(s)://` address.
2. Settings: **Detect N frames/s**, **Alert after N consecutive detections**, **Test for N minutes** (for video streams).
3. Click **Start test**. You can click **Stop early** at any time.
4. Results: how long it ran, how many alerts, and the **Per hour** rate, broken down by class; below are the **False-positive frames** (red boxes are what the model reported; only the latest 60 are kept).
5. Click **Add these frames to the dataset as negative samples**: they're added as "No objects" images, so the next training run learns not to alert on scenes like these. If any of them contain real objects, annotate them on the Annotate page after adding.

### 11.7 Export a delivery report

1. Click **Export report** and choose where to save it (default file name "<project>_<run>_model_report.html").
2. The report is a single HTML file containing the data overview, training parameters, metrics, curves, confusion matrix, errors, recommended threshold and false-positive test results. Open it directly in a browser and send it to your client for acceptance.

## 12. Model pre-labeling and picking images

### 12.1 Pre-label with your own model

1. Go to the **Annotate** page. In "AI assist" on the right, choose **My models** and pick a trained model from the drop-down (showing its name and mAP50 / accuracy).

## 13. Export datasets (with anonymization)

### 13.1 Export

1. On the **Data** page, click **Export dataset**.
2. **Format** (depends on the project task):
   - Detection: YOLO, COCO, VOC;
   - Segmentation: YOLO-seg, COCO, VOC (bounding boxes only);
   - Keypoints: YOLO-pose, COCO keypoints, VOC (object boxes only);
   - Classification: class folders (`train/<class>/<image>.jpg`).
3. **Scope**: unlabeled and skipped images are not exported; images marked "No objects" are exported as negative samples. With team collaboration, you can also check **Export approved images only**.
4. **Train / Val / Test ratio (%)**: images not yet split are assigned by these ratios. To redo the whole split, click **Re-split all** (previous training results won't be directly comparable with the new split).
5. **Export to**: click **Browse** to choose a location. The **Folder name** is generated automatically and can be changed (once you change it, switching formats won't overwrite it).
6. Click **Export**. When it's done, it shows how many images and annotations were exported and how many went into each split; click **Open folder** to view them.

To export a dataset version: click **Export this version** in the dataset version list. The split is fixed to the one stored in the version.

### 13.2 Anonymization

When exporting a dataset, exporting a version, or splitting into packages, you can check **Anonymize images**:

1. **By class**: choose the classes to anonymize from the drop-down, e.g. the "Face" and "License plate" classes you labeled. Classes with "face" or "plate" in their name are selected by default.
2. **Auto-detect**: check **Auto-detect faces** and **Auto-detect license plates**, and the app finds them with an open-vocabulary detection model (the model is downloaded the first time; much faster with a GPU).
3. **Method**: **Mosaic**, **Blurry** (blur), **Black out**.
4. The export shows an extra "Anonymize" stage in its progress.

Anonymization only changes the exported copies; the original images in the project are untouched. Auto-detection may miss very small faces, side profiles and distant objects, so spot-check important data.

## 14. Deploy

Click **Deploy** on the left and choose a trained model. The page has five tabs: **Live test**, **Batch recognition**, **Export model**, **Inference service package**, **Field data loop**.

### 14.1 Live test

Connect a camera or a video and see how the model performs in the real world:

1. Choose **Video streams** or **Local video**.
2. Enter the stream address: an RTSP camera (e.g. `rtsp://admin:password@192.168.1.64:554/Streaming/Channels/101`), or an HTTP-FLV, HLS (m3u8) or MP4-over-http address. You can also click **Choose video file**.
3. Click **Start**. While starting up it shows "Preparing the runtime environment…", "Loading model…" and "Connecting to the video source…" in turn. Once the video appears, results are drawn on it in real time: boxes for detection models, outlines for segmentation models, points and skeletons for keypoint models, and the top classes in the upper-left corner for classification models. The top shows the resolution and whether inference is on the GPU or the CPU.
4. Drag the **Confidence** slider to adjust the threshold. It defaults to the recommended threshold from the Evaluate page; after changing it, click "Use recommended 0.xx" to change it back.
5. When you see missed detections or false positives, click **Add snapshot to dataset**. The image is added as "Unlabeled"; annotate it and retrain.
6. Click **Stop** to finish.

### 14.2 Export model

1. Choose formats:
   - **ONNX (dynamic size)**: a universal format; onnxruntime runs it on Windows / Linux / ARM;
   - **ONNX (fixed size)**: input fixed at [1,3,N,N], for inference frameworks that need a fixed shape;
   - **OpenVINO**: acceleration on Intel CPUs, integrated graphics and industrial PCs, converted and verified right in the app (OpenVINO is installed automatically on first use; if it can't be installed, only this format is skipped and the other formats export as usual);
   - **TensorRT conversion package**: for NVIDIA GPUs and Jetson; run the script on the target device to build the engine;
   - **RKNN conversion package**: for Rockchip RK3588 / 3568 and similar; run the script on Ubuntu to convert.
2. If you need a fixed size, set the size.
3. Choose the **Export to** location and the **Folder name**, then click **Export**. Only ONNX is checked by default. During export it shows "Step N / M" and the current format; when it's done, each format shows whether it succeeded or failed; click **Open** to view it.

The built-in Faster R-CNN is a two-stage model, and NPUs (RKNN) and older versions of TensorRT have limited support for it, so conversion may fail or run slowly. For such devices, train YOLOX or another single-stage model (RetinaNet, FCOS, SSDLite). ONNX and OpenVINO are safe to use.

When exporting YOLOX models: ONNX (dynamic size) and OpenVINO work the same as for other models, with resizing, decoding and duplicate box removal (NMS) built into the model, so they output results directly. ONNX (fixed size), TensorRT and RKNN conversion packages use the official YOLOX format (BGR input in 0–255, padded with 114 at the top left, output without NMS). All operators are plain convolutions, so NPUs and TensorRT can run the whole model; see the README in the conversion package for post-processing.

Segmentation and keypoint models (Mask R-CNN, Keypoint R-CNN) can also be exported to ONNX, OpenVINO and other formats. Segmentation models have an extra output `masks` (mask probabilities for each object; above 0.5 is the object), and keypoint models have extra outputs `keypoints` (x, y and visibility of each point) and `keypoints_scores`. Live test and the inference service package support detection, segmentation, keypoint and classification models.

### 14.3 Inference service package

Builds an inference service that runs as soon as you copy it to an on-site computer. Detection, segmentation, keypoint and classification models are all supported:

1. **Video streams**: enter a name and address. Click **Add stream** to add more streams. The address can be:
   - an RTSP camera: `rtsp://…`;
   - FLV / m3u8 / MP4 over http(s): `http(s)://…`;
   - a local video file: enter the file itself, e.g. `D:\test\video1.mp4`, not just a folder. Local videos loop at their original speed, and each video takes up one stream.
2. **Detection interval (s)**: how often to run detection on one frame of each stream.
3. **Alert rules**:
   - **Alert classes** (leave empty to alert on all classes);
   - **Confidence threshold** (defaults to the recommended threshold from the Evaluate page);
   - **Dedup interval (s)**: alert at most once in this period for the same class on the same stream;
   - **Active hours**: all day, or e.g. `07:00-19:00`;
   - **Save alert snapshots (with boxes)**.
4. **Alert delivery**:
   - Webhook: POST JSON to this URL on alert, optionally with **Include snapshot (base64)**;
   - MQTT: server address, topic, username, password (leave empty to disable).
5. **Service**: **HTTP API port**; **GPU inference** (the on-site computer needs onnxruntime-gpu installed, otherwise the CPU is used automatically).
6. **Field data loop**: frames the model is unsure about (confidence within the set range) are saved to the service package's `reflux/` folder.
7. Choose the **Output to** location and click **Build inference service package**. It shows "Step N / M" while building.
8. Copy the whole folder to the on-site computer: on Windows, double-click `run.bat`; on Linux, run `sh run.sh`. The configuration is in `config.json`, and instructions are in `README.md`. The on-site computer doesn't need PyTorch or a GPU; it only depends on onnxruntime, OpenCV and numpy. The first run needs Python 3.9 or later and a network connection to install these dependencies; if the installation fails halfway, it's reinstalled automatically on the next run.

### 14.4 Field data loop

1. While the service package runs on site, it saves frames the model is unsure about to the `reflux/` folder.
2. Regularly copy `reflux/` back, then on the **Field data loop** tab click **Import field images** and select that folder. Progress is shown during import, and you can stop it.
3. Click **Annotate this batch** to send only the newly imported batch to the Annotate page, pre-label with the model, then correct the results.
4. Retrain, then build a new service package to replace `model.onnx` on site. The model keeps getting better the more it's used.

### 14.5 Upload to the Xuntong AI platform

If you don't want to deploy a service yourself, upload the model to the Xuntong AI platform and connect cameras and set up alerts there (object detection models only for now):

1. First set up Xuntong AI in **Settings** (see 2.3).
2. Under "Upload to Xuntong AI platform" at the bottom of **Deploy → Export model**, adjust the **Model name** and click **Upload**. If ONNX hasn't been exported yet, it's exported automatically first.
3. After upload, the platform takes a few seconds to a minute to validate it, showing "The platform is validating it". Once validated, it changes to "Validated" (if it fails, the reason is shown). The recommended threshold from the Evaluate page is uploaded with it and becomes the default threshold on the platform.
4. Click **Open console**, go to "Custom models", and click **Enable**. Then you can connect cameras and set up alerts.
5. "Custom models on the platform" below lists the uploaded models, their validation status and whether they're enabled. Accounts without hosting can only hold 1 model; **Delete** the old one before uploading a new version.
6. Alert images generated on the platform can be fetched back for annotation (see 4.7).

### 14.6 Batch-recognize a folder

Without deploying a service, you can run the model over a whole folder of images right on your computer. For example, drop each day's return photos into one folder and have them sorted by class:

1. In **Deploy → Batch recognition**, choose the **Folder to recognize** (images in subfolders are included) and where to **Save results to**. The results folder can't be inside the folder being recognized.
2. Adjust the **Confidence threshold**. It defaults to the recommended threshold from the Evaluate page:
   - Image classification: if the best class scores below the threshold, the image is marked "Unsure" and left for a person to check;
   - Multi-label classification: every class that reaches the threshold counts; if none does, the image is marked "Unsure";
   - Detection, segmentation, keypoints: objects scoring below the threshold don't count; if none are found, the image is marked "No objects".
3. If you check **Copy into a folder per class**, images are copied into folders named after each class inside the results folder (an image with several classes is copied once per class; the originals stay untouched). Images from subfolders get the subfolder name added to the front of their file name so names don't clash.
4. Click **Start**. You can click **Stop** at any time; images already recognized are still written to the spreadsheet.
5. When it's done, it shows how many images each class has. Open "results.csv" in the results folder directly in Excel: one row per image, with the file, the result and the top score, followed by one column per class (a score for classification, the number found for detection). Images that can't be read are marked "Error".
6. If some images are "Unsure" ("No objects" for detection), click **Add the N unsure images to the project to annotate** to import them into the current project, then click **Annotate this batch** to go through just those images. Annotate them and retrain, and the model gets better the more you use it.

**Recognizing videos**: videos in the folder (mp4, mov, mkv, avi and so on) are recognized too. This works well for setups like "one folder per order number, each holding a video of the returned item":

1. Under **Video**, set **how many seconds between checked frames** (1 second by default) and **how many frames must match to count** (1 frame by default; if a single frame often gets it wrong, raise it to 2–3).
2. Each video is watched only once. The spreadsheet has one row per video, the "Folder" column shows the subfolder the video is in (such as the order number), and the result reads like "Fan blade damaged (3 frames)", meaning the class was found in that many frames.
3. A screenshot is saved for each class found (the frame with the highest score, with boxes drawn for detection models). It goes into a subfolder of the results folder named after the video's subfolder, e.g. `results/1367524416106/Fan blade damaged_00m12s_0.93.jpg`. Videos at the top level of the folder get a folder named after the video file.
4. The first time you recognize videos, ffmpeg (about 90 MB) is downloaded automatically.

### 14.7 FAQ

- **The service package log keeps showing "[Camera 1] Connection failed, retrying in 10 s"**: the address of this stream can't be opened.
  - Local video: check that you entered the full path of the video file (with an extension such as `.mp4`). Entering only a folder causes this. If the path contains non-English characters and it still won't connect, move the video to a plain English path and try again, e.g. `D:\test\1.mp4`.
  - Camera: check the username, password, IP and port, and whether the on-site computer can ping the camera. You can also try opening the same address in VLC first.
- **I want to recognize all the images or videos in a folder**: use batch recognition (14.6). Each video is watched once, and the screenshots are sorted by subfolder (such as order number). The service package is meant for long-running camera monitoring, so local videos loop by default; to play one only once, add `"loop": false` to that stream in `config.json`. To connect it to your own system, call the service package's HTTP API `POST /predict` and send the images one at a time; see `README.md` in the service package.

## 16. Xuntong AI guide

Xuntong AI ([xuntongai.com](https://xuntongai.com)) is an AI recognition platform. It has ready-made dedicated recognition models (waste sorting, hard hats, smoke and fire, etc.) and LLM recognition, and it can also host your own models, connect cameras and push alerts. With Wulabel connected to it, **annotation, training, going live and field data** form a closed loop. The earlier chapters cover its features here and there; this chapter brings them together.

Where Xuntong AI is used in Wulabel:

| Where | What it does | See |
|---|---|---|
| Settings → Xuntong AI | Sign in, check your quota | 16.1, 16.2 |
| Annotate → AI assist → Xuntong AI | Auto-label with dedicated models / LLM / project classes | 16.3–16.5 |
| Annotate → AI assist → Recognition rules | Write recognition notes, chat with AI about how to recognize, sync to the platform | 16.5 |
| Deploy → Export model → Upload to Xuntong AI platform | Put your trained model on the platform | 16.6 |
| Data → More import options → Fetch alert images from Xuntong AI | Bring on-site false positives and missed detections back for annotation | 16.7 |
| Collaborate → Online · Xuntong official relay | Let members on the internet join in | 16.8 |

### 16.1 Sign in

1. Open **Settings** and click **Sign in to Xuntong AI** in the "Xuntong AI" section.
2. Your browser opens the Xuntong AI web page:
   - Sign in first if you aren't already (the same way you normally sign in to Xuntong; verification code or SMS both work);
   - Check that the confirmation code on the page matches the one in the Wulabel dialog, then click **Allow**.
3. Back in Wulabel, after a few seconds it shows **Signed in as** with your account name and plan, remaining quota, and the recognition methods you can use.

Notes:

- No need to create and copy an API key in the console: at sign-in, the platform issues a dedicated key for this computer, named "Wulabel · <computer name>". You can see it on the "API Key" page of the Xuntong console, and disable it there too.
- Signing in again on the same computer replaces the old key automatically. Personal accounts can have up to 2 keys; when that's full, you can't click "Allow" on the web page. Disable an unused key in the console and try again.
- If the browser didn't open: click **Reopen** in the dialog, or copy the address and open it yourself. The sign-in code is valid for 10 minutes.
- **Sign out**: the key on this computer is deleted, and the key issued at sign-in is disabled on the platform.
- If you already have an API key, or your Xuntong platform is self-hosted: click **Advanced: enter an API key manually or a self-hosted platform address**.

### 16.2 Quota and cost

- The Settings page shows how much of each quota is left and when it expires: LLM recognition, dedicated model recognition, custom model recognition, add-on packs and so on, depending on your plan.
- How it's counted: recognizing one image counts as 1 image. Before batch pre-labeling, you'll see the total number of images; each round of chatting with AI about recognition rules counts as 1 image of LLM quota.
- Only your own account's quota is used; when collaboration members chat with AI, it uses the host's quota (the host can turn off "Members can use AI assistance" on the Collaborate page).
- When the quota runs out, you'll see "quota exceeded", and batch pre-labeling stops. Images already labeled are kept.

### 16.3 Choosing between the four recognition methods

Choose **Xuntong AI** in "AI assist" on the right of the Annotate page. The "Select a recognition model" drop-down has:

| Recognition method | Good for | Speed | Quota |
|---|---|---|---|
| Dedicated models (e.g. waste sorting, hard hats) | The project's classes match a ready-made platform model | **Fastest**: 8 images per batch, two batches sent at a time | Dedicated model recognition |
| Custom models you uploaded and enabled | Models you trained yourself and uploaded to the platform | Same as above | Custom model recognition |
| Recognize by project classes (recommended) | No matching model on the platform; you only want the project's few classes | One image at a time, slower | LLM recognition |
| General LLM recognition | Finding hazards by broad safety category (fire safety, electrical, sanitation, etc.) | One image at a time | LLM recognition |

It's simple: **if there's a matching dedicated model, use it** (fast and accurate); if not, use **Recognize by project classes** and write clear recognition notes for each class (16.5).

### 16.4 Batch auto-labeling with a dedicated model

Using waste sorting as an example:

1. Create a detection project and import images. You don't have to create the classes first: when the model recognizes a class name (e.g. "Recyclables") that the project doesn't have, it's created automatically.
2. Open the Annotate page, choose **Xuntong AI** in "AI assist" on the right, and choose **Waste sorting** as the model.
3. Adjust **Confidence**: start with the default; raise it if there are too many boxes, lower it if a lot is missed.
4. Press `P` first to label the current image and see how it does. If you're happy, click **Batch pre-label**. It recognizes all "Unlabeled" images that have no annotations yet, batch by batch, with a progress bar.
5. Recognized boxes are dashed (source "Xuntong"). Check each image: delete the wrong boxes, drag the off ones into place, add what was missed, and press `Enter` (Done & next).
6. To go even faster: after a few hundred images, train your own model with this data (Chapter 10) and pre-label locally from then on, without using quota.

If a batch hits "too many requests", it slows down and retries automatically without being charged twice; errors like quota exceeded or a model not enabled stop it and tell you how many images were labeled.

### 16.5 Recognize by project classes and recognition rules

When there's no matching model on the platform, use "Recognize by project classes": the platform only looks for your project's classes, with class names matched exactly, and **nothing outside the list is ever reported**. How well it works depends on how clearly you state the rules.

**Write recognition notes:**

1. Under the edit button next to a class, fill in the **Recognition notes**: what exactly this class means, and what does / doesn't count. For example:
   - No helmet: a person without a helmet on; wearing a helmet without fastening the strap also counts; box only the head and upper body.
   - E-bike: two-wheeled electric bikes and scooters; bicycles and motorcycles don't count.
2. Or click **Recognition rules** next to the "AI assist" title, and under **Current rules** edit the **Overall rules** (apply to all classes, e.g. "Only look at the walkway in the lower half of the frame; ignore posters and anything on screens") and each class's notes in one place, then click **Save rules**.

**Chat with AI:** if you're not sure how to write the rules, say it in plain words under **Recognition rules → Chat with AI**:

- "A helmet with the strap undone still counts as no helmet"
- "Reflective vests don't count as helmets"
- "Why wasn't the person on the left of this image recognized?"

The current image is attached by default, and after replying, the AI tries recognizing this image with the new rules. When the AI suggests rule changes, it lists the details, and they're only saved when you click **Apply these rules**; if the trial recognition found something, click **Add the trial boxes to this image** to use them directly.

**Sync to the Xuntong platform (optional):** at the bottom of "Current rules", click **Sync to Xuntong platform** to store the rules on the platform. It's disabled by default, so the platform's current recognition is unaffected.

To make the Xuntong platform's own recognition (snapshots, alert push) report only your project's classes, turn on **Use these rules for platform recognition**. Note: once on, recognition for your whole Xuntong account follows these rules; the scenes it applies to can be adjusted on the "Recognition rules" page of the Xuntong console.

Once bound, every time you save or apply rules the content syncs automatically, but it won't change the on/off state or the scenes you set in the console. To stop syncing, click **Unbind**; the rules on the platform are not deleted.

**Limits:** up to 30 classes, with class names of at most 30 characters; overall rules up to 1000 characters, and each class's recognition notes up to 500 characters; each Xuntong account can have up to 20 rule sets.

### 16.6 Upload your trained model to Xuntong

1. Train an **object detection** model in Wulabel (Xuntong currently only accepts detection models).
2. Go to **Deploy → Export model**. Under "Upload to Xuntong AI platform" at the bottom, adjust the model name and click **Upload**. If ONNX hasn't been exported yet, it's exported automatically first; the recommended threshold from the Evaluate page is uploaded with it.
3. The platform takes a few seconds to a minute to validate it: it shows "Validating" → "Validated" (or "Validation failed" with the reason).
4. Click **Open console**, go to "Custom models", and click **Enable**. Once enabled, you can connect cameras and set up alerts on the platform, and you can also choose it from the model list on the Annotate page.
5. "Custom models on the platform" below lists the uploaded models, their validation status and whether they're enabled. Accounts without hosting can only hold 1 model; **Delete** the old one before uploading a new version. Model files can be up to 200 MB.

### 16.7 Fetch on-site alert images and keep improving

Once the model is live, the false positives and missed detections in on-site alert snapshots are exactly the data most worth adding:

1. **Data → More import options → Fetch alert images from Xuntong AI**.
2. Choose the time range (last 1 / 3 / 7 days), which model's alerts, and the maximum number of images. **Use the platform's detected boxes as pre-labels** is checked by default.
3. The fetched images are in the project's `images/xuntong_<time>/` folder, with dashed boxes (source "Xuntong").
4. Fix them one by one: delete false-positive boxes (for an image with no real objects, just press **Enter** (Done) to keep it as a negative sample) and add what was missed.
5. Retrain, evaluate, and upload a new version to replace the old model on the platform.

Note: the platform keeps alert images for 7 days, so fetch regularly; only accounts with a push channel configured generate alert records.

That's the closed loop: **annotate → train → upload to Xuntong → on-site alerts → fetch back and fix → retrain**, and the model keeps getting better the more it's used.

### 16.8 Xuntong AI in collaboration

- **Official relay**: on the Collaborate page, choose **Online · Xuntong official relay** as the sharing method, and members on the internet connect through Xuntong's servers, with no server of your own needed. You must sign in to your Xuntong account first. Each account can run up to 3 shares at a time; images and annotations are forwarded through Xuntong's servers, not stored. For sensitive data, use LAN or a self-hosted relay.
- **What members can use**: members can't use Xuntong AI pre-labeling directly (it would use your quota); with "Members can use AI assistance" turned on, members can open recognition rules and chat with the AI (using your quota). Whether they can edit the rules follows the "Members can add and edit classes" switch.

### 16.9 FAQ

- **Nothing happens in the browser after clicking sign in**: click **Reopen** in the dialog, or copy the address into your browser. Do the same if your work computer blocks opening the browser automatically.
- **Can't click "Allow" on the web page**: the account has reached its key limit. Disable an unused key on the "API Key" page of the Xuntong console.
- **It shows "Connection failed"**:
  - Check the reason in the message;
  - For a manually entered key, check that it was copied in full (starts with `sk-live-`), is enabled in the console, and has no IP allowlist set (keys issued at sign-in have no allowlist);
  - You can also sign out and sign in again.
- **It says "quota exceeded or too many requests"**: check your remaining quota on the Settings page; once the quota is used up, renew on Xuntong or buy an add-on pack. Batch labeling already throttles its own speed.
- **A dedicated model is missing from the model list**: your account hasn't enabled it. Activate the matching plan on Xuntong AI.
- **Recognized class names differ from the project's**: dedicated models use their own class names, and names the project doesn't have are created automatically. To keep names consistent, use "Recognize by project classes", or rename the class in the class editor after recognition.
- **Self-hosted Xuntong**: under "Advanced" in Settings, enter your own platform address and API key.
